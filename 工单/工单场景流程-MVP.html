工单场景流程图

与 工单提交 · 分类入口、新建工单、工单详情 口径一致；下图由 Mermaid 渲染（需联网）。状态名与 SLA 以正式配置为准，本页为产品对齐示意。

工单状态机（各场景共性）

发起 → 分派/接收 → 处理中 → 待协同或待反馈 → 结案；支持驳回、撤回（未进不可逆节点）、转派。

flowchart TD
  A[发起人创建工单] --> B{自动分派 / 待接单}
  B --> C[处理人接收]
  B --> R1[驳回 → 发起人修改重提]
  C --> D[处理中]
  D --> E{需转派 / 升级?}
  E -->|是| F[转派至目标池/人]
  F --> D
  E -->|否| G{待外部反馈?}
  G -->|是| H[待海外仓/客户/财务反馈]
  H --> D
  G -->|否| I[结案归档]
  D --> W[发起人撤回]
  W --> A

工作台页签：待办、我发起、我处理、超期、已结案；流转记录各节点留痕可审计。

港前拆柜前找付雪

对应场景：港前·拆柜前找付雪。系统发起。

flowchart TD
  S1[业务员创建工单] --> S2[提交至港前客服池]
  S2 --> S3{付雪接收或驳回}
  S3 -->|驳回| S4[填写原因退回业务员]
  S4 --> S2
  S3 -->|接收| S5[进入拦截换标预报等后续动作]
  S5 --> S6[海外仓提柜拆柜组承接]
  S6 --> S7[处理完成或异常升级]
  S7 --> S8[结案]

SLA：约定时效内完成接收/驳回；驳回须填原因。接收后可拆分为「柜子计划协同」子流程继续跟踪。

港前柜子计划协同

对应场景：港前·柜子计划拦截换标。需记录拦截原因、换标要求、共享表更新人。

flowchart LR
  A[创建工单关联柜号] --> B[付雪接收]
  B --> C[拦截指令]
  C --> D[换标与标签确认]
  D --> E[更新共享表]
  E --> F[预报海外仓]
  F --> G[海外仓执行提柜拆柜]
  G --> H{结果}
  H -->|成功| I[结案]
  H -->|Hold/标签错误等| J[工单内升级并抄送客服组]
  J --> G

港前拆柜报告异常

对应场景：港前·拆柜报告异常。收到海外仓拆柜报告后 24h 内反馈。

flowchart TD
  A[海外仓出具拆柜报告] --> B[系统或人工创建异常工单]
  B --> C[指派港前/海外仓协同处理人]
  C --> D{24h 内反馈}
  D -->|少件| E[核实数量与责任方]
  D -->|破损| F[拍照留痕与索赔评估]
  E --> G[更新工单处理记录]
  F --> G
  G --> H[通知业务员与客户口径]
  H --> I[结案]
  G --> J[纳入月度异常分析视图]

港后私卡客服问题

入口卡片汇总；新建页可选：改地址、预约联系不上、改尾端派送方式等。

flowchart TD
  Start[创建工单选择私卡场景] --> T{问题类型}
  T -->|改地址/收件信息| A1[私卡客服接单]
  A1 --> A2[核对地址线路与客户诉求]
  A2 --> A3[下发海外仓或承运指令]
  A3 --> Done[结案]
  T -->|预约联系不上| B1[私卡客服发起反向工单]
  B1 --> B2[路由至港后客服池]
  B2 --> B3[客服回电客户或协同销售]
  B3 --> Done
  T -->|改尾端派送方式| C1[私卡客服接单]
  C1 --> C2{是否已入仓需改渠道}
  C2 -->|是| C3[勾选通知配仓组]
  C2 -->|否| C4[直接调整派送指令]
  C3 --> C4
  C4 --> Done

港后FBA 客服问题

含改仓/改发货渠道、尾端派送调整、改原单费用（费用类可走专用流程）。

flowchart TD
  Start[创建工单] --> T{诉求类型}
  T -->|改仓/改发货渠道| F1[FBA 客服接单]
  F1 --> F2[确认仓点渠道与指令边界]
  F2 --> F3{涉及出仓?}
  F3 -->|是| F4[通知配仓组]
  F3 -->|否| F5[更新仓内/系统指令]
  F4 --> F5
  F5 --> Done[结案]
  T -->|尾端派送调整| G1[FBA 客服明确新渠道时效回执]
  G1 --> G2[同步海外仓执行]
  G2 --> Done
  T -->|改原单费用| H1[见「原单费用调整」流程]

港后自提协同

单卡派转自提、到仓提货与回执确认；转派须留痕。

flowchart TD
  A[创建自提类工单] --> B{场景}
  B -->|单卡派转自提| C1[自提客服接单]
  C1 --> C2[系统记录转派人与接单人]
  C2 --> C3[更新派送方式为自提]
  C3 --> D[海外仓/到仓侧执行]
  B -->|到仓提货| P1[自提客服确认提货信息]
  P1 --> P2[客户补充资料如有]
  P2 --> P3[回执确认]
  D --> E[结案]
  P3 --> E

港后改尾程派送方式

对应场景：港后·私卡改尾端方式 / 自提转自提等；确认后写回运单 尾端派送方式。

flowchart TD
  A[发起工单并关联运单] --> B[私卡或 FBA 客服接收]
  B --> C{变更类型}
  C -->|改自提等| D[路由自提池或同单转角色]
  C -->|改私人卡派等| E[私卡/FBA 确认新派送方式]
  D --> F[自提确认后写回运单]
  E --> F
  F --> G{已入仓需出仓?}
  G -->|是| H[通知配仓组]
  G -->|否| I[海外仓/承运执行]
  H --> I
  I --> J[回执确认后结案]

港后池内「转派处理人」仍可用于换人；改派送方式以确认写回运单为准，见场景配置维护。

尾端未上架索赔

对应场景：尾端·未上架索赔。材料须在首条完整上传。

flowchart TD
  A[业务员提交未上架截图与资料] --> B[校验 ASIN 到仓凭证等]
  B --> C[亚马逊客服接收工单]
  C --> D[线下协调海外仓核实]
  D --> E{3 个自然日内海外仓反馈}
  E -->|未反馈| F[催办并标红超期]
  F --> E
  E -->|已反馈| G[客服核实结果]
  G --> H{是否成立索赔}
  H -->|是| I[完成索赔动作]
  H -->|否| J[通知业务员结案说明]
  I --> K[财务确认入账]
  K --> L[结案归档]
  J --> L

异常异常件跟进

媒体区断更、预约联系不上等；含 12h 开查、每周跟进、第 6 天标红。

flowchart TD
  Start[发起异常件工单] --> T{子场景}
  T -->|媒体区断更| M1[业务员或刘奎林发起]
  M1 --> M2[接收后 12h 内开查]
  M2 --> M3[记录官网/平台反馈时间]
  M3 --> M4[每周追加跟进记录]
  M4 --> M5{第 6 天是否闭环}
  M5 -->|否| M6[系统标红推送发起人/主管]
  M6 --> M4
  M5 -->|是| Done[结案]
  T -->|预约联系不上| P1[私卡客服发起反向工单]
  P1 --> P2[追踪回电与客户确认]
  P2 --> Done

费用原单费用调整

对应场景：费用结案·改原单费用。业务联动：联动对象=费用/原单，财务确认/结案时写回（见 场景配置维护）。

flowchart TD
  A[业务/FBA 客服提报费用调整] --> B[填写原单号差异金额原因]
  B --> C[提交工单]
  C --> D[财务复核]
  D --> E{差异确认}
  E -->|驳回| F[退回补充依据]
  F --> B
  E -->|通过| G[系统入账或标记已调整]
  G --> H[工单结案归档]
  H --> I[保留历史金额与调整依据供审计]

联动节点：财务点「财务确认」→ 调费用 API（非改运单）。详见 #WO-202605-012 演示。

其他其他问题

无法归入以上大类时进入；新建页自行选择阶段与业务场景。

flowchart TD
  A[分类入口选其他问题] --> B[新建页选择阶段与场景]
  B --> C[按分派规则路由至默认池]
  C --> D[处理人接收并处理]
  D --> E[必要时转派或升级]
  E --> F[结案]

建议运营侧定期将高频「其他」类沉淀为正式场景字典，减少错派。
