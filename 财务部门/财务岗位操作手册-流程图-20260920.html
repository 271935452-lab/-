一、公共操作框架

所有财务岗位使用同一条主线：接收事项 → 校验数据与权限 → 执行/提交 → 复核或审批 → 回写结果 → 留痕与异常闭环。

发起人

提交完整的业务对象、金额依据、附件与说明；被退回后补充并再次提交。

岗位操作人

只在本人有权限且前置条件齐全时处理；不以线下口头结论替代系统记录。

复核/审批人

核验关键金额、客户、账期、费用方向及异常原因，保留审批/驳回意见。

统一留痕要求：涉及金额、客户归属、账期、费用方向、客户资料或核销的操作，至少记录操作人、操作时间、原值、新值、原因及关联单据/凭证。

收款岗位操作手册

已确认方向 微信流水不自动认领/对冲；支付宝可参与规则匹配；多候选、重复或失败进入人工确认。

与现行手册不一致 / 范围缺口：《应收客服岗位操作手册(1)》还覆盖拉/发账单、催款、理赔、退款、客户解锁、报关抵扣、中信保与仓储费。现行“自动认领水单核销”未区分微信、多候选和失败回退；本次调研明确这些场景须进入人工确认池。该渠道判断需优先按调研方案补齐。
岗位目标

将有效回款准确认领至客户和应收单，完成核销并保证凭证、客户和金额联动一致。

主要入口

银行流水、手工水单、自动认领/自动对冲异常池、收款管理、凭证明细。

完成标志

认领/核销结果已回写；凭证明细刷新；异常有责任人和处理结论。

岗位操作步骤

  1. 接收流水：确认来源、收款日期、币种、金额、付款方、收款账户和流水号是否齐全。
  2. 识别渠道：微信直接进入人工确认；支付宝和银行流水可执行规则候选匹配。
  3. 核对候选：唯一且可信时执行认领；金额重复、多客户候选、匹配失败时不自动核销。
  4. 人工处理：选择对应客户和应收单，按人民币/美元分别核销；必要时填写无法处理原因。
  5. 完成复核：确认凭证明细切换正确、核销结果刷新、处理记录可追溯。
不得直接处理：多候选、重复金额、微信无对方户名、币种不一致、凭证与客户明细未联动时，必须留在人工确认或异常处理路径。

成本岗位操作手册

覆盖主单实际费用、付款管理、现金流量、应付与海外仓成本数据核对。岗位关注点是对象不能错绑、币种与汇率可追溯、成本记录不丢失。

与现行手册不一致 / 范围缺口：《成本组岗位操作手册》以共享表、群聊、价格表、PDF转表格和人工调差完成预估、对账、费用分摊与导入；调研提出服务商模板、系统预估、批量导入、费用回写与对象维度管理。两者不是金额口径冲突，但系统化替代范围、手工调差权限和审批留痕尚未确定。
岗位目标

将费用准确归属到主单、柜子、装车单或客户单号，保证付款、汇率、应付和成本明细一致。

主要入口

主单实际费用、付款管理、现金流量表、付款凭证、应付明细、货件汇总。

完成标志

费用对象、服务商、币种、汇率、金额和凭证均可回溯；异常不覆盖原始记录。

岗位操作步骤

  1. 登记前核对：确认费用依据、服务商、费用方向、币种、主单/柜子/客户单号与业务事实一致。
  2. 处理错绑：换绑提单时，原提单冲减记录不得自动跟随到新提单；发现错误先登记异常，再由有权限人员更正。
  3. 校验金额：付款管理按币别筛选；汇率支持四位小数。汇损流水按已确认公式生成，财务备注金额取凭证金额。
  4. 付款与回写：付款凭证/流水导入后，回写费用与凭证关联；保留服务商简称和处理来源。
  5. 导出复核：货件汇总、应收/应付明细展示拆柜、重量、地址及关联字段，核验导出与页面一致。
待确认：汇损与服务商核销流水的最终格式、公式边界、人工调整权限及已核销成本的修改限制，需成本组与资金组共同拍板。

分析岗位操作手册

分析岗负责输出业务数据统计、轨迹、资金占用、损益、提成等结果；先校验基础数据完整性，再解读报表，不把缺失成本、缺失节点或已核销数据直接当作零值。

与现行手册不一致 / 范围缺口：《财务分析岗位操作手册》大量依赖导出、粘贴模板、下拉公式、手工维护参数和图表取数范围；调研中的目标是补齐系统报表字段、查询/导出性能、统一时效和利润口径。手册中的人工“改公式/改参数”不能直接固化为系统规则，需先确认字段源头、重算范围和历史锁定。
岗位目标

提供可追溯的经营、成本、利润、时效与提成数据，及时识别口径、性能和数据质量问题。

主要入口

业务数据统计、轨迹报表、资金占用、提货管理、损益收入表、打单/海外提成报表。

完成标志

报表说明筛选口径、时间基准、异常数据和导出范围；问题能定位到具体单据或规则。

岗位操作步骤

  1. 确定口径：先选择对象（运单/客户/柜子）、时间基准（开船、到港、到货等）和组织维度，再执行查询。
  2. 基础校验：无成本、轨迹节点缺失、重量/价格档不一致时，不直接得出经营结论，先列入数据问题。
  3. 计算或重算：变更销售产品、比重、合并计费或报价后，按已确认的可重算范围操作；已核销数据不默认覆盖。
  4. 输出结果：报表和导出需一致；大结果集使用异步导出，记录筛选条件、数量与导出时间。
  5. 跟进异常：将无成本卡死、整柜轨迹缺失、查询性能、规则未命中等分派至对应系统/数据维护人。
分析红线：资金占用时间基准、费用类型、合并计费/取消合并、提成基数和利润取数涉及金额；在未确认公式前，只能输出问题/差异，不能手工替代系统口径。

税务岗位操作手册

当前调研明确覆盖个税累计测算、专项附加扣除下载、公司维度导出与提成身份证映射。开票接口能力仍由税务、收款和技术共同确认。

范围缺口：《税务会计岗位操作手册》还包含公司做账、增值税/企业所得税/财产行为税申报、邮管局/外汇申报、1039市场采购、统计、工商变更和社保申报。9月调研只讨论个税测算与导出；因此本页个税流程不能替代完整税务岗位流程。
岗位目标

按年度累计口径完成个税测算，保证人员唯一性、税率版本、已缴金额和导出数据可追溯。

主要入口

个税测算、专项附加扣除下载、公司维度个税表、提成表。

完成标志

本月应缴结果可回溯至年度累计、已缴和扣除数据；敏感信息按权限展示。

岗位操作步骤

  1. 准备数据：下载公司范围内人员、收入/提成、已缴个税与专项附加扣除数据。
  2. 校验人员：以身份证号为税务唯一识别；重复或缺失数据先进入补充处理，不参与正式测算。
  3. 按年度累计测算：使用本年度税率版本、累计减除费用、专项扣除、速算扣除数，得到年度应缴与本月差额。
  4. 复核异常：处理补发、更正、负数、人员变更及税率版本；保留测算依据。
  5. 导出与权限：按公司导出；身份证等敏感字段须按税务权限脱敏展示。
待确认：社保公积金、补发/更正、负数税额、税率年度版本切换、身份证脱敏和提成表导出权限尚未形成完整规则。

资金岗位操作手册

资金岗覆盖月度滞纳金、资金风控、报关抵扣、账户流水对接、自动对冲与提成扣款。金额生成、客户豁免、风险解除和抵扣分录必须有明确规则及审计。

关键口径冲突：现行《资金组岗位操作手册》规定客户每月最多两次临时解锁、单次最长5个自然日，第二次到期未付款按“逾期金额 × 0.002 / 次”收取解锁滞纳金；9月调研提出每月10日10:00核算上上月及以前未回款的“月度滞纳金”，并涉及两年追溯、余额抵扣与提成扣减。两种滞纳金是否并存、是否可叠加、优先级和客户豁免规则均为 P0，未确认前不能自动扣款。
岗位目标

识别回款、账期、风险和余额异常，完成可追溯的对冲、抵扣、扣款或人工处置。

主要入口

滞纳金核算、风控、报关抵扣、资金账户流水、自动对冲异常池、提成特殊扣款。

完成标志

每笔处理能追溯客户、单号、费用/余额、审批或豁免原因及结果状态。

岗位操作步骤

  1. 日常监控：查看账户流水、自动认领/对冲失败、退款、不同客户同账号回款与风险提示。
  2. 月度核算：按已确认的账期、产品、到港日和核算日读取应收；识别免收客户/单号与多收、负数等排除项。
  3. 金额处理：规则齐全时生成滞纳金、余额对冲、特殊事项扣款或报关抵扣候选；规则不全时只出待审核，不自动入账。
  4. 人工确认：复核客户、单号、费用方向、客户直付报关行、多个账户和风险解除理由。
  5. 回写：将处理结果写入应收、应付、余额、特殊扣款或风控状态，并保留审批/豁免证据。
资金处理红线：滞纳金“千分之二”的计费周期、两年追溯、余额抵扣顺序；报关抵扣分录；风险锁定/解除条件均尚未完全确认，不得直接自动执行。

客户管理岗位操作手册

客户管理作为财务部门统一分类，覆盖开户、风险推送、合同/账期、客户分配、欠款和线上线下资料治理。重点是客户资料真实、重复可见、合同与欠款可追溯。

与现行手册不一致 / 范围缺口：现行应收客服手册已包含账期申请审核、天眼查风险判断、客户开户权限、客户保护期、客户转交、改抬头、中信保及美库开户等具体操作；9月调研新增OCR回填、全局重复提示、草稿、合同外欠款提示、部门经理风险推送等目标。现行的具体时限/权限规则尚未在调研中逐条确认，不能直接写入新系统配置。
岗位目标

维护客户主数据、风险、合同和归属，避免重复开户、资料覆盖错误和客户欠款信息不一致。

主要入口

客户列表、开户/编辑、附件审核、合同/账期、客户分配、欠款明细、操作日志。

完成标志

客户资料审核/开户状态清晰，重复提示已处理，合同/欠款/归属变更留痕并同步下游。

岗位操作步骤

  1. 接收资料：收集营业执照、企查查截图、合同及联系人资料；上传后可做图片识别，但必须人工确认回填结果。
  2. 核对重复：以统一/关联信用代码、电话、法人电话、注册地址等检索全局客户库；公海与历史客户也应参与提示。
  3. 审核与开户：附件审核通过后才可开户；资料未齐时保存草稿，草稿不改变开户状态。
  4. 维护合同与分配：合同维护我方抬头、合同编号、起止时间；改账期/合同时间时提示合同外未核销欠款。选择业务员后自动带出客服，批量调整需写日志。
  5. 数据治理：线上线下资料以客户代码匹配导入；变更业务员、客服、账期或客户时记录前后值，并检查欠款、权限和同步影响。
待确认：风险最终推送路由、允许重复开户后的原因/审批、线下资料覆盖优先级、合同外欠款的时间字段、电话校验规则和客户转交的历史查看权限。

DIF-001收款现行流程包含自动/手工水单核销，但未单列微信流水及多候选匹配的处置口径。微信不自动认领；识别到重复、多条候选或自动对冲失败时进入人工确认列表。[冲突] P0自动匹配范围必须先拆分。建议未命中、重复候选、微信流水、对冲失败一律不自动落账，进入收款人工确认池并留痕。待财务确认
DIF-002收款 / 开票现行手册按费用性质区分 6%、9% 与免税跨境，并包含开票及税控相关操作。已出的开票原型聚焦拖车费、报关费、服务商、起运/目的地、车牌和品名。[范围缺口] P0原型字段不足以决定税率、开票主体、合并规则及税控系统动作。确认前仅可做开票资料准备，不能自动开票。待税务 / 收款确认
DIF-003成本海外仓、头程、拖车、报关等账单主要依赖共享表、群聊、PDF 转 Excel、人工调差和付款核对。调研提出服务商模板、海外仓预估、费用导入、费用回写、按客户单号/柜子维度展示。[系统化缺口] P1需先拆分“导入、匹配、差异确认、审批、回写”责任边界；人工调差的操作人、审批和前后值留痕尚未确认。待成本组确认
DIF-004成本 / 海外仓现行海外仓对账和组合价依赖价格表与人工沟通，分摊口径未形成唯一系统规则。调研提出所有分摊按材积；海外仓添加费用均为应付；提拆派报价按生效时间取价，费用时间口径还在沟通。[冲突] P0“组合价、计费时间、材积分摊、应收/应付方向”必须形成同一份规则。未统一前不能批量重算或自动回写。待成本 / 海外仓 / 财务确认
DIF-005分析现行经营分析、成本预估、损益和看板大量通过导出、粘贴、下拉公式、参数表和图表范围人工维护。调研要求补齐轨迹、资金占用、业务数据统计、提成、损益等报表字段，并修复多单号搜索与大数据量导出。[系统化缺口] P1手工公式、参数与报表口径不能直接迁入系统。需逐张报表确认数据来源、计算公式、刷新频率和导出上限。待分析组确认
DIF-006税务现行职责覆盖做账、增值税/所得税/财产行为税申报、邮管局、外汇、1039 市场采购、统计、工商变更和社保。当前调研明确讨论的是个税累计测算、专项扣除下载、公司维度下载和身份证映射。[范围缺口] P1个税页面不能代表完整税务岗位系统化范围。需确认本期仅做个税，还是逐步纳入其他税务台账与申报协同。待税务确认
DIF-007资金现行临时解锁：每月最多两次、单次最长 5 个自然日；第二次到期未付款按“逾期金额 × 0.002 / 次”收取解锁滞纳金。调研月度滞纳金：每月 10 日 10:00 核算上上月及以前未回款，涉及两年追溯、余额抵扣和提成扣减。[冲突] P0两种滞纳金是否并存、能否叠加、核算范围、豁免和审批人均未统一。确认前不做自动扣款或自动锁定。待资金 / 收款确认
DIF-008资金现行还承担返现、提成预算及发放、现金盘点、资金调度、银行账户/U 盾、外汇、日报、项目贷和理财等工作。调研重点是月度滞纳金、风控、报关抵扣、账户抓流水、自动对冲异常。[范围缺口] P1未进入调研的资金事项不应被默认排除或纳入系统。建议列为二期候选清单，由资金负责人按风险和频率排序。待资金确认
DIF-009客户管理现行手册已有账期审核、天眼查风险、开户权限、客户保护期、客户转交、改抬头、中信保和美库开户细则。调研新增风险推至部门、OCR 回填、重复提示、草稿、合同外欠款提示、批量改客服和日志修复。[冲突] P0现行审批时限、开户/转交权限、保护期和风险拦截是否保留为配置规则尚未确认；不能用新页面覆盖旧制度。待客户管理 / 资金确认
DIF-010客户管理现行资料由多个岗位、线下表和系统页面维护，涉及开户、合同、账期、客户归属与风险资料。调研要求线上线下数据更新、OCR 内容填充、信用代码支持多值、全局重复校验和准确日志。[冲突] P0需明确客户代码、统一社会信用代码、注册地址等匹配键，以及线上/线下冲突时谁覆盖谁；否则可能覆盖有效主数据。待客户管理确认
DIF-011跨岗位审批现行手册多处通过企业微信、群聊或线下审批完成费用确认、账期、退款、调差和客户变更。调研提出使用系统现有审批流，并在业务对象中展示审批状态。[系统化缺口] P1需逐类确认审批发起条件、审批流模板、驳回目标、审批结果回写和线下遗留记录的处理方式。待财务 / IT 确认
