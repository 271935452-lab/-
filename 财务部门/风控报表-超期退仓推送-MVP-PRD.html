二、跑批规则 KEY

每日跑批；阈值天数与适用销售产品均以「超期风控配置」已发布版本为准，不写死在代码里。 命中进财务全量；已签出只给财务看，未签出由系统自动推接收人办理退仓。

进池标准（须同时满足 · 10/15）：① 有签入时间；② 按销售产品匹配配置且超期天数 > 0；③ 运单主数据为非已退件（已退件不进池）。不按扣件类型过滤进池。

规则类型销售产品范围（配置）时间差公式阈值（配置）财务接收人 / 退仓
① 指定阈值行 配置页「指定阈值行」多选的销售产品（可增删改）
  1. 在仓时长：已签出 = 签出−签入；未签出 = 当前−签入
  2. 超期天数 = 在仓时长 − 配置阈值 T

三附、退仓标记状态流转 KEY · 10/15

仅未签出且已进池的运单走下列标记；已签出命中退仓标记列为「—」。

顺序退仓标记触发条件下一动作
1 待推送业务 跑批/刷新进池，且跑批后系统自动推接收人完成（或刷新补推）；尚未「一键推送给业务员」 接收人执行一键推业务员 → 进入「业务员跟进中」
2 业务员跟进中 一键推业务员成功；列表展示缓冲截止 = 推送日次日 08:30（中国时区） 等待系统识别业务员有效处理，或等待定时任务
3a 系统自动退件退款 处于「业务员跟进中」，截止前系统未识别为「业务已处理」，且到点时运单非已放行/已退款 → 定时任务执行退件退款成功 终态；运单挂载 1 条自动退日志（见 §三附二）
3b 业务已处理 处于「业务员跟进中」，系统识别业务员侧有效处理（运单主数据为已放行或已退款等，与自动退前复核口径一致） 终态；不触发自动退件退款；标记不回退；列表无接收人操作按钮

口径：进度只看退仓标记列；不再使用「待跑批」「待推业务员」「缓冲跟进中」等旧文案。

三附二、运单侧日志（挂载运单） KEY

退仓风控在运单上挂载操作日志（与关务/船务 ESS 通用组件一致，key = 运单号）。 本需求仅写一条，其余推送链步骤不写运单日志。

项规则
何时写 仅当系统执行自动退件退款成功时写入（缓冲截止次日 08:30 仍无有效操作，且运单非已放行、非已退款）。
不写（跳过自动退） 到点执行前运单已为已放行或已退款 → 不自动退、不落本条运单日志（批次任务日志可记「跳过」供审计，实现方式研发定）。
类型（type） 系统自动退件退款
操作人 系统（sys: true）
不写运单日志 跑批命中、系统推接收人、接收人推业务员、业务员消息、列表刷新等 — 仅批次/后台审计（见日志模板），不落运单。
入口 退仓列表操作列「日志」；运单详情同源（现网运单日志能力复用）。
文案要点 缓冲截止时间、超期天数/命中规则摘要、退件退款执行结果；示例见日志模板 §4.2。

测 Given 某票已自动退件退款；When 打开该运单「日志」；Then 仅 1 条类型为「系统自动退件退款」，操作人=系统。

五、推送链 · 业务员缓冲 · 自动退件退款 KEY · 10/13

主路径：跑批命中 → 系统自动推配置接收人（弹窗：签入时间距当前时间已超过阈值，请关注并告知业务员）→ 列表一键推业务员 → 缓冲至次日 08:30 → 未操作自动退件退款。以上链路不在列表页重复展示，仅 PRD 与配置/日志规范中说明。

功能点说明原型
① 系统自动推接收人
  1. 跑批完成后，未签出命中票自动进接收人待办
  2. 接收人待办列表可见预配舱号、扣件状态

② 接收人 → 业务员
  1. 接收人点击待办后，可一键推送给业务员
  2. 推送成功后记录推送时间，并计算缓冲截止时间

③ 缓冲截止
  1. 业务员缓冲约一天；截止时刻固定为次日 08:30（中国时区）
  2. 例：接收人 10/13 15:20 推业务员 → 截止 10/14 08:30

④ 自动退件退款
  1. 截止前系统已识别「业务已处理」→ 不自动退，退仓标记保持业务已处理
  2. KEY 定时任务到点前复核运单现状：若运单主数据已为已放行或已退款，系统标记「业务已处理」、不执行自动退件退款（不写运单挂载自动退日志）
  3. 截止时仍未识别为业务已处理 → 系统自动退件退款；列表「退仓标记」= 系统自动退件退款；写批次日志 + 运单挂载 1 条自动退日志（§三附二）
 规则验收（日志）

六、验收测点（Given / When / Then）

#测点
P1Given 产品 P 阈值 T，已签出且 (签出−签入)−T>0；When 跑批；Then 进清单，超期天数=(签出−签入)−T，退仓标记「—」
P2Given 同上，未签出且 (当前−签入)−T>0；When 跑批；Then 进清单，接收人待办自动生成
P2bGiven 兜底阈值 U，非指定行产品 (在仓时长)−U>0；When 跑批/刷新；Then 按兜底进池
P3Given 同批含已签出+未签出命中；When 跑批；Then 仅未签出进接收人待办，已签出不推
P4Given 接收人点「一键推送给业务员」；When 成功；Then 业务员待办生成，截止=次日 08:30
P5Given 已推业务员且截止前无操作；When 到次日 08:30；Then 系统自动退件退款，退仓标记+批次日志+运单仅 1 条自动退日志
L3打开「日志」抽屉；Then 仅「系统自动退件退款」一条（未自动退前可为空）
P6Given 退仓标记为「业务员跟进中」且系统已识别「业务已处理」；When 到次日 08:30；Then 不自动退件退款，标记仍为业务已处理
P6bGiven 标记「待推送业务」；When 一键推业务员成功；Then 标记变为「业务员跟进中」且展示截止时刻
P7Given 已推业务员且截止前运单主数据变为已放行或已退款；When 系统复核/自动退任务执行；Then 退仓标记为「业务已处理」、不自动退件退款、运单挂载日志无新增
P8Given 超期天数>0 且扣件为正常件、运单非已退件；When 跑批/刷新；Then 进财务退仓清单（扣件仅展示）
P9Given 超期但运单状态为已退件；When 跑批/刷新；Then 不进清单
P10Given 未签出进池且未读；When 筛选「提醒已读=未读」；Then 仅未读行；When 点「标记已读」；Then 该行变已读且菜单角标减 1
P11Given 未读且待推送业务；When 一键推业务员成功；Then 自动已读且退仓标记为业务员跟进中

过会口令：进池=超期+非已退件；跑批系统自动推接收人→接收人推业务员；次日 08:30 自动退件退款（已放行/已退件等跳过）；财务看全量不手工推；退仓只对未签出。
