本期做啥 / 本期不做啥

本期要做本期不做
  1. 配置页：不同产品超几天算超期、每天几点自动算
  2. 财务列表看全部单（已签出 + 未签出）；只有没签出的系统自动通知接收人
  3. 接收人推业务员 → 业务员「去处理」+ 运单页必选弹窗；推送后 2h 未点「去处理」→ 自动退件退款
  4. 配置保存后，下一次定时任务用新规则
  5. 列表有预配舱、扣件状态、退仓标记、点「日志」；自动退只在运单上留 1 条记录；演示按钮在侧栏「原型演示」里
  1. 财务不能手工帮接收人推
  2. 已签出的不能办退仓、不能推接收人
  3. 不能在本需求里改运单签入、签出原始数据
  4. 接收人终配舱弹窗（辅助功能，另说）

为啥要做

项大白话
业务痛点扣件在仓放太久，海运费还涨；没签出的超期要能催到业务员、到点能自动退
公司要啥财务能盯全部风险单；没签出的能自动走完退件退款
怎么走每天算出超期 → 系统自动找接收人 → 接收人推业务员 → 业务员 2h 内点「去处理」并选处理方式；未点则自动退

谁干什么

谁能看啥能干啥不能干啥
财务所有进列表的单（含已签出）查询、看退仓标记、点日志不能手工推接收人；不能给已签出办退仓
接收人（如黄少飞）系统推来的、还没签出的待办一键推业务员、标已读已签出的不会推过来
业务员接收人转过来的（本期主要看日志验收）缓冲期内自己处理—
配规则的人配置页改阈值、时间、接收人并保存保存前别乱改已生效口径

名词（口语版）

词意思
签入时间货第一次进仓的时间；没有就不算超期
签出状态已经签出 / 还没签出；没签出就没有签出时间
超期天数比配置多放了几天；已签出用签出减签入，没签出用今天减签入，再减配置天数；必须大于 0
能进列表超期了 + 运单非已退件（不看扣件类型）
扣件状态和运单列表一样展示；不参与进池判断
自动退时点推业务员成功时刻 +2 小时内未点击「去处理」→ 自动退（国内时间，精确到秒按推送成功时间起算）

一、怎么查

条件在哪说明原型
新页面—没有老页面筛选项，全是新建的—
运单、预配舱、产品、签入时间、提醒已读上面查询区预配舱可模糊；查完可重置搜索
全部 / 未签出 / 已签出列表上方芯片只在已经进列表的单里再筛；括号条数跟着当前查询变，不会从别处拉新数据芯片
已签出 / 未签出数据哪来的进池规则定时任务或「刷新」按配置重算超期；已签出、未签出用同一套条件进列表（超期 + 非已退件）。签出状态来自仓库轨迹。进池后：未签出自动通知接收人、可推业务员；已签出仅财务盯盘，不推、不自动退（退仓标记口径见第 9 点）

二、列表上每一列是啥

只有「超期了 + 非已退件」的单才会出现在列表；签入签出时间跟运单一致；扣件列仅展示。

列从哪来说明原型
勾选框—全选当前页；上面显示选了几条列表
运单运单只显示运单号，不显示柜号列表
销售产品主数据用来匹配配置里超几天列表
运单状态运单已签入、海外出库等；自动退完会变已退件列表
签出状态仓库已签出 / 未签出列表
预配舱业务数据没有就显示「—」列表
扣件状态运单列表正常件 / 普通扣件 / 特殊扣件；仅展示，不进池条件列表
签入、签出时间运单没签出则签出时间为「—」列表
超期天数系统算比配置多几天；不大于 0 不进列表列表
命中规则系统算显示匹配的配置名和天数；不能用来筛，只能看列列表
提醒已读系统推接收人后：未读 / 已读 / —列表
退仓标记系统未签出：待推送业务 → 业务员跟进中 → 业务已处理（RR-25/26）或系统自动退件退款（推送后 2h 未点「去处理」，调问题件跟踪·退件（退件退款））；已签出：「—」列表
操作按钮推业务员、标已读、看日志；无「业务已处理」按钮（系统识别）；自动退在运单上只留 1 条日志列表

三、功能怎么走

环节大白话原型
每天自动算 关键
  1. 每天跑一次（几点在配置页设），用已保存的配置
  2. 不同产品可以设不同超期天数；没配到的产品不算
  3. 要超期 + 非已退件才进列表（不看扣件）
  4. 系统自带的 8 天、16 天只是示例，运营可以改
 配置
改配置
  1. 保存后一般从第二天那次任务开始用新规则，老列表不倒算
  2. 能改：超几天、几点跑、谁收待办
  3. 验证规则是否生效：去推送列表点「刷新」看命中规则列
 规则配置
自动通知接收人
  1. 算完后：进列表、还没签出、还没办完的单，系统自动通知配置的接收人；已签出的不通知
  2. 弹窗大意：签入太久超了，请关注并告诉业务员；财务这边没有「推接收人」按钮
  3. 已签出的退仓标记列为「—」（仅财务盯盘，不办退仓）
 列表
点「刷新」
  1. 用最新配置重新算谁超期、规则列显示啥
  2. 不该在列表的会去掉；新超期且没签出的会自动通知接收人
 刷新
接收人推业务员
  1. 列表里「一键推业务员」
  2. 记下推送成功时刻；业务员侧弹出退仓代办，主按钮「去处理」；列表展示自动退截止 = 推送时刻 +2h（国内时间）
 列表
业务员「去处理」NEW
  1. 业务员在代办弹窗点「去处理」 → 跳转运单管理/运单列表，查询区自动带上该运单号条件（URL 参数与列表筛选项一致）
  2. 运单页加载完成后弹出必选对话框（不可关闭跳过）：退件退款 或 刷新到货时间为今天，必须二选一后点确定
  3. 测：未选点确定 → 拦截；仅关闭弹窗不选 → 不允许视为已处理
 运单页 + 弹窗
弹窗 · 选「退件退款」
  1. 确定后调用问题件跟踪 · 退件能力，处理方式 =「退件退款」（与现网问题件退件同一套接口/参数口径）
  2. 成功：运单状态按退件退款结果更新；退仓标记 →「业务已处理」；本票不再走 2h 自动退
  3. 失败：弹窗/页面提示失败原因，退仓标记仍为「业务员跟进中」，可重试
 问题件 · 退件
弹窗 · 选「刷新到货时间为今天」
  1. 点确定前读取当前运单到货时间；运单新增字段「原到货时间」，仅在本操作首次成功时写入并持久化（保存变更前的到货时间；若已有值则不再覆盖，保留第一次刷新前的原值）
  2. 将运单到货时间更新为点击「确定」的服务器时刻（「今天」= 确认日；格式与现网到货时间一致，如 yyyy-MM-dd HH:mm:ss）
  3. 到货时间写入成功后，同步调用重新计费接口按新到货时间重算（失败需提示；到货时间/原到货时间是否回滚按现网重新计费与运单编辑规则）
  4. 到货+计费均成功：在运单操作日志写入一条（操作人=当前业务员）：签入时间超过阈值后操作更新到货时间：由{原时间}更新为{更新时间}（{原时间}=本次写入「原到货时间」的值或空时展示「—」；{更新时间}=新到货时间）
  5. 退仓标记 →「业务已处理」；本票不再走 2h 自动退
 运单 · 原到货时间 · 重新计费 · 运单日志
2 小时未点「去处理」自动退 关键
  1. 自推送业务员成功起算 2 小时内，业务员未点击代办「去处理」→ 自动退件退款定时任务扫描命中
  2. 执行动作与手工选「退件退款」相同：调用问题件跟踪 · 退件，处理方式 =「退件退款」
  3. 成功：退仓标记为系统自动退件退款；运单挂载日志仍仅 1 条（见日志模板）；已点击并完成弹窗（任一分支）的 → 不按本条触发
  4. 执行前校验：非已放行、非已退件；否则不写自动退日志
 定时任务

还没定死的（别先开发）

项说明本期
业务员独立待办列表页 单独菜单查全部退仓待办 本期不做；用代办弹窗 + 运单页弹窗（见「去处理」）验收

技术侧要注意的

项要求
定时任务① 每天 1 次超期跑批（几点可配）；② 自动退件退款任务（建议高频扫描或延迟队列）：「已推业务员、未业务已处理」且推送成功时刻 +2h 已过、仍未点击「去处理」→ 退；失败可重跑/告警
时间唯一自动退触发：推送时刻 +2h（未点「去处理」）；列表/代办展示截止 = 推送 +2h
日志自动退在运单上只留 1 条；别的推送记在后台任务日志，列表底下不滚长日志
运单字段本需求在运单上新增「原到货时间」（与到货时间同类型）；仅在「刷新到货时间为今天」确定且首次成功时从当前到货时间快照写入；供展示、审计与日志占位符 {原时间}
外部接口① 问题件跟踪-退件：处理方式固定传「退件退款」（业务员手工选退件、2h 自动退共用）；② 重新计费：仅「刷新到货时间为今天」分支在到货时间更新成功后调用
运单日志（刷新到货）与风控「挂载 1 条自动退」无关；本分支成功后在运单现网日志增加：签入时间超过阈值后操作更新到货时间：由{原时间}更新为{更新时间}

验收怎么测

#测什么
P1指定产品超期了、已经签出 → 进列表，退仓标记「—」
P2同样条件、还没签出 → 进列表，接收人待办自动有
P2b走「其余产品」那条规则超期 → 按兜底规则进列表
P3一批里既有已签出又有未签出 → 只有没签出的推接收人
P4接收人推业务员成功 → 列表/代办展示自动退截止 = 推送时刻 +2h
P5推送后 2h 内未点「去处理」→ 自动退任务调用问题件退件（处理方式=退件退款）
P62h 内业务员已完成「去处理」弹窗（任一分支）→ 不自动退，标记业务已处理
P7自动退执行前单子已放行或已退件 → 不自动退、不写那条自动退日志
P7c点「去处理」→ 运单页带运单号条件 + 必选弹窗；未选确定 → 拦截
P7d弹窗选「退件退款」确定 → 问题件跟踪退件接口成功 → 业务已处理，不自动退
P7e弹窗选「刷新到货时间为今天」确定 → 写入/保留「原到货时间」→ 到货时间=确认时刻 → 重新计费成功 → 运单日志含「由{原时间}更新为{更新时间}」→ 业务已处理
P8超期且正常件、非已退件 → 进列表（扣件仅展示）
P9超期但运单已退件 → 不进列表
