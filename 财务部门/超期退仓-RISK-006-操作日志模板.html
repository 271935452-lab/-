一、两层日志

层级 展示位置 对象 Key 用途
批次推送日志 后台/审计（不在退仓列表页展示） —（按时间流） 跑批、推接收人、推业务员、自动退等汇总事件
运单挂载日志 列表「日志」/ 运单详情 · 右侧抽屉 运单号 仅 1 条：系统自动退件退款（见 PRD §三附）

口径：业务提交成功才写；查询、打开抽屉不写。系统任务操作人=系统（灰字）。

二、日志类型字典 开发对照

类型（type） 触发时机 操作人 写批次日志 写运单挂载日志
跑批命中 每日跑批重算超期，运单进入风控池 系统 可选 否
系统推接收人 未签出命中，跑批后自动推配置接收人 系统 是 否
接收人推业务员 列表「一键推送给业务员」成功 接收人 是 否
业务员消息 消息中心下发退仓跟进 系统 否 否
系统自动退件退款 已推业务员且缓冲截止（次日 08:30）仍无有效操作；且运单非已放行、非已退款 系统 是 是（唯一）
列表刷新 等 配置重匹配、刷新列表 用户/系统 是 否

三、运单挂载日志字段（单条）

字段必填说明
key是运单号
at是执行时间 YYYY-MM-DD HH:mm:ss
user是固定「系统」
type是固定 系统自动退件退款
text是见 §4.2
sys是true

四、文案模板

4.1 批次推送日志（后台，列表页不展示）

[{时间}] <strong>系统自动推接收人</strong>（{来源}）：未签出 <b>{N}</b> 票
[{时间}] <strong>接收人→业务员</strong>：运单 <b>{waybill}</b> · 缓冲截止 <b>{deadline}</b>
[{时间}] <strong class="red">系统自动退件退款</strong> · 运单 <b>{waybill}</b>

4.2 运单挂载日志（仅本条）

【系统自动退件退款】缓冲截止 {salesDeadline} 前业务员无有效操作，系统执行退件退款；运单 {waybill}；规则：{ruleLabel}；超期 {overdueDays} 天。

五、列表「退仓标记」与日志

  • 未签出流转：待推送业务 → 业务员跟进中 → 系统自动退件退款 或 业务已处理（详见 PRD §三附）。
  • 仅「系统自动退件退款」与运单挂载日志类型 系统自动退件退款 同时出现；「业务已处理」不写运单挂载日志。
  • 未自动退前，打开「日志」可为空或提示暂无记录。

六、验收抽查

编号步骤预期
L1 跑批 / 推接收人 / 推业务员 运单挂载日志无新增
L2 到期自动退（原型：模拟到期自动退） 退仓标记=系统自动退件退款；运单挂载仅 1 条系统自动退件退款
L3 到点运单已放行或已退款 不自动退；运单挂载日志无新增
