总导航 · 银行流水认领 · 自动对冲

收款管理 · 手工录入 × 银行抓取 · 自动对冲

原方案是人工对冲；现改为认领后自动匹配 + 数据置换。 手工已部分核销时费用前端保持核销不变，后台把来源从虚拟流水换成真实银行流水。 本页可演示自动对冲、手动对冲与撤销对冲，三种操作共用一套日志字段。

1. 方案对照

原方案（人工对冲）现方案（自动匹配 + 置换）
触发 财务在列表勾选手工凭证 + 银行凭证，点「凭证对冲」 银行流水抓回并认领成功后，系统按字段全集匹配虚拟流水
部分核销 易出现费用先反核销再重核，前端状态会闪 费用保持核销；只换核销记录上的来源流水 ID
凭证 两套凭证并存或手工作废 虚拟流水标记「已作废/已替换」，不生成正式凭证；正式凭证只基于真实银行流水
数据置换 无（靠对冲分录把两边轧平） 有：核销记录 source_flow_id 从虚拟 ID 更新为真实银行流水 ID
锁定状态：手工录入并核销后，该笔收款标记为「临时核销」，关联 虚拟流水 ID（不入正式账）。 真实流水认领匹配成功后进入置换；费用核销状态对外不变。

2. 完全匹配字段（认领后自动识别）

须全部命中才自动对冲；任一不等则进入待人工处理池，不自动置换。

时间窗：凭证时间相差 ≤ 48 小时。账户：对方账户、我方账户须一致。金额：收款金额 + 汇算金额（折算本币）须一致。

3. 手工已部分核销 · 怎么处理

场景规则
一笔手工收款核销了多笔费用（未用完） 该笔收款仍是「临时核销」；其下全部核销分录随来源 ID 一起置换。未核销余额转到真实流水上继续可核。
费用侧已核销金额 费用行保持「已核销 / 部分核销」，不反核销、不重做。前端无波动。
金额对不上 / 超 48h / 账户不一致 不自动对冲。真实流水保持已认领待核销；虚拟流水保持临时核销。进「待人工对冲」。
对冲后真实流水又核了新费用 允许继续核销。此时禁止「转换回来」，须先撤销对冲后新增的核销。
会计期间已关账且虚拟已误出正式凭证 不走静默置换；走红冲 + 真实流水重出凭证（本原型不演示关账）。

5. 三种操作日志（给开发 / 测试）

三种操作写同一张对冲日志表：1 条主日志 + N 条核销分录明细。费用详情、虚拟流水、真实流水「操作记录」都按 batch_no 互查。对冲明细页签展示关系，不另写一套字段。

    6. 撤销对冲 · 测试口径

    自动对冲、手动对冲都可以撤销，动作相同：核销分录 source_flow_id 改回虚拟 ID；虚拟流水恢复「临时核销」；真实流水恢复「已认领待核销」；正式凭证作废（或关账后红冲）；费用状态不变。 日志一律 HEDGE_ROLLBACK，用 rollback_of_biz_type 区分撤的是自动还是手动。
    勾选「对冲后又核销了 FY-NEW」再点撤销，应 result=BLOCKED。对冲可逆，叠加新核销后不可直接逆。
