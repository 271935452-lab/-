# 回款核销｜开发与测试待补 PRD 确认稿

> 文档状态：需求草稿，暂不可直接进入开发或测试。本文只列当前 PRD 尚未明确、需要产品确认或研发评估的契约和验收口径。
> 依据：现有回款申请 PRD、回款工作台 PRD、2026-11-13 最新确认补充 PRD。

## 1. 当前已确定、研发必须遵守的规则

| 规则 | 实施要求 |
| --- | --- |
| 水单/申请单维度 | 回款处理列表一行一张水单；回款申请可关联多张水单，是放行审批、放行结果和汇总日志的对象。 |
| 提交时机 | 点击提交预核销后才执行自动认领、比对和核销。 |
| 流水窗口与付款时间 | 付款时间是自动认领必备条件。水单优先取 AI 识别付款时间，识别不到时由系统取上传时间；回款申请和业务补资料入口仅只读展示。真实流水仅可在该时间后 48 小时内参与自动匹配，窗口外、无系统时间或手工新增凭证均不得成为候选。 |
| 账户 | 客户付款账号前 4 位+后 4 位；我方收款账号后 4 位。 |
| 金额 | 自动核销以当前客户全部待支付请款单待结算金额为基准；水单确认金额大于或等于该金额才自动全核，超出部分转客户余额；小于则进入人工核销。 |
| 异常 | 无法唯一认领进入自动认领异常；已认领但金额/费用项不满足进入已比对待核销。 |
| 放行 | 放行和核销独立；已放行未核销可撤销放行，已核销不得撤销放行。 |
| 处理状态 | 原“处理阶段”和“处理状态”合并为唯一“处理状态”。水单值为自动认领异常、已比对待核销、待业务补资料、已核销、重新匹配中；放行状态单独展示。 |
| 放行审批粒度 | 放行列表按水单展示；选择任一待放行水单后，财务按回款申请单一次审批，结果同步回写该申请下全部待放行水单。 |
| 部分核销 | 支持一张水单多个账单、多个水单一个账单；分配金额逐笔保存。 |
| 列表编号 | 异常列表只展示回款编号；回款申请号保留为内部关联字段，不重复展示。 |
| 账户核对 | 付款账户和我方收款账户统一展示在水单列表“账户核对”列，分别显示脱敏值和匹配状态；弹窗下方不再重复展示。 |
| 待业务补资料 | 认领异常、放行审批都可退回同一个“待业务补资料”池；通过退回来源区分，不新增平行状态。 |
| 补资料重跑 | 业务重新提交后重新执行认领、账单比对、放行和核销判断；不替换水单复用原识别结果，替换水单才重新识别。 |
| 配置口径 | 放行比例按确认金额/到期未结算账单金额计算，低于比例人工复核；确认金额相对识别金额允许上下调整，绝对差值不得超过配置。 |
| 人工核销入口 | 本期原型暂不开放人工核销按钮；保留状态、字段和规则契约，是否恢复在回款处理工作台或迁移到收款管理列入评审。 |
| 发起权限与同客户 | 多运单、多个请款单仅可合并为同一客户的一张申请；业务员/客服/结算员仅可操作其主页面客户数据权限范围。 |
| 可匹配账单 | 自动认领、自动核销和回款申请仅使用状态为“待支付”的请款单；部分付款、已结清不得进入。 |
| 水单确认 | 单次申请最多 5 张；确认金额默认识别金额且可编辑；付款/收款账户逐行可编辑且非必填；付款时间为 AI 识别或系统上传的只读值，识别错误仅可替换水单重新识别；列表全选/逐行勾选替代总核对。 |
| 回款协同筛选 | 申请明细支持客户简称、关联运单号、申请时间组合筛选；付款备注随申请保存、列表和日志回显。 |
| 指派处理人 | 候选来源为员工管理中部门=收入管理的在职员工；后端必须拒绝非该范围人员。 |
| 工作台新增字段 | 列表新增业务员、客服、提交人，分别来自客户主数据业务员/客服及回款申请创建人，只读回显。 |
| 回款协同状态 | 去掉主申请单状态，拆为预核销状态和放行状态两个字段并列展示。 |
| 手工凭证 | 手工新增凭证不进入自动认领/自动核销候选池；仅可在现网收款管理人工处理。 |

## 2. 后端仍需补齐的契约

### 2.1 对象和唯一键

需要研发确认对象的最终字段和唯一约束：

- 回款申请：回款申请号、申请客户、申请状态。
- 回款编号：沿用回款申请生成的编号，用于列表和跨页面展示；不再另建异常编号。
- 水单处理记录：水单编号、文件 ID、处理批次号、确认金额、付款时间来源、处理状态。
- 真实流水：流水号、入账时间、付款主体、付款账号、收款账号、到账金额、币种。
- 认领记录：水单编号与流水号唯一绑定。
- 核销分配记录：水单编号、流水号、请款单号、运单号、费用项 ID、分配金额。
- 放行申请：放行申请号、回款申请号、版本号、状态、撤销原因、原申请号/新申请号关系；一张放行申请仅对应一个回款申请单。

### 2.2 自动认领接口行为

必须明确查询、提交、重跑匹配、人工认领保存的业务行为：

- 匹配时间条件：付款时间是必填候选过滤条件，且只能取水单 AI 识别值或系统上传时间，不接受业务端传入的手工修改值。`付款时间 < 流水入账时间 <= 付款时间 + 48小时`；时区统一为北京时间，边界是否含等号需研发确认，建议包含结束边界。
- 账号脱敏和比对：不得用脱敏展示值以外的字段绕过账号匹配规则。
- 无候选、多候选、唯一候选分别返回可观察的业务结果。
- 同一流水并发被两张水单认领时，只允许一个成功，另一个返回“流水已被认领”。
- 重复提交、超时重试不得创建重复认领或核销记录，接口必须幂等。

### 2.3 核销分配和事务

- 保存分配时必须同时校验流水余额和费用项余额。
- 多水单共同分配一个费用项时，余额校验必须加锁或使用等价并发控制。
- 水单、费用项、请款单状态必须由分配结果统一计算，不允许前端直接传入最终状态覆盖后端计算结果。
- 尾差只能通过明确的“转客户余额/保留待核销/取消本次核销”业务动作产生。
- 失败或部分失败时，必须明确整体回滚还是按分配明细部分成功；建议一次保存采用全量事务，失败全部回滚。

### 2.4 撤销放行

- 只允许“回款申请已放行，且该申请下没有已实际核销水单”撤销。
- 撤销必须保存原因、操作人、时间、回款申请号、原放行申请号及关联水单号。
- 撤销后重新锁定客户下单状态；新放行申请必须产生新版本/申请号。
- 已核销记录调用撤销核销，不得复用撤销放行接口。

### 2.5 数据同步和日志

- 回款工作台、收款管理、请款单管理、回款协同使用同一业务记录，不得复制出独立状态。
- 日志至少记录：对象 ID、操作类型、操作人/系统、前状态、后状态、金额前后值、账号匹配结果、原因、时间、关联申请/流水/核销记录。
- 状态更新成功但同步通知失败时，主交易不能回滚；必须可重试并告警。

### 2.6 状态、字段和配置来源

- 原“处理阶段”和“处理状态”合并为水单唯一处理状态（自动认领异常、已比对待核销、已核销、待业务补资料、重新匹配中），由后端状态机根据动作和校验结果流转，不允许前端或财务手工修改。
- 放行状态（未申请放行、未达放行条件、待放行审批、已放行、已撤销放行）由放行申请和审批动作写入；水单行只展示该状态，放行比例和审批写入范围按回款申请单计算，初始比例 100%。
- 异常类型来自异常类型字典和匹配规则编码；异常原因由“原因模板 + 本次流水/水单/账单动态参数”生成并保存快照；建议处理由异常类型与当前状态的处理建议映射生成。
- 回款编号来自回款申请主记录；水单编号来自上传水单处理记录；真实流水号、金额、账户和到账时间来自凭证/收款管理；关联请款单、运单和费用项来自请款单及账单数据。
- 48 小时匹配窗口、放行比例、水单金额可调整幅度和币种精度属于配置项；退回原因、重复确认原因和放行结论属于字典值。以上值必须在接口和页面说明中携带来源，不能只写“系统返回”。
- 财务填写的处理说明是人工输入，不得覆盖系统生成的异常原因；重新匹配后生成新的原因快照，历史版本保留。

## 3. 前端仍需补齐的契约

- 提交预核销时展示匹配窗口、候选数量和失败原因；不能只显示“处理失败”。
- 人工认领：多候选必须选择唯一流水；已唯一匹配时隐藏流水选择控件。
- 人工核销：本期入口隐藏，不允许通过其他按钮绕过；先选流水、再展开费用项的交互和校验规则保留在 PRD，后续评审确认入口后再开放。
- 分配金额逐项可编辑，总分配金额、流水剩余金额和费用项剩余金额实时显示。
- 尾差处理必须有明确下拉或单选项，不能通过关闭弹窗隐式丢弃尾差。
- 撤销放行弹窗显示实际核销状态；已核销记录不显示按钮。
- 操作成功后刷新列表、页签条数、申请单处理进度和日志；失败保留用户输入并提示可重试。
- 任何弹窗打开时，外层序号置灰不可点击；弹窗关闭后恢复。
- 异常列表不展示重复的“回款申请”列；列表仅展示“回款编号”，回款申请号仍可用于详情、日志和接口内部关联。
- 水单列表“账户核对”列同时展示付款账户、我方收款账户和各自匹配结果；下方账户字段隐藏但内部值仍参与匹配和提交。
- “待业务补资料”详情必须展示退回来源，并区分认领异常和放行审批；业务可不替换水单直接修改确认金额、账户等确认字段后重新提交，也可替换水单触发重新识别；付款时间始终只读不可修改。
- 补资料详情中识别金额只读，确认金额可编辑；确认金额超出财务配置的上下调整幅度时禁止提交并提示原因。
- 自动放行判断展示“水单确认金额/到期未结算账单金额”比例；低于配置比例进入人工复核，达到或超过才自动放行。
- 异常列表、筛选、详情和导出只展示一个“处理状态”，不得再展示“处理阶段”；“待放行审批”仅展示在放行状态字段。
- 放行审批弹窗/抽屉必须带出同一回款申请下全部待放行水单、确认金额合计、去重后的关联到期未结算账单金额、放行比例和实际核销状态；按钮“同意放行/退回业务补资料”只提交一次申请单级操作。
- 回款申请的水单列表必须显示表头全选和行勾选、识别金额、可编辑确认金额、只读付款时间及来源、可编辑付款账户/我方收款账户及各自匹配标记；删除弹窗下方重复的当前水单确认金额、当前水单付款时间和总核对勾选。
- 上传控件在选择文件时校验本次申请水单总数不超过 5；超出时不写入任一新水单，保留已上传列表。
- 回款协同申请明细筛选区包含客户、运单号、申请时间开始/结束；输入变化后仅刷新查询结果，不清空当前筛选页签或修改数据。

## 4. 测试缺少的验收场景

### 4.1 自动认领

1. 付款时间后 48 小时内唯一流水：认领成功并进入后续核销判断。
2. 正好在 48 小时边界的流水：按最终边界口径验收。
3. 超过 48 小时流水：不得成为候选。
4. 无候选、多候选、唯一候选：分别进入正确状态。
5. 客户付款账号前 4 位+后 4 位匹配、我方收款账号后 4 位匹配、任一匹配失败。
6. 同一真实流水被两张水单并发认领：只能一张成功。
7. 水单付款时间在回款申请和待业务补资料入口均不可通过键盘、日期控件或接口参数被业务修改；识别错误时替换水单生成新识别版本，原版本可追溯。
8. 流水在付款时间前、刚好在付款时间、超过 48 小时、付款时间无系统值或为手工新增凭证时，均不得自动认领。

### 4.2 自动核销和部分核销

1. 水单确认金额等于当前客户全部待支付请款单待结算金额：自动核销成功。
2. 水单确认金额大于待结算金额：自动核销全部待支付请款单，超出金额自动转客户余额并写日志。
3. 水单确认金额小于待结算金额：不得自动核销，进入已比对待核销并由财务人工核销。
4. 一张水单核销多个账单：按费用项分配并校验每项余额。
5. 多张水单核销一个费用项：每张水单独立认领后再汇总分配。
6. 手工新增凭证：不进入自动认领、重新匹配和自动核销候选；仅在收款管理人工流程可见。
7. CNY/USD 两位小数及其他币种精度：按币种精度比较和展示。
8. 多人同时分配同一费用项：不得超分配。

### 4.3 放行和撤销放行

1. 未申请放行：只产生预核销，不产生放行申请。
2. 未达条件申请放行：关联水单展示“待放行审批”，不自动解锁。
3. 同一申请单含多张待放行水单：列表展示多行；从任一水单进入审批后，审批页汇总全部水单，确认一次后同步回写全部水单的放行状态和日志。
4. 审批放行：仅更新申请单及关联水单的放行状态，不改变任何水单的处理状态和核销状态。
5. 已放行未核销撤销：原因必填、客户重新锁定、业务可重新申请。
6. 已核销记录：不显示撤销放行，只能走撤销核销。
7. 重复发起放行：新申请与原申请、撤销日志正确关联。

### 4.4 资料、退款和历史兼容

1. 财务退回资料后只能由业务重新提交，旧批次和日志可追溯。
2. 已核销退款走撤销核销；理赔走理赔流程；不得覆盖原核销记录。
3. 现网收款页面原流程不变，新异常页面处理结果能在收款管理和请款单管理同步展示。
4. 同一水单、流水、请款单多次刷新或重试不产生重复记录。
5. 异常列表同一条记录只出现一个业务编号：展示回款编号，不再展示内容相同的回款申请列；隐藏展示列不影响详情、日志、水单映射和接口关联。
6. 水单列表账户核对同时展示付款账户、我方收款账户；两项匹配状态分别正确，页面下方不再出现重复账户字段。
7. 认领异常退回和放行审批退回均进入同一待业务补资料列表，并正确展示退回来源。
8. 不替换水单重新提交时不生成新的 OCR 识别版本，但会重新执行全量匹配和状态判断。
9. 替换水单重新提交时生成新识别版本，旧识别结果和修改日志仍可追溯。
10. 确认金额向上、向下调整在配置范围内可提交，超出范围不可提交。
11. 水单确认金额低于到期未结算账单金额配置比例时进入人工复核，达到或超过时自动放行。
12. 多个运单关联同一客户的待支付请款单时允许发起；关联不同客户、非当前用户权限客户或部分付款请款单时禁止发起，前后端校验结果一致。
13. 单次上传 1、5、6 张水单以及分批累计超过 5 张时，数量限制、列表和提示正确。
14. 识别金额默认回填为确认金额且不可直接修改识别值；确认金额在/超出配置幅度、账户已识别/未识别/为空、全选/部分勾选时，提交结果正确。
15. 回款协同按客户、运单、申请时间单项和组合筛选；空结果、日期边界、越权客户及各页签组合结果正确。
16. 指派处理人下拉仅展示员工管理中收入管理部门的在职员工；传入其他人员 ID 时后端拒绝并保留原处理人。
17. 回款处理工作台业务员、客服、提交人来自正确的客户/申请主数据；客户人员信息变更后的展示快照口径与研发确认结果一致。
18. 回款协同不展示主申请单状态；预核销状态和放行状态可独立组合、筛选结果和详情回显一致。
