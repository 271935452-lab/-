〇、全天结论摘要（给评审/排期用）
════════════════════════════════

【上午主线】目的港邮箱洪峰 · 查验包否 · 价格表批量 · 大客户调成本
1. ~103 个柜子通知邮箱：滞港/滞箱/AN杂费/到达通知；水单回邮；不付提不到货；付完进业务员成本。
2. 「是否包查验」标记：散货不包加收、包不加收；整柜跟报价是否包查验。
3. 价格表高频维护（全量约 3h）：类别 + 多选批量（多只改时间/金额）；吴总/珊珊宜系统直调；中美普船降 7 毛等规则；特价仓易翻车。
4. 大客户 = 调成本（申请价→财务→导入业务员成本）；要对比系统差额、一步到位；统计导出缺单价。
5. 合同/AN 不签不放行；进口商邮箱难找；SOC/COC、免箱期、PU 码等名词见上午详节。

【下午主线】港前提柜准备 · 港后预约派送与费用 · 整柜海外仓预报
6. 港前：到港前发柜子计划；DO 发海外仓；PU；刷约；整柜预报表；HOLD 抓取预警；报价/运价绑海外仓。
6b. **轨迹/状态**：卸船后每 3 天自动加轨迹；等待提柜每 3 天更新；清关放行后 3 天未提也要更新。预报在主单跟进；按海外仓导出预报模板；非美库付雪（周约二三十柜）。
6c. **改址/拦截**：改地址上系统（支持批量同址）；到港前可拦、提柜后不拦；已预报改址走美库系统。
7. 港后：第一步先汇集自己的资料 → 再跟收件人预约派送（邮件/电话/网站）；亚马逊整柜固定/临时代理；live/drop/卸货重柜/住宅罚金等费用；账单确认升级；多代理碎片化；柜号搜索、单号跳转卡派跟进。
8. 整柜重点：海外仓 DRAYEASY 现需手动在系统预报 → 问袁经理是否有预报接口可对接；整柜报价须带海外仓信息；费用有的收客户、有的进成本。

一、上午（10:25～11:32）· 邮箱 / 查验 / 价格 / 大客户成本

（完整原文结构见：调研纪要_2026-08-04_上午_卢慧恒.txt；此处为整合后保留要点）

1.1 目的港邮箱与费用
· 每天 100+ 邮箱登录（约 103 个；2 月起；路上邮箱也在发）。
· 处理：滞港费、滞箱费、AN 杂费、到达通知；付款水单回邮。
· 不付款 → 目的港提不到货；付完 → 加系统「业务员成本」。
· AN：到达通知，目的港代理 → 进口商邮箱。
· SOC 私人柜：代理箱-还箱、客户柜-不需要还箱 / COC 船司柜；港内免箱期卡最后一天提；港外免箱期 4+8。
· PU 提柜号（上火车柜子）给收货人邮箱、火车站提柜。- 文件和文字上系统、尾端客服是否需要看到？-先把邮箱的这一步优化
· 合同：法务审核 → 改点 → 签字页回传 。供应商的营业执照、合同。(外配的尾端的货物交给哪个供应商，供应商的时效是否影响头程的时效。（要跟美库关联）)
AN 回传目的港邮箱（一天十几个）；不签不放行。
· 申请滞港费跟船司发邮件；异常提不了跟国内同事沟通。-非业务端口的备注
· 查验车架费：问海外仓有无用车架，没用退回。船司的账单和检查站的账单重叠。查验-还柜。查验是邱水平那边的。是否能进预估？根据历史数据沉淀。
· 待确认：Foxmail 能否回复；还柜「不会抓」。

1.2 查验包否
· 系统标记「是否包查验」。
· 散货：包 → 不加收；不包 → 加收。
· 整柜：根据报价是否包查验。

1.3 价格表，调价日志
· 近一周调整频繁；全量约 3 小时。
· 批量：多选列表；加「类别」批量加/调；多数只改时间+金额。
· 中美普船统一降 7 毛；抛货/重货计费重规则不一（有的有规则有的无）。
· 珊珊/吴总给价晚 → 更新晚 → 建议系统直调。
· 特价仓经常调，易出问题。
· 分区管理新：新排除重复项。
· 艺星快船：我方邮件取消；代理截单放舱时邮件+备注取消。
. 下单和改完仓库或者地址没价格了-修改了之后会重算，配仓前没费用提示业务员和客服。

1.4 大客户 = 调成本
· 申请价手动给财务 → 导入业务员成本。
· 诉求：与系统价对比差额；能否一步到位。
· 业务数据统计导出缺「单价」字段。

二、下午 · A 港前（含 13:35～14:13 付雪补点）
════════════════════════════════
口径：到港前要把柜子计划、DO、预报、约提柜准备好；保证海外仓/代理能正常提柜。
补点口径：付雪侧（非美库一周约二三十柜）+ 轨迹/状态自动更新 + 预报/改址/拦截。

【到港前计划与文件】
· 到港前发「柜子计划」。
· DO 要发给海外仓，保证到港之前正常提柜。
· DO 等文件找陈秋玉邮箱。——上传系统标记，夜班干；对接到海外仓邮箱发送。
· 转货车的 PU（提柜/转运相关码）。——传系统 / 群消息 / 邮箱。
· 「后续处理不了」——部分异常后续兜不住（需流程/系统兜底）。——付雪确认场景。

【轨迹 / 状态自动更新（头程 · 港前关键点）】
· 头程预报柜子：卸船后柜子 → **每 3 天自动加一条轨迹**。
· 「等待提柜」→ **每 3 天更新一次**（状态仍为等待提柜）。
· 清关放行后等提柜：若 **3 天没提**，也要更新提柜相关轨迹/状态（避免静默挂起）。
· 状态口径补充：等待卸船、等待提柜（港前可视）。

【柜子预报 · 主单跟进 · 模板】
· 柜子预报做在「主单跟进」；需导数据。
· 有私卡货：私卡成本目前在**询价时填**（后续与实际费用登记衔接）。
· **非美库**柜子：付雪侧做；一周除美库外约 **二三十条**。
· 每个海外仓各自「导出预报模板」（按仓模板导出，减手拼）。

【一件代发 / 整柜分工】
· 一件代发：群里对哪些单号做一件代发 —— **费时间**（系统应可标渠道/清单）。
· 一件代发渠道下单 → 都是**自提**；一件代发**只跟踪到轨迹**。

【改地址 / 备注 / 拦截（到港前优先）】
· 批量改到同一地址：现状一个柜子单票改；多在表格改、**系统没改** → 诉求：**修改地址上系统**；支持批量改同址。
· 不同柜子一起送、留仓 → 放备注（一件代发备注 / 留仓备注）。
· 私卡改地址 → **拦截**。
· 快递 / FBA 拦截：先确认能不能拦；**最好到港前拦**；**提柜之后就不拦了**。
· 客户未付款、财务要求拦截：同样 **提柜后不拦**。
· 提柜到仓之后 → 交对应负责人（进入港后分工）。
· 改计划时机：
  - 还没做计划 → 在计划里改；
  - **已预报过柜子** → 在**美库系统**上改；
  - 计划之后改 → 也在美库系统改。
· 船务装柜换船 / 关务查验换船（换船信息需同步港前可见）。
· 非常规业务多下**自提**（下到吴慧俊、袁华君）；M1 开头单据按经验看能否按明细下。
· 拆柜 / 丁鑫（口径待补全）。

【提柜准备 / 预警诉求（港前侧）】
提柜异常背景：柜子倾斜平板车、超重、SOC、滞港费等特殊备注规则，提前告知海外仓，指定提柜地点（陈秋玉 AN 邮箱）。
诉求清单：
1. 刷约：有「约提柜约」（视不同目的港服务情况，带车架的柜子不用预约）——预计提柜？费用人工录成本。
2. 整柜预报表：提前给海外仓预报。
3. HOLD 等状态（抓取码头网站；类似海放码；抓到正常、抓不到标记）→ 提柜预警。
4. 前端报价同步海外仓 → 尾端分配提柜商确认依据。
5. 费用影响面：仓储费、预提费、空跑费、滞箱费、滞港费等。——整柜统一尾端录入（进预估）；是否有人跟进还柜（跟王总确认）？
6. 提柜算到送仓的仓储费；预提约 200 美金（口径）。

【报价 / 运价 / 海外仓绑定（港前数据准备）】
· 跟运价绑定之后直接绑定报价；并绑定海外仓。
· 整柜报价要加上海外仓信息。
· 整柜报价费用：有的收客户，有的归属成本（需字段/规则拆分）。——只自动加成本，应收不加。
· 私卡的实际费用：海外客服登记。

【谁做】
· 整柜：海外仓安排。
· 港前港后同一人处理。

【DRAYEASY · 预报对接（重点）】
· 现状：海外仓 DRAYEASY 需要手动在系统里做预报。
· 诉求：DRAYEASY 是否有对接预报的接口？
· 动作：问袁经理确认接口能力与对接可行性。
· 关联：到港前柜子计划 + 整柜预报表提前给仓 + DO 发海外仓。

【整柜报价】
· 报价须带上海外仓信息。
· 运价绑定 → 直接绑报价 → 再绑海外仓（串起来减少漏绑）。
· 费用拆分：部分收客户 / 部分进成本（与「大客户调成本」、业务员成本体系对齐）。

【整柜代理】
· 亚马逊整柜：固定代理或临时代理。
· 多柜多代理并存，分配依据希望用「前端报价同步海外仓」确认提柜商。
· 预约派送渠道：邮件、电话、网站。
· 亚马逊整柜：固定代理或临时代理。
· 十几个柜子可能对应七八个代理（碎片化强）。
