背景与痛点 · 我们解决什么问题

业务背景

工单入口分散在提单、运单、尾单跟踪、海外仓协同和异常页签；业务不知道从哪里发起，主管难以看全量待办。工单发出后与海外仓缺少统一数据联动，处理完成后关联运单、柜、地址、异常标记和费用往往未同步。

核心痛点

  • 业务需求轻、执行重：登记台只记事实与跟进，真正要人办、要协同、要回写的事项缺少统一执行中枢。
  • 转单不清：现网宽表场景配置与统一工单执行字段混杂，A（转单前需求）与 B（统一工单执行）边界模糊，映射规则散落。
  • 状态与回写口径分散：失败是否改状态、母工单与指令版本关系、海外仓完成是否等于结案，开发与验收难对齐。
  • 配置重复维护：场景字典、审批流、SLA、回写白名单多处拷贝，一改多处漏。

本期要解决什么

  • 改 现网「海外跟进」「改派重出(GW)」功能页下线：跟进 / 重出一律在履约工作台（及提交入口→新建）处理，不再保留平行登记口。
  • 快递异常事实若仍需字典登记，仅保留快递异常件轻量登记；要人办直接进统一工单，不经海外跟进/GW 中转。
  • 用工单配置中心维护场景配置与状态流模板（两页互链），替代现网宽表场景配置与可拖拽全流。
  • 母工单 + 指令版本承载拦截、换标、重出等后续要求；失败/拒绝/超时保持当前状态（C-09）。
  • 旁支计划二 #9–#12（非美库 / 改快递重出 / 港前·港后拦截）纳入同一配置与状态骨架；入口收敛为工作台 / 提交入口。

2.2 业务主链路

  1. 发起（BR-ENTRY-001）：客服/业务提交 → 直接创建一张独立工单。资料不全只保存发起页草稿，不进入履约工作台。
  2. 配置命中：工单配置命中场景 → 引用状态模板 → 按模板首节点派至责任岗位/工单池。
  3. 执行链：受理 → 执行 → 提交结果/附件/实际费用 → 按模板进入待审批 / 待费用审核 / 待客服验收等节点。
  4. 验收与回写：海外仓/执行人提交结果不等于完成，须客服验收通过后回写业务数据；本工单完成或关闭。
  5. 本单完结（BR-STS-009）：本单无待费用、待回写、待验收即可结案。新要求另建独立工单并填关联工单号。
  6. 失败/超时（C-09）：失败、超时、回写失败不改变业务状态，停留当前状态并增加异常标记。

3.0 流程与交互口径（原页顶说明）

配置粒度：工单类型 + 港前/港后 + 海外仓。例如「港前拦截 + 美库」和「港后换标 + 美库」分别配置头程修改字段、推送字段、完结回写字段，不能所有工单共用一套。其他海外仓不推送美库，只配置人工登记后的头程更新字段。

3.4.1 头程修改与美库推送

适用于港前，或任何需要先改头程数据的场景。客服不勾选「要不要推送」；点「确认并推送美库」后按本组合配置执行。

工单确认执行 → 修改头程柜子/运单数据 → 保存修改后的头程数据 → 按最新数据生成推送快照 → 推送美库 → 记录美库工单号、推送版本和结果。

港前拦截 + 美库的典型配置：

  • 头程修改字段：柜子计划 Move Type = 留仓
  • 头程备注：柜子备注追加拦截工单号、指令、时间、操作人
  • 推送字段：柜号、客户单号、货物信息、最新 Move Type、操作要求、附件、费用确认信息
  • 推送触发：点击「确认并推送美库」
  • 推送失败：头程修改保留，工单进入「推送失败待重试」，不得回滚为原 Move Type

头程修改对象仍仅两类：拆柜计划（Move Type / 柜子备注 / 操作标记）、运单信息（收货地址 / 尾程派送方式 / 拦截状态 / 少件标记）。禁止覆盖「原渠道」。

3.4.2 美库完成与头程回写

适用于美库处理完成、关闭、异常等回传事件。

美库完成操作 → 美库回传工单号、状态、结果、附件、实际费用 → 匹配头程工单和柜子/单号 → 更新头程对应数据 → 工单进入已处理、异常或完结。

按工单类型勾选可回写字段：美库工单号；海外仓处理状态；处理结果/异常原因；操作完成时间；回传附件链接；新单号、面单等结果数据；实际操作费用（写入头程应付，BR-FEE-001）；工单处理日志。

3.4.3 关键状态

待修改头程数据 → 待推送美库 → 已推送 / 推送失败待重试 → 美库处理中 → 回写头程中 → 已处理并回写 / 回写失败待重试 / 美库无法处理 → 工单完结。

失败不回滚头程：推送失败停在「推送失败待重试」，已保存的 Move Type / 备注保持；回写失败停在「回写失败待重试」，不把已推送的美库结果清掉。允许按权限重试。

测：打开「港前·柜子计划拦截换标」与「换标·港后」，两者的头程修改字段和推送字段不同；切到「其他海外仓」时推送链路关闭，且没有美库工单号可回写。

5.2 执行—验收双阶段闭环

分册详述：统一工单-状态流转 · BR-STS-007。

客服/业务发起指令 → 路由执行岗位/海外仓 → 执行人提交结果/照片/费用/无法执行原因 → 客服验收
  ├─ 通过：完成 / 回写业务数据
  ├─ 不通过：退回原执行人返工（同一指令，不建 V2；不允许任意改派）
  └─ 无法执行：客服确认原因后直接关闭当前指令（不自动生成后续指令）
  • 国内仓操作在 PDA，只能提交结果；海外仓在仓系统回传。都不能自行完结工单。
  • 客服负责下达与验收，不承担拍照、测量、换标等一线操作。
  • 改 「无法执行」经客服确认原因后进入已关闭；不自动生成后续指令。若客户另有新要求，由人工新建后续指令（升版）。
  • 改 验收不通过：只能退回原执行人返工，不允许任意改派。例外：场景规则允许时（如「改快递」需切换港后客服责任范围）可改派至对应港后客服（BR-REWORK-001）。
  • 客户新要求（如先拦截再换标）才建 V2；验收返工不建 V2，退回「待执行/执行中」并记原因/次数/附件要求。
  • 改 母工单完结（C-10 / BR-STS-009）： 
    母工单处理中
→ 子工单 V1：拦截
→ 子工单 V2：拍照
→ 子工单 V3：换标
→ 所有子工单完成、无待确认事项
→ 母工单完结
    不以「货物终结」作为关母单前置；详 状态流转 PRD · BR-STS-009。
  • 核心目录与默认岗位见状态流模板页 / BR-STS-008。

测：无法执行关闭后无自动 V2；验收退回处理人不变；改快递场景可演示规则改派；仓侧无完结按钮。

5.3 四类状态对象边界

母工单状态、指令工单状态、外部执行状态、费用/回写状态 — 分开保存，禁止混成一个可拖拽大枚举。海外仓「已完成」≠ 指令完成 ≠ 母工单结案。配置中心：工单配置引用状态模板；状态模板内配置节点（含待审批、待费用审核、待客服验收等）及前后置。

已确认 一期无「业务记录阶段 / 待转业务记录」；草稿仅发起页。费用审核与审批均为模板内节点，不是平行流程。

测：模拟推送失败/回写失败后状态字不变，时间线追加失败记录与异常标记、重试按钮。

六、旁支计划二场景 #9–#12

侧栏短卡 + 测： 见 计划二分册；总册索引 旁支计划二 #9–#12。

#9 发起类型 · 非美库

  1. 流程与美库类同（履约工作台 / 统一工单执行），但不对接美库。
  2. 费用、备注、改单须人工标记；不推美库仓工单、不自动贴标附件下发。

测：非美库场景提交后工作台可见；无「推美库」自动动作；费用状态可人工改。原型：提交入口 · 新建

#10 改快递 · 需重出（美库）

  1. 改 唯一履约入口：履约工作台 / 分类提交 → 新建；不经海外跟进 / GW。
  2. 改 流程匹配（BR-WO-017）：自动按名称匹配工单流程/场景 「重出」；匹配不到则报错阻断，不模糊匹配其它名称。
  3. 改 按子单重出：发起粒度为快递子单（非子单根运单整票）；多子单分别建指令、分别回填新单号，均挂同一母工单。
  4. 流程：确认费用 → 下重出费用单 → 腾信按子单重出回填 → 打单/地址确认 → 推美库（贴标附件）→ 状态/费用同步。

测：配置有「重出」可建单；无「重出」报匹配不到；仅填根运单无子单号校验失败；两子单各出指令。原型：提交入口 · 新建·重出

#11 快递拦截 · 港前

  1. 入口：港前节点 / 统一工单「快递拦截·港前」/ 履约工作台新建。
  2. 关联：独立工单 + 关联工单号 + 美库执行单（BR-WO-016）。
  3. 流程：母工单处理中 → V1 拦截 →（新要求）V2 拍照 → V3 换标 → 所有子工单完成且无待确认事项 → 母工单完结（BR-STS-009 / C-10）；费用/附件挂各版本。

测：详情 #WO-202605-INT 可见指令版本链；改令后版本号递增。

#12 快递拦截 · 港后

  1. 入口：快递异常件（可选）/ 尾程快递件 / 统一工单「快递拦截·港后」/ 履约工作台新建。不经海外跟进。
  2. 关联：同 #11 三级关系；港后与港前分流，母工单仍按根货件不断链。
  3. 流程：版本链同 #11；解拦 / 失败 / 已交承运商对齐 Q-WO-004。

测：快递异常件转工单带港后场景；详情版本链与港前同构、入口标签区分港后。

工单异常标记（跨页 · 计划二挂总册）
