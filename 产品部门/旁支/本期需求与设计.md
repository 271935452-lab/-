已分配（待装柜及之后）、已作废：退运按钮拦截。

1. `pickNoList` 非空；提单存在。
2. **仅待分配**：复用列表口径 `LOADING_COMPANY_NO1 IS NULL`；且 `STATUS` 不属于已作废类（`已作废`、`换船-已作废`、`换柜换船-已作废`）。

对每个目标行：

1. 有正式提单：更新 `S_SCAN_PICK_BILL.STATUS = '已作废'`；空号占位按上节校验第 6 条处理。
2. **禁止**向业务标记字段写入「退运」。
3. 有金额且有正式 `pickNo` → 写提单预估：`billType=提单`，`billNo=pickNo`，`costNo=A87`，`flagState=1 已确认`，不进业务员成本、不进柜应付；`dataFrom=提单退运`。空号无正式号时**不允许录费**（或前端禁用金额）。
4. **已定稿（Q1=A）**：**不**解绑仓位、**不**回退运单节点/状态。
5. 操作日志：  
   `退运: [柜:xx, 提单:xx|空号, 状态:待分配→已作废, 退运费A87:币种 金额 · 挂提单预估|无]`

### 1.6 子项 C · 改单同步运单（详细设计）

#### 1.6.1 改造点（已定稿）

- 接口仍为：`POST /bussSailingPosition/saveBooking`
- 入参增加：`syncOrder`（Integer：`null` / `0` / `1`）

| syncOrder | 行为 |
|-----------|------|
| 0 | 只保存仓位 + 草稿（及现有 saveBooking 逻辑），**不**改运单主数据 |

1. 仓位已绑定运单（`BILL_NO` 非空）。
2. `syncOrder == 1`。
3. 相对库内旧值，白名单字段至少有一个变化（无变化则不写运单、不报错）。

#### 1.6.3 同步字段白名单（已定稿）

| `etd` | `EXPECTED_ETD` | 是 |

#### 1.6.4 写库顺序

3. 日志：`完善提单同步运单: [起运港:旧→新, …]` 只列变更字段。

**请求体：**

| 字段 | 必填 | 说明 |

**校验：**

2. 每个 pickNo 对应 `S_SCAN_PICK_BILL` 存在（报关列表主数据若是终配舱维度，需确认主键到底是 `pickNo` 还是 `finalStowageNo`——**见 2.4.1**）。

#### 2.4.1 主键口径（已定稿 + 联调适配）

现网报关写费用多从终配舱取 `pickNo`（见 `customsPassNew`）。列表勾选展示的是提单号。

**接口同时接受其一（互斥）：**

- `pickNoList`：直接写预估；
- `finalStowageNoList`：查终配舱得 `pickNo`，无提单则失败「未绑定提单不可登记费用」。

前端传哪种以联调为准，后端两种都实现即可，不算产品问题。

### 2.5 写库步骤

1. 解析得到待处理 `pickNo` 集合（去重）。
2. 预加载费用类型、汇率。
3. 双重循环：`for pickNo : pickNos` × `for fee : feeList`：
   - 组装 `BalancePayEstimate`：
     - `billNo = pickNo`
     - `billType = "提单"`
     - `costNo / costAmount / currencyNo / rate / amountCny / notVerifyAmount`
     - `flagState=1`，`flagName=已确认`
     - `isShare=0`，`isSyncSub=1`
     - `feeTime=now`
     - `businessNode=报关环节`
     - `dataFrom=报关费用登记`（与放行顺带加费的 `报关环节` 区分来源）
     - `remark`：仅单笔说明；整单备注只进日志
     - `serviceNo`：报关供应商有则填，无则允许为空（列表登记不因缺供应商失败）
     - owner 公司字段：从提单或终配舱带，对齐 `buildPayEstimateCustoms`
   - 优先 `saveBatch`；汇率按币种缓存，避免循环查库。
4. 操作日志汇总：  
   `报关费用登记: [提单:a,b; 笔数:2; 整单备注:xxx; 明细:国内-报关费-CNY100, …]`
5. **不**发邮件、**不**写水单、**不**写业务员成本、**不**写柜应付。

展开条数：`pickNo 数 × feeList 数`。例：2 票 × 3 笔 = 6 条预估。

### 3.3 现网缺口（已核对）

| 能力 | 现状 |
|------|------|
| `S_SCAN_FINAL_STOWAGE_CUSTOMS` | 有报关状态/查验/客服等；**无**核准标记、资料员、改单标记列（Oracle DESCRIBE 已核实） |

### 3.4 数据模型（已定稿草案）

挂在报关维主表 `S_SCAN_FINAL_STOWAGE_CUSTOMS`（主键 `LABEL_NO` = 终配舱 labelNo；列表行通过终配舱关联提单号）。

建议新增列（SQL 脚本实现时落 `docs/旁支计划一/sql/`）：

| 列名 | 类型 | 含义 |
|------|------|------|
| `APPROVE_FLAG` | NUMBER(1) 或 VARCHAR2(10) | 核准标记：0/未核准；1/已核准。默认 0 |
| `APPROVE_TIME` | DATE | 核准通过时间 |
| `APPROVE_MAN_NO` | VARCHAR2(32) | 核准人编号（= 资料员编号口径） |
| `DOCUMENTATION_SPECIALIST` | VARCHAR2(50) | 资料员展示名或工号；列表「资料员」列。退回置空 |
| `CHANGE_ORDER_FLAG` | NUMBER(1) 或 VARCHAR2(20) | 改单标记：0 无；1 改单中/改单（与船务业务标记同列语义，取值以列表筛选字典对齐，见下） |
| `CHANGE_ORDER_REMARK` | VARCHAR2(500) | 最近一次退回「改单说明」 |
| `CHANGE_ORDER_TIME` | DATE | 最近一次写改单标时间 |

**改单标记展示口径（已定稿）：**

- 报关列表业务标记出现「改单」（与船务换柜换船写下的改单标**同列展示**）。
- 本需求退回写入的是关务侧改单标；不要求本接口去改船务提单上的换船场景码（①②③）。
- 若现网业务标记是拼接字符串字段，实现时查报关列表实际用的标记列/组装逻辑，往同一展示管道写入「改单」；**禁止**另造一列前端看不到。

**资料员（已定稿）：**

- 核准通过：`DOCUMENTATION_SPECIALIST` / `APPROVE_MAN_NO` = 当前登录用户。
- 退回修改：两字段清空（列表显示 —）。
- 再次核准：按新操作人覆盖。

### 3.5 状态机

```
未核准（APPROVE_FLAG=0，分票可编辑）
    └─[核准通过]→ 已核准（APPROVE_FLAG=1，分票锁定；写入资料员）
         └─[退回修改]→ 未核准（解锁）；清空资料员；CHANGE_ORDER_FLAG=改单；可选写费用
              └─可再编辑 → 再核准通过…
```

校验：

- **核准通过**：当前必须未核准；买单轧差为负不可核准（若分票未做，本接口可不校验轧差——轧差属分票主干；#3 最小核准只做标记写入）。
- **退回修改**：当前必须已核准，否则失败「未核准无需退回」；**已核准态点退回必出弹窗**（前端）；后端仍要校验已核准。

### 3.6 接口设计

#### 3.6.1 核准通过（前置最小集）

- `POST /customs/approveDocumentation`（名可再定，挂 `CustomsController`）
- 入参：`labelNo` 或 `pickNo` / `finalStowageNo`（与报关列表主键对齐，建议 `labelNo` + 可选 `pickNo` 校验）
- 行为：
  1. 查 `S_SCAN_FINAL_STOWAGE_CUSTOMS`；不存在则失败。
  2. 已是已核准 → 失败或幂等成功（建议失败「已核准」）。
  3. `APPROVE_FLAG=1`，`APPROVE_TIME=now`，`APPROVE_MAN_NO`/`DOCUMENTATION_SPECIALIST`=当前用户。
  4. 操作日志：`核准通过: [资料员:xx]`。
- **不做**：分票锁定以外的舱单重推、品牌授权（PRD 已移除）。

#### 3.6.2 退回修改（#3 主接口）

- `POST /customs/revokeDocumentationApprove`
- 事务：`@Transactional(rollbackFor = Exception.class)`

**请求体：**

```json
{
  "labelNo": "终配舱报关主键",
  "pickNo": "COSU6502971850",
  "changeOrderRemark": "改单说明，可空",
  "feeList": [
    {
      "feeBigClass": "国内",
      "costNo": "D38",
      "costAmount": 100,
      "currencyNo": "CNY",
      "remark": "改单费"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| labelNo 或 finalStowageNo/pickNo | 是 | 能唯一定位报关维；实现时与列表勾选主键一致 |
| changeOrderRemark | 否 | 改单说明 |
| feeList | 否 | 空=不录费；有则每笔字段同 #2 精简版。Q4=B 时可忽略本字段 |

**校验顺序：**

1. 定位报关记录存在。
2. `APPROVE_FLAG` 必须为已核准。
3. 若 `feeList` 非空：金额/币种/费用类型校验同 #2；`pickNo` 必须能解析到（挂提单预估）。

**写库步骤：**

1. `APPROVE_FLAG=0`；`APPROVE_TIME`/`APPROVE_MAN_NO` 可保留历史或清空（**建议保留历史核准时间备查，但资料员展示字段必须清空**）。
2. `DOCUMENTATION_SPECIALIST` 置空。
3. `CHANGE_ORDER_FLAG` 置为改单；`CHANGE_ORDER_REMARK`/`CHANGE_ORDER_TIME` 更新。
4. 若业务标记是拼接字段：追加/写入「改单」，保证报关列表业务标记列可见。
5. `feeList` 非空且 Q4=A：按 #2 逻辑写 `S_BALANCE_PAY_ESTIMATE`，`billType=提单`，`dataFrom=做资料退回修改`（改单费可用 `D38`）。
6. 操作日志：  
   `退回修改: [核准:已核准→未核准, 资料员:xx→空, 改单标:写入, 改单说明:…, 费用:有|无]`

**成功后前端**：分票可再编辑；列表资料员为 —；业务标记有改单。

### 9b.4 接口设计

**新建（推荐，勿塞进 `customsPassNew`）：**

`POST /customs/saveReturnBill`

| 入参 | 规则 |
|------|------|
| `pickNo` 或 `finalStowageNo` | 二选一必填；解析出本柜运单范围 |
| `billNoList` | **当前应标记为退运的运单全集**（替换语义）；空数组=清除本柜全部国内退运标 |

**步骤：**

1. 校验柜/终配舱存在；查出本柜全部 `billNo` 集合 `S`。
2. `billNoList` 中任一不在 `S` → 失败（禁止跨柜乱标）。

**查询回显：**

- `getPickOrderList`（及分票/报关单维子表若同源）SELECT `CUSTOMS_RETURN_FLAG`，供子表勾选框回显。

**禁止事项写进接口注释：** 不调用 `rollBackOrderNode`、不改提单 `STATUS`、不写清关退运表。

### 二.3 指标公式（已定稿 · 与 PRD 一致）

| 指标 | 公式 |
|------|------|
| 总票数 | 筛选范围内已签入运单数 |
| 实查票数 | `INSPECTION_PIECE > 0` |
| 查验空白 | `INSPECTION_PIECE` 为空或 0 |
| 保函豁免 | 空白票中已存在类型「保函」附件 |
| 漏查票数 | 空白 − 保函豁免（含：无附件且已确认漏查；无附件且待确认也先计入漏查分子——见下「确认」） |
| 应查票数 | 总票 − 保函豁免 |
| 查货率 | 实查 / 应查 × 100%；应查=0 → 展示 100% |
| 达标 | 率 ≥ 100% → 已达标，否则未达标 |

**确认漏查（待确认行）：**

| 保函展示 | 条件 | 操作 |
|----------|------|------|
| 有保函 | 已上传保函附件 | 可预览/下载；不计漏查 |
| 待确认 | 空白 + 无保函附件 + 未确认漏查 | 显示「确认漏查」 |
| 无保函 | 空白 + 无附件 + 已确认漏查 | 计入漏查；无确认按钮 |

落库（新建列，建议挂 `S_BUSS_ORDER_VERIFY`）：

| 列 | 含义 |
|----|------|
| `MISS_CONFIRM_FLAG` | `1`=已确认漏查（无保函） |
| `MISS_CONFIRM_TIME` / `MISS_CONFIRM_MAN` | 审计 |

> 漏查统计：空白且无保函附件（不论是否已点确认）均计入漏查；「确认」只把待确认→无保函，避免重复点。若产品要「待确认暂不计入漏查」，与 PRD「漏查=空白−豁免」冲突——**以 PRD 为准：无附件即不豁免=漏查**；确认仅改展示态。

| 到港时间 | 实际到港 | `S_SCAN_PICK_BILL.ACTUAL_ARRIVAL_TIME`（空则主单跟进 `NEW_ARRIVAL_TIME` 兜底，与列表同源优先） |
| 海外仓 | 拆柜仓 | `S_TAIL_PICK_BILL_FOLLOW.OVERSEAS_WAREHOUSE`（或集装箱 `OVERSEAS_STORAGE_CODE` 映射名；筛「美库」按仓名/编码判定） |
| 到仓时间 | = 提柜时间 | `BussOrderTrack`（提单维）`A00195.TRACK_TIME`；空则 `ACTUAL_PICK_TIME` |
| 提柜时效（天） | 到仓 − 到港 | 按自然日差；>5 → 标红 + 「提柜超5天」页签 |
| 拆柜日期 | 业务拆柜日（周归属锚点） | `S_OVERSEAS_STORAGE_CONTAINER.UNSTOW_TIME`；空则 `DEVANNING_TIME` |
| 等拆时效（天） | 拆柜日期 − 到仓 | >2 → 标红 + 「等拆超2天」页签；缺任一侧则时效空、不进超时页签 |
| 开拆 / 拆结 | 美库导出时刻 | 同柜货件行上 `UNSTOW_TIME_START` / `UNSTOW_TIME_END`（柜层解析后同值）；非美库空 |
| 拆柜耗时 | 拆结 − 开拆 | 小时（可带小数）；仅美库；>2h → 整行粉底+耗时红字 + 「拆柜超2小时」页签 |
| 总件数 | 柜下子单件数合计 | `S_BUSS_ORDER_SUB` 且已配柜（`PICK_FLAG=1` 且 `PICK_NO=`） |
| FBA/票 · 私卡/票 · 自提/票 | 运单票数按派送方式 | `DELIVERY_TYPE`/`DELIVERY_TYPE_STATUS`：`FBA派` / `私卡派` / `自提`（字典 `P_GUID=20A11138013E28F5E0630B0010AC7379`） |
| 联邦/件 · UPS/件 | 子单件数按单号前缀 | 字典 `P_GUID=2AB3F9DE4FAD4AD3E0630B0010ACCA73`；FEDEX/UPS 正则（与主单跟进 SQL 一致） |
| 异常信息 | 提拆柜计划 → 查看拆柜报告 → **拆柜异常反馈** | 有则原样展示；无报告/无反馈 →「—」；**不**拼提柜/等拆人工 `REMARK` |
| 限时达 | 页签过滤 | 船司/产品名含「限时达」（T16限时达、T20限时达、加班限时达等） |

**统计周：** 自然周周一～周日；柜是否进周 = **拆柜日期**落在该周（原型「拆柜归属」）。无拆柜日期的柜：不进「导出本周」；自定义日期筛时是否纳入「当前列表」——按当前筛的日期字段若用户改筛「拆柜日区间」则跟筛，默认周视图只看有拆柜日的。

### 五.1 交付边界

| 能力 | 是否纳入 |
|------|----------|
| 列表双列：未确认实际金额 / 修改后金额 | **是** |
| 行内/勾选「修改实际费用」抽屉（金额/币别/汇率/原因/备注） | **是** |
| 未分摊直接改 vs 已分摊对冲分流 | **是** |
| 一键改为预估金额；抽屉「填入预估金额」 | **是** |
| 分摊只摊勾选费用行（修改后金额） | **是**（沿用并收紧口径） |
| 列表筛/现网其它列/导入实付/账单确认/付款请款 | **否（本期不复述）**：沿用现网，不因本旁支重做 |
| 改预估费用表、对冲科目细则重设计 | **否**：对冲复用现网 `hedgePayShareDetail` |

### 五.2 现网与缺口

| 项 | 现网 | 本期 |
|----|------|------|
| 入口 | `POST /balancePayDetail/getPickPayList`（`BILL_TYPE=提单`） | 列表加列；改费扩接口 |
| 金额 | 仅 `COST_AMOUNT` | 拆成未确认 + 修改后 |
| 改费 | `updateBatch` **仅** `FLAG_STATE=0` 草稿 | 未分摊均可直接改；已分摊走对冲 |
| 对冲 | 重摊/覆盖/总值时有 `hedgePayShareDetail` | **已分摊改金额**也必须先对冲 |
| 一键对齐预估 | 无 | 新增 |
| 修改原因 | 无字段；仅操作日志文本 | 必填原因码 + 备注 |
| 预估 JOIN | `BILL_NO+COST_NO+CURRENCY_NO`（缺服务商） | 对齐预估时补 `SERVICE_NO`（预估表有该列） |

### 五.3 数据模型（DDL）

表：`S_BALANCE_PAY_DETAIL`

| 列 | 含义 | 规则 |
|----|------|------|
| `UNCONFIRMED_COST_AMOUNT`（新） | 未确认实际金额 | 导入/账单/新增写入；**修改接口禁止更新** |
| `COST_AMOUNT`（沿用） | 修改后金额 | 折合 RMB、分摊、对冲均按本列；默认=未确认 |
| `CURRENCY_NO` / `RATE` / `AMOUNT_CNY` | 币别/实际汇率/折合 | 改费时可改币别汇率；`AMOUNT_CNY=COST_AMOUNT×RATE` |
| `IS_SHARE` | 0待分摊 / 1已分摊 / **2待重新分摊** | 已分摊改费对冲后置 `2`（对齐预估表注释口径） |
| `MODIFY_REASON`（新） | 修改原因码 | 见下枚举 |
| `MODIFY_REMARK`（新） | 修改备注 | 「其他」建议必填备注 |
| `MODIFY_TIME` / `MODIFY_MAN_NO`（新，建议） | 最近一次旁支改费审计 | 与通用 `UPDATE_*` 可并存 |

**历史数据迁移：** `UNCONFIRMED_COST_AMOUNT = COST_AMOUNT`（一次回填）。

**修改原因枚举（与原型一致，可落字典）：**

| 码/文案 |
|---------|
| 代理账单金额错误 |
| 实际账单与预估不一致 |
| 对齐预估金额 |
| 汇率调整 |
| 费用漏录 / 补录 |
| 其他（见备注） |

### 五.4 状态与分流（核心）

**列表分摊页签（原型）：** 全部 / 待确认 / 待分摊 / 已分摊  

| 页签 | 判定（建议） |
|------|----------------|
| 待确认 | `FLAG_STATE=0`（草稿） |
| 待分摊 | `FLAG_STATE≠0` 且 `IS_SHARE∈{0,2}`（含待重新分摊） |
| 已分摊 | `IS_SHARE=1` |

**改费分流（不得混用）：**

```
选中费用行
 ├─ IS_SHARE ≠ 1（未分摊：待确认/待分摊/待重新分摊）
 │    → 直接更新 COST_AMOUNT / 币别 / 汇率 / AMOUNT_CNY
 │    → 写 MODIFY_* ；UNCONFIRMED 不动
 │    → 不对冲、不改 IS_SHARE（已是 2 则保持 2）
 └─ IS_SHARE = 1（已分摊）
      → 调用现网 hedgePayShareDetail（对冲 S_BALANCE_PAY_SHARE_DETAIL / S_BALANCE_PAY_ORDER，FLAG_STATE=5）
      → 再写新 COST_AMOUNT / 币别 / 汇率
      → IS_SHARE=2（待重新分摊）；UNCONFIRMED 不动
      → 写 MODIFY_* + 操作日志（含对冲说明）
```

对冲科目/凭证形态 **不对齐重做**，复用现网实现；PRD 只定分流。

### 五.5 分摊（收紧口径）

| 点 | 口径 |
|----|------|
| 入口 | 现网 `shareByPayDetailList`（勾选 `payDetailNoList`） |
| 金额 | **只用修改后金额** `COST_AMOUNT`（含已调整） |
| 范围 | **仅勾选行**；同柜未勾选费用项保持原分摊，禁止整柜隐式重算 |
| 已分摊行 | 须先改费对冲→待重新分摊后，再点分摊；或分摊前对已分摊勾选行先走现网「重摊前对冲」（与现网 `IS_SHARE==1` 再摊一致） |

### 五.6 一键改为预估 / 填入预估

| 入口 | 行为 |
|------|------|
| 工具栏「一键改为预估金额」 | 勾选 ≥1 且均为**未分摊**；`COST_AMOUNT`←匹配预估 `COST_AMOUNT`；原因默认「对齐预估金额」；未确认列不变 |
| 抽屉「填入预估金额」 | 仅回填抽屉内「修改后金额」编辑框，保存仍走分流接口 |
| 已分摊勾选 | 一键对齐：**拒绝**或逐条走对冲分流（建议拒绝并提示先改费对冲，避免批量静默对冲） |

预估匹配键：`BILL_NO + COST_NO + CURRENCY_NO + SERVICE_NO`（必要时再加 `BUSINESS_NODE`）；修正现网列表 JOIN 缺服务商导致串数。

### 五.7 接口草案

挂现网 `/balancePayDetail`（扩展，不新建模块名）：

| 接口 | 用途 |
|------|------|
| `POST /getPickPayList` | 出参增加 `unconfirmedCostAmount`、`modifiedCostAmount`（=costAmount）、最近修改原因等 |
| `POST /modifyActualAmount`（新） | 单行/批量改费：入参金额/币别/汇率/原因/备注；内部分流未分摊直接改 / 已分摊对冲 |
| `POST /alignEstimateAmount`（新） | 一键改为预估（仅未分摊） |
| `POST /updateBatch` | **收窄或废弃旁支场景**：勿再给已确认行开「仅草稿」后门与新接口双轨；前端改走 `modifyActualAmount` |
| `POST /shareByPayDetailList` | 沿用；文档约束只摊勾选行 |

抽屉只读区：主单号、柜号、环节、费用名、服务商、未确认金额、当前修改后、预估、原折合、预估 RMB、新折合、金额变更（新−当前修改后）。
