1. 原型 vs PRD · 谁说了算

东西管什么不管什么
原型
*-MVP.html		 长什么样、点哪里、弹什么窗、演示数据 长业务说明、接口细节、完整验收条文
PRD
*-MVP-PRD.html		 规则、字段口径、读写联动、怎么测 用演示假数据当接口真值

冲突时：以 PRD 为准。原型只服务评审与演示。

类型格式例子

  • 一页能力 = 一个原型 + 一个同名 PRD（可薄，但不能没有）。
  • 跨多页的规则放组总 PRD；页面 PRD 写「见总 PRD §x」即可。
  • 产品部评审用「产品部全文」：内嵌本期分册细则，每条功能点带原型跳转。开发/测试仍用组总 PRD 索引，不把细则复述回总 PRD。
  • 同目录放在一起，路径尽量相对、可点开。

3. 变更标记

标记含义用在哪
NEW / 新 本次全新能力、新页、新列 导航入口、页面内新控件、PRD 字段表
改 现网已有，本期改交互/字段/规则 菜单增量、表单改动、工具栏调整
  • 菜单入口与页内功能点标记可分开：入口标「改」，页里新增点仍可标「新」。
  • 去掉的能力在 PRD 写「去掉」，原型直接不展示，不必留灰按钮。
  • 待定不写进验收；写了也必须标清「不得开发」。

4. 页面 PRD · 固定三段

一页能力 = 一个原型 + 一个同名 PRD。PRD 一律按下面三节写，筛选项再多、列再多也不另开别的骨架。每一条说明必须带原型链接（能锚到按钮/弹窗更好）。

节写什么列
一、筛选条件只写本期新增或改了口径的筛（含页签、预警胶囊）。其余线上已有项归一行「现网条件」列出名称即可。没有列表筛选就写「本页无列表筛选」。条件 / 位置 / 说明 / 原型
二、列表字段只写本期新增或改了口径的列/表单格。其余线上已有项归一行「现网字段」列出名称即可，不必逐条写。没有列表则写表单项，标题仍用「列表字段」，第一行注明「本页为表单」。字段 / 说明 / 原型
三、功能逻辑说明按功能点：工具栏、弹窗、校验、回写、拦不拦。说明用 1. 2. 3. 分点，不要揉成一段。测法单独成条，写成「测：…」。功能点 / 说明 / 原型

写法

  • 大白话：能写「空着也能存」就不要写「允许为空字符串」。
  • 说明超过一句就拆成 <ol class="steps">：一条规则一个点，人能扫着读。不要把入口、必填、回写、拦不拦糊在同一段。
  • 测单独成条（可多条）。一条测点只验一件事。
  • 「写到哪」落到具体页面/字段/日志，不写「系统同步」。
  • 硬约束加粗：拦提交、超限能否强制等。
  • 顶栏：日期、本页原型、组导航。可嵌 iframe（见下节挂接）。

5. 原型约定

  • 对齐现网骨架：顶栏 Tab + 左侧菜单 + 白底列表/表单。
  • 页顶少放长说明；规则去 PRD。
  • 弹窗：点遮罩不关，必须点关闭/取消/确定。
  • 结果用 toast；危险操作用确认框。
  • 演示数据要能看出差异（有值 / 空 / 告警各至少一条）。
  • 新/改控件打标，与 PRD 同义。

6. 原型挂 PRD（推荐）

原型页底部放隐藏源，自动出右侧「PRD」芯片（共用 二期/ess-prototype-prd.js）：

<div class="ess-prd-source" hidden aria-hidden="true"
     data-prd-href="本页同名-MVP-PRD.html">
  <span class="ess-prd-chip">PRD · 一句话标题</span>
</div>
<script src="../二期/ess-prototype-prd.js"></script>
  • 同目录相对路径；总 PRD 可用 data-prd-anchor="章节id" 锚到某一节。
  • 组导航同时挂上原型与 PRD 两条链接。

7. 交付前清单

  • 同名原型 + PRD 都在，路径可点
  • PRD 三段：筛选条件 / 列表字段 / 功能逻辑；每条说明都能点开原型
  • 说明用 1. 2. 3. 分点，测单独成条，不把大段规则糊在一格
  • 新·改标记与导航一致
  • 必填、空存、拦截说清楚
  • 硬约束写在规则列，测列能对着原型做出来
  • 原型挂了 PRD 芯片（或页顶明确链到 PRD）
  • 组导航 / 总导航已加入口
