③ 详解 · 运价 + 九项 · 流程 / 注意 / 系统落点

工作〇 运价维护 / 核对 · 船务 / 陈秋玉（价目）

流程：对照船司官网运价与航线 → 更新或核对我司价目表（不定期）→ 订舱/舱位播报/回复客服业务时可引用。

注意：我司运价一般不定期更新；船司价与我司成交价可能不一致，需明确以谁为基准（待确认：是否先维护船司价）。
系统：船司价 / 我司价分列维护；航线×船司×柜型维度；过期未更新提醒；播报与客服回复可一键带出运价。 交互原型：运价管理 · 我司订舱 / 代理订舱 / 价差对比（含合约导入、同步报价组、代理 Local）。

工作一 仓位播报 · 张亚晨 / 黄少飞

流程：根据船司官网制作每日舱位情况 → 关注截单时间及航线 →（可选）带出对应运价摘要 → 发集团营销中心群（0730）。黄少飞侧另有渠道早报，盯签入时间+截单时间。

注意：截单时间 · 航线；签入时间与截单联动；区域分工（青岛/厦门/潍坊；义乌宁波北苑→黄少飞）。
系统：舱位播报卡片（待配仓货量 + 航线截单 + 运价摘要）→ 一键发群；挤满柜子再安排提示；一水绑柜数标记（散货 ≤5）。

工作二 厦门泉州青岛仓库配舱 · 张亚晨

流程：看仓库现有货 → 分渠道安排 → 车辆与柜子到仓装柜。SOP：注意货量与到仓签入时间，及时装柜；托盘货、合并报关货重点看。

注意：不同渠道分开安排；货量 + 到仓签入时间；合并报关尽量同柜（衔接收关 0729）。
系统：待配仓批量勾选（对标制单）；配仓优先合并报关；装柜计划系统内分配（告别先安排后录）。自动配舱规则已写入 需求 PRD 4.7（同渠道：合并报关 → 服装货 → 托盘货 → 报关件 → 不够补买单；反倾销装同一柜）。作业台可视化仍二期。

工作三 发舱单 · 黄选富 / 张亚晨

流程：资料员将舱单信息发舱单群 → 船务在海管家平台完成发送。

注意：仔细核对信息，及时发送。0730：现状舱单发送偏晚，约轮流一周。
系统：同船舱单可批量推海管家；发送节点 SLA 提醒；与提单收发通/单号校验联动（一周约 3～4 票错单治理）。

工作四 舱位登记 · 黄选富 / 张亚晨

流程：代理将舱位信息发群或邮箱 → 登记到舱位表。SOP 订舱侧：提前一周订舱、截单前补料、船开前改单；美森 SW 保函船开前送达代理。

注意：仔细核对，及时登记；舱位表 / 装柜表 / 系统 / 拖车群信息一致（郭森豪核对职责）。
系统：舱位表线上化；代理邮件/群信息结构化入库；登记超时提醒；开船时间与预计出发统一字段。

工作五 分配提单 · 做分票提单 · 张亚晨 / 郭森豪

流程：配舱后先分配提单（票怎么拆、挂哪票）→ 再按客服资料做分票提单填写。郭森豪：腾飞系统制单（义乌总部↔宁波）、填装柜表（拖车群箱封）、P 提单按模版改收发通/品名/件毛体。

注意：0730：分配提单依赖个人经验较重。另：仔细核对；中转港；勿选 EPS 拖车代理；上海新洋核还箱点；去掉他司 logo/电话；装柜时间写入提单。
系统：分配规则可配置/可推荐（降低对人经验依赖）+ 提单 AI 识别；列表按周·同船聚合；装完/美装完色标；终配性能优化（卡 10～20s）；优先合并报关同票同柜。

工作六 删除舱单 · 张亚晨

流程：报关行提供删除截图 + 报关单 → 海管家删除舱单。

注意：核对提单与报关单；报关单号与提单号一一对应。
系统：删单作业台：上传材料 → 自动校验单号对应 → 通过后才允许海管家删；留痕可追溯。

工作七 回复客服及业务员 · 张亚晨

流程：按问题回复船期、舱位、运价等信息；及时、积极响应。

注意：及时回复；运价以价目表/约定基准为准。衔接甩柜通知（客服+业务员必须同步）。
系统：船期/舱位/运价/放行状态一键引用回复；甩柜/晚开自动推送客服业务员。

工作八 柜子放行信息查询 · 张亚晨 / 黄少飞

流程：在对应出口码头查询放行信息；异常及时反馈。黄少飞：进港放行异常、甩柜重装、查验放行后通知关务转船。

注意：及时查看；一天盯海放签入约 3～4 次（0730）；义乌整柜多为产品签入，放行沟通费时。
系统：按开船时间+轨迹拉数；临近开船未放行标记；提单管理列表直接显示放行状态/放行标记；已开船未报完→智能甩柜；码头抓取+手动补轨迹。

工作九 整柜签入 · 整柜客服（现状）

流程：客户单号 + 资料在系统签入。SOP 另有签出/成本表链路（郭森豪等）。

注意：0730 定稿：签入目前在整柜客服解决，船务本迭代不排签入改造（#9 范围外）。
系统：船务侧仅需状态可见/衔接即可；单号校验若整柜客服侧已有则复用，不单独立项。

⑤ 0730 增强与缺口（0～9 定稿口径）

以下为调研收口后的增强清单：左侧 As-Is 缺口，右侧系统 To-Be。对应日常工作 〇～九。

As-Is 共性： 船司运价未进系统 · 播报靠手动拼 · 提单/待配仓交互弱 · 舱单资料与发送脱节 · 分配提单靠个人经验 · AI/排序不足 · 舱单调整无系统留痕 · 异常通知不到位 · 放行人肉刷码头 · 签入在整柜客服侧完成（非船务主责系统）。
#增强项As-Is 缺口系统 To-Be优先级
0 船司运价上系统 运价不在系统或难引用；播报/回复靠口头或线下表 船司运价维护进系统；航线×船司×柜型可查可引用； 运价管理原型 P0
1 仓位播报 播报数据目前手动处理 系统数据正确后支持直接复制出播报文案/表格（少拼少改） P0
2 提单管理 ↔ 待配仓 两边割裂，跳转/勾选/回写不顺 交互优化：待配仓批量、与提单列表联动、状态互见 P0
3 舱单资料与发送 资料不全/晚发；群→海管家手工断点多 资料完善校验 + 发送流程线上化（同船可批、节点提醒） P0
