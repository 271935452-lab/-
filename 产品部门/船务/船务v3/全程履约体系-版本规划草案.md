# 全程履约体系版本规划（草案）

> 文档状态：可评审草案，暂不可直接进入完整开发
> 主要读者：产品、运营负责人、船务/关务/海外对接负责人、研发
> 依据：当前全程履约原型、履约台账与看板讨论
> 当前范围：中美海运全程履约；后续可扩展至其他运输方式

## 一、方向结论

全程履约不应只做“轨迹展示”或“事后统计”。推荐按四层建设：

1. **描述**：现在履约到了哪里、达标多少、哪些票即将超时。
2. **诊断**：哪个节点、渠道、责任部门、服务商或目的地区域造成了问题。
3. **预测**：哪些主单/柜/运单有可能超时，预计何时超时。
4. **决策与闭环**：系统把风险推给正确责任人，记录处置，沉淀后续 SLA、供应商和产品优化依据。

这是对 MSBA（商业分析硕士）公开课程中常见的“数据管理—描述与可视化—预测建模—优化决策—商业沟通”链路的产品化借鉴。海外项目中，MIT Sloan MBAn、Carnegie Mellon Tepper MSBA、UCLA Anderson MSBA 都将数据管理、机器学习/预测、优化与商业决策作为组合能力；国内头部商学院的商业分析、管理科学与供应链分析方向同样强调业务问题、数据建模和管理决策的闭环。

## 二、一级菜单与权限边界

| 一级菜单 | 二级功能 | 核心使用人 | 权限原则 |
| --- | --- | --- | --- |
| 履约配置中心 | 产品履约模板、节点时效与责任、数据来源与采集 | 产品、履约管理员 | 配置菜单权限 + 编辑权限；规则发布需要独立权限 |
| 履约分析中心 | 全程履约运营中心、节点达标率、履约绩效分析 | 管理者、运营负责人、责任部门 | 菜单查看权限 + 数据范围权限；异常处置另设操作权限 |

**数据范围**建议按公司、站队/部门、渠道、产品、起运港/目的港、责任部门划分。配置权限与分析查看权限不能互相默认继承。

## 三、看板应该怎样呈现

### 1. 管理层：履约健康总览

- 公司履约率、当日/当周/当月/累计履约率。
- 在途量、即将超时量、已超时未关闭量、异常关闭及时率。
- 按阶段的在途分布：国内操作、海运、清关、海外仓、尾程。
- 高风险路线、渠道、服务商和责任部门 TOP3。

用途：判断整体是否偏离承诺，不进入单票处理。

### 2. 运营负责人：风险处置台

- 主单/柜/运单当前节点、应操作时间、预计超时、责任人、待办状态。
- 缺失轨迹、时间冲突、未匹配服务商/渠道/责任部门的数据待核对。
- 超时原因、处置动作、升级层级、关闭时长。

用途：今天要处理什么、谁处理、是否真的关闭。

### 3. 诊断分析：问题在哪里

优先支持以下维度交叉分析：

| 维度组 | 首期维度 | 后续深化 |
| --- | --- | --- |
| 业务 | 渠道、销售产品、尾程方式、客户类型 | 货物属性、服务等级、贸易条款 |
| 网络 | 起运港、目的港、州、邮编范围 | 仓库、码头、航段、配送区域 |
| 履约 | 标准节点、当前阶段、是否准点、异常原因 | 节点等待时长、节点回退、轨迹完整度 |
| 责任 | 责任部门、责任人、处置动作 | 升级次数、关闭及时率、重复异常率 |
| 供应 | 服务商、船司、海外仓、尾程承运商 | 合同/SLA 版本、容量、报价与成本 |
| 时间 | 当日、当周、当月、累计、累计周、累计月 | 同比/环比、节假日、工作日/自然日 |

用途：解释“为什么低”，而不是只给一张排名表。

### 4. 预测与决策：后续版本

- 超时风险分级：低/中/高，并给出触发因子。
- ETA（预计到达时间）偏差趋势和预计违约量。
- 服务商/渠道在相同路线与区域下的时效、稳定性、成本综合评分。
- 建议动作：提前催办、切换责任人、升级、换服务商/渠道的人工决策建议。

**[本期不做]** 自动改船、自动换供应商、自动向客户承诺新的 ETA。必须先完成数据稳定性与人工审批闭环。

## 四、版本规划

| 版本 | 目标 | 核心能力 | 可衡量产出 | 前置依赖 |
| --- | --- | --- | --- | --- |
| 一期：V1 + V1.5 合并上线 | 同时做到履约可见与数据可信 | 产品 SLA 模板、节点字典、规则版本快照、轨迹/人工实际时间、履约运营中心、基础超时待办；来源优先级、数据待核对、缺失/冲突处理、州/邮编适用规则、统计口径版本 | 每票可定位节点、责任部门和超时票；看板可说明分子/分母和排除数据 | 标准节点、主单/柜/运单关系、基础轨迹来源；时间来源、责任部门、渠道、服务商主数据完整 |
| V2：运营闭环 | 让风险有人处理并可复盘 | 预警分级、统一异常工单、催办/升级、关闭时限、异常原因库、部门/服务商/渠道绩效分析 | 超时关闭及时率、重复异常率、责任闭环率 | 待办中心、消息能力、组织与角色权限 |
| V3：预测预警 | 从事后统计转为提前处置 | 风险评分、预计超时、ETA 偏差、趋势与根因分析 | 高风险票提前识别率、预警有效率 | 至少多个稳定统计周期、完整异常关闭结果 |
| V4：履约优化 | 支持经营决策与网络优化 | SLA/成本/稳定性综合评价、渠道与服务商推荐、场景模拟、目标分解 | 渠道/服务商优化收益、承诺达成率提升 | 成本、报价、容量、客户承诺和履约数据联通 |

## 五、一期当前应锁定的业务对象

`产品履约模板 → 规则版本 → 履约任务 → 标准节点 → 实际事件 → 异常/待办 → 统计指标`

其中，履约任务必须明确关联到主单、柜、运单/子单中的哪一个对象；一个任务保存创建当时的 SLA 规则快照，后续改配置不能静默影响历史统计。

## 六、MSBA 框架下对当前一期的优化建议

当前版本最应优先补的是“可信、可比较、可行动”，不建议现在就上复杂预测模型。

| 优先级 | 当前优化项 | 看板呈现 | 解决的问题 |
| --- | --- | --- | --- |
| P0 | 统一指标语义层 | 每个履约率可查看统计对象、分子、分母、排除数据和规则版本 | 同一指标在部门、渠道、供应商间算出不同结果 |
| P0 | 数据完整度与样本量 | 每个排名同时展示已统计票数、缺失比例、人工补录比例 | 小样本高分或数据缺失被误判为优秀/差 |
| P1 | 目标与趋势对比 | 当日/当周/当月/累计旁增加目标值、较上周/上月变化 | 只能看到当前数值，无法判断是否在改善 |
| P1 | 从结果下钻到行动 | 公司 → 渠道/部门/供应商 → 节点 → 主单/柜/运单 → 异常待办 | 排名发现问题后仍要跨页面人工找票 |
| P1 | 领先指标与结果指标分开 | 领先：即将超时量、剩余缓冲时间、轨迹缺失；结果：履约率、超时率、关闭及时率 | 只做事后复盘，无法提前干预 |
| P2 | 统一比较基准 | 同一路线、产品、州/邮编范围、服务等级下比较供应商/渠道 | 不同难度业务直接比排名，结论失真 |
| P2 | 成本与客户承诺联动 | 滞箱滞港/补收风险、客户承诺 ETA 偏差、异常恢复成本 | 时效优化与成本、客户体验脱节 |

**建议本期先落地的三个增强：**

1. 在每个履约率、排名和明细旁展示“已统计票数 / 缺失票数”，并固定口径版本。
2. 在绩效看板增加目标线与环比，只做当前、目标、变化三项，避免信息过载。
3. 所有红黄指标必须能一键下钻到具体异常票，并能回到责任部门待办。

## 七、进入一期开发前需确认的 P0

| 编号 | 待确认事项 | 不确认的影响 |
| --- | --- | --- |
| P0-01 | 履约率的分子、分母及统计对象：主单、柜、运单还是节点任务 | 看板、部门排名、服务商排名可能不一致 |
| P0-02 | 当日/当周/当月/累计/累计周/累计月的起止时间、时区和是否按自然周/月 | 当前新增的七类履约率无法统一取数 |
| P0-03 | 实际时间的来源优先级，以及人工覆盖后的审计规则 | 超时判定与责任归属可能错误 |
| P0-04 | 州、邮编范围的匹配优先级：精确邮编、区间、州、全国规则如何覆盖 | 同一产品可能套用错 SLA |
| P0-05 | 配置中心、分析中心、异常处置的菜单/数据/操作权限矩阵 | 无法安全上线分权使用 |

## 八、建议下一步

1. 先确认上述 5 项 P0，形成统一计算口径。
2. 以“一期：V1 + V1.5 合并上线”为一个可上线切片：先覆盖一条中美海运主路径和 8～10 个关键节点。
3. 一期内同时交付数据待核对、统计口径和基础绩效分析；不把“看得见”和“算得准”拆成两次上线。
4. V2 再把预警、工单、升级、关闭纳入闭环；数据稳定后才进入预测与优化。
