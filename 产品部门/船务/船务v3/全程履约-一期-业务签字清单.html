A. 本期做什么（总口径）

一句话：在现有作业页上补齐履约要用的时间字段；用一套规则版本推算应操作时间；运营台按「当前节点」盯超时；达标率 / 绩效只看结果。

确认编号说明
FF-01 本期在现有页面加字段和规则，不另开一套手录节点台。实际时间优先：订单已有 / 扫描 / 轨迹；人只补没有可信来源的。
FF-02 主数据：柜级节点以柜/提单为准；票级尾程在卡派。柜发生一次的时间抄到该柜下每条运单再比。卡派不重复维护柜级主数据。
FF-03 标准节点本期全部挂运单核算。整体时效：POD 回传 − ATD（实际开船） 折合天数 ≤ 承诺时效(柜)。
FF-04 ③等装与④装柜时长是两套考核，不合并。离场时间保留，但不参与④判定。

B. 船务 / 仓库要录或只读看的字段

确认编号说明
海派仓位表 · 提单管理
FF-05 F1要求到柜 / 柜子应到仓：装柜日前必填，且须早于装柜日。仓库只读带出。提单可用「维护履约字段」批量写。
FF-06 F2最迟还重柜：放舱后～开装前必填。本页只录「应」；实际还重走飞驼，不在本页手录实。
FF-07 F3报关最迟放行：绑提单后必填。关务只读。实 = 海放 / 飞驼，不等于实际截单(F8)。
FF-08 F16承诺时效(天)：只读。取当前柜子下所挂销售产品承诺时效的最大值。公式：MAX(该柜各产品.承诺时效天)。履约页 / 维护履约字段不改。
FF-09 提单工具栏「维护履约字段」：勾 ≥1 条可批量写应截单、F1、F2、F3、ETD、ETA；左侧勾「写入」的字段才更新；F16 不在此改。
装柜计划 · 仓库视图
FF-10 具体到柜时间：仓库到场填写，回写提单侧实际到柜，与 F1 比对。
FF-11 F4开始装柜：取装柜扫描第一次扫描时间，本页不手填（未扫描显示「未扫描」）。同时作③等装终点和④装柜时长起点。
FF-12 F6装柜完成：取扫描点「装柜完成」时间，本页不手填。
FF-13 F7实际离场：可填车/柜离仓；不参与④装柜时长判定。
FF-14 判定：③等装 = 开始装柜 ≤ 具体到柜 + 1 小时；④装柜时长 = 装柜完成 ≤ 开始装柜 + 3 小时。

FF-19 F14最迟出库：按渠道规则自动；覆盖选填且要原因。

FF-21 F15外港人工时刻：无美库时补本票实际；票写票，不回写柜级主数据。签收 / POD 仍用现网字段。

D. 规则怎么配（配置中心）

确认编号说明
FF-22 履约规则版本：全部销售产品共用一套版本；同一时间只有一个启用。版本只定：启用哪些节点、提前几小时、推送到谁。不在版本上再配承诺天数。
FF-23 节点时效与责任：节点编码系统自增；核算对象本期仅运单；责任部门 = 海派小组或运单所在仓；供应商取服务商类型。应操作 = 起算字段 + 时长；要拆分时在拆分行各自写起算和时长。
FF-24 多维时效：热门仓可直接填；字段因子一行绑「库字段」或「轨迹编码」（二选一）。选字段时直接填数据库字段名，不再弹选字段窗。时长写在节点页，不在本页另开推算公式表。
FF-25 轨迹命中映射编码后，把时间写入所选履约字段，再按规则重算。飞驼 / 美库覆盖以联调确认为准；确认前按「建议」。

E. 运营台怎么盯（全程履约运营中心）

确认编号说明
FF-26 列表默认看未完成 = 即将超时 + 已超时。不设「待处理」。要看已达标：履约状态选「已完成」或「全部履约数据」。
FF-27 当前节点 = 启用链上第一个尚未达标的节点。列表只铺当前节点一行；点「当前节点」看全票轨迹。时效状态只看当前节点，不是历史上任一节点超过就整票标红。
FF-28 即将超时 = 到了「应操作 − 提前小时」且还没达标实际；已超时 = 已过应操作且无达标实际。待办推给版本里「推送到人」。本期底表不做操作列。
FF-29 「下载底表」导出横向全量宽表（对齐《全程履约节点配置-横向底表》），范围跟当前筛选；列表本身不铺整票 15 列。

F. 看板与绩效（只看结果）

确认编号说明
FF-30 节点达标率看板：按周期 / 销售产品 / 起运港看各节点达标率与超期次数。标准以节点上配的时长为准，本页不改时长。
FF-31 履约绩效：缺责任部门 / 供应商 / 渠道，或供应商重复匹配 → 进「数据待处理」，不进对应排名。

本期不做（知悉即可）

知悉编号说明
OUT-01 不在运营中心底表做「操作 / 处置」入口；轨迹查看走点「当前节点」。
OUT-02 不在履约规则版本上再配一套承诺天数或按销售产品拆多套版本。
OUT-03 飞驼 / 美库事件覆盖以接口联调最终确认为准；未确认前按「建议」映射，不强制验收全自动。
OUT-04 不把仓库「实际离场」当作④装柜完成；不在卡派票上再维护柜级提柜/拆柜主数据。
