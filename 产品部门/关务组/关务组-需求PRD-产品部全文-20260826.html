背景与痛点 · 我们解决什么问题

业务背景

关务在运单签入后立刻做资料（推送报关行、跟预录、确认、改单撤销重发）。这是运单维作业，不并进报关执行列表先做三套功能；先把资料发出去，预录进度在本页跟。本页报关状态页签/列名与报关执行一致。

核心痛点

  • 报关件混进买单：专门的预录页必须只看报关件，非报关件不应出现、也不该生成催促代办。
  • 着急看的三件事散落：是否已出预录、哪家报关行、预录是否已确认，必须在列表上一眼看到。
  • 确认口径不清：确认是关务手动勾选，允许改回；上传放行单后必须锁定。
  • 改单路径断：件毛体/品名变更后要先撤当前预录，再重发，新预录回来再确认。
  • 合并报关漏改：多运单共用一份报关时，推送/确认/改单/放行必须同组一起改。

本期要解决什么

  • 独立作业台：签入成功 → 仅报关件进本页。
  • 列表三件套 + 报关标记（报关 / 合并报关 / 拆分报关）+ 客户委托标记 + 报关编号 运单号-序号(件数)。
  • 合并组同改状态；拆分一票多编号。
  • 与运单管理（待配舱/终配舱）、报关执行列表同源展示报关行、预录确认、已放行；状态名与报关执行对齐。

一、规则口径（8/15–8/20 沟通）

1. 只看报关件 张珊珊 8/15

专门的预录单页面不进买单/非报关件。签入后若非报关件，跳过本页，不生成预报/预录待办。后续改成报关件再重新判定。

是否报关件报关资料系统动作本页
是已上传进入「待推送」；推送后跟预录/确认显示
是未上传拦截推送；催促代办显示（待上传资料）
否—跳过预报/预录路径不进本页

2. 列表三件套

每票必须能直接看到：是否已出预录单、哪家报关行、预录是否已确认。运单管理同步展示标识。

3. 确认 = 手动勾选

关务核对后勾选「预录已确认」；允许取消/改回。客户改口或核对有误时可反复改，直到放行单上传。留操作人、时间。

4. 放行后锁定

上传放行单后不可再取消/修改确认。改单撤销、重发同样不可用，走线下异常单。

5. 改单 → 撤销 → 重发 卢慧恒 8/20

  1. 改单：件毛体、品名/HS、收发通、抬头等变更（含退税改买单）。
  2. 撤销单：撤销当前有效预录；同时取消「预录已确认」；记原因。
  3. 重发：按最新资料再推报关行，状态回到「报关行处理中」。
  4. 新预录回传后，关务重新核对并勾选确认。
  5. 已上传放行单：本路径关闭，走线下异常 / 改配，不在本页硬撤。

6. 待配舱 ≠ 终配舱

运单管理原「待终配舱」拆成两个状态。本页同步展示配舱阶段：待配舱也可提前推送；终配舱后继续跟预录/放行。本页配舱阶段只读，主数据在运单管理。

7. 签入后推送

报关件 + 资料已上传 → 待推送；报关件缺资料 → 拦截并催促（业务/客服代办）。资料齐后自动转待推送。推送与放行后抓取主键为报关编号（合并报关多运单共用一个编号，工作可在分单号未出前置）。客户单号可随附件带出作辅键。分单号在绑定提单之后按规则生成，只给舱单；调整后重算，不因此重推报关行。无客户委托不可推送报关行（须委托标记=已委托）。

8. 与报关执行列表

本页是关务「做资料/预录」作业台（运单维、只报关件，未排柜可用）。报关执行列表不再展示预录阶段页签，也不再挂本页入口。排柜后正式件/放行在报关管理列表，预录单状态与预录已确认打在运单明细。两边报关状态说法一致：待推送 / 报关行处理中 / 预录待复审 / 待放行 / 已放行。

9. 报关标记 NEW

三档：报关（单票）· 合并报关（多运单一组、同一报关编号）· 拆分报关（一票拆成多份报关编号）。勾选后可改标记。已放行的运单不可改标记。

10. 合并报关 · 同改状态 NEW

同组合并报关的运单，推送 / 出预录 / 确认 / 改单撤销 / 重发 / 放行一起改，避免漏改导致漏报、重复报。

11. 报关编号 NEW

格式 运单号-序号(件数)，例 WY260820001-1(8)。合并组用主运单号 + 组内件数合计；拆分同一运单出 -1(3) -2(2)。

12. 客户委托标记 NEW

对接报关行：不按分票号查询委托。报关行自行匹配电子委托书，与报关单、放行单打包回传。未对接报关行时本页人工「委托标记」：无标记 / 未委托 / 已委托（无「催办」「已标记·催客户」）。列表「委托标记」列始终展示状态标。合并组同步。仅已委托可推送/重发报关行。

13. 报关行默认分配 NEW

报关件签入进入本页时，按《报关件预录单-销售产品与报关行规则》的收货仓 → 报关行自动指定报关行。规则表「整柜」组已填写映射；散货各组单元格为空，本期凡进本页的报关件一律按收货仓套用同一映射（产品组差异待业务补全后再覆盖）。收货仓无法匹配时报关行为空，须「修改报关行」手工指定后才能推送。可手工改；已推送后改行则退回待推送再推。合并组同步。待放行及之后不可改（含已放行）。改单已撤销仍可改，再重发。

Webhook 回调

  • 系统生成每报关行唯一回调 URL，供报关行配置出站推送。
  • 可订阅：预录单附件回传（#04）、正式件收取（#08）、报关单号（#09）、放行资料就绪（#10）、电子委托（#12）。
  • 正式件收取（#08）→ 抓取最新预录单信息、保存报关正式件 → 待放行；放行资料齐全 → 自动 报关放行。

与业务联动

  • 列表「报关供应商」命中本配置后，按启用能力调用对应接口。
  • 未配置或停用的报关行由头程发放协作链接上传资料，头程在供应商上传审核确认（等同 #04/#08 线下通道）。

第 8 章 · 供应商上传审核

未对接 API 的线下通道。确认后等同 #04 / #08。

打开原型 · 上传审核 → 分册 PRD

头程侧 · 供应商上传审核

报关客服处理未对接 API报关行通过链接协作提交的资料，确认后进入与 API 相同的状态与附件归档。

协作链接发放

  • 指派报关行且 API 停用时，在报关列表或本页生成工作台链接（7 天）或任务链接（72h，单票）。
  • Token 字段示意：brokerId、taskId、scope、exp；HMAC/JWT 签名，服务端校验。
  • 退回须生成新 token，旧链失效；报关行 API 启用后停止发链并跳转失效页。

确认规则

  • 报关资料 确认 → 资料齐套，可继续指派供应商「回传预录单」或内部推送（线下无 #01 自动推送时由客服手动推进）。
  • 预录单 确认 → 附件写入提单「报关预录件」，状态 预录待复审（等同 #04）。
  • 正式件 确认 → 附件写入「报关正式件」，状态 待放行（等同 #08）。

退回

  • 须填写退回原因；系统生成新任务链接，协作任务变为「已退回」，可重新上传。

与 API 配置关系

  • 报关行 API 配置 为「停用」的供应商走本模块；启用 API 的供应商不应出现待确认记录（以 API/webhook 为准）。

第 9 章 · 供应商上传任务

协作链接任务列表。API 启用后停发链、旧链失效。

打开原型 · 任务列表 → 分册 PRD

工作台链接 · 待办列表

与头程报关管理、供应商上传审核分域部署；报关行不进入 ERP，仅通过链接访问本协作站。

链接类型

  • 工作台链接（本页）：?token=…&scope=workspace · 有效期建议 7 天 · 可见该报关行全部待办。
  • 任务链接（直达上传页）：?token=…&scope=task&task=material&taskId=… · 有效期建议 72h · 仅单票操作。

鉴权（示意）

  • Token 为签名 JWT 或一次性随机串；服务端校验：未过期、报关行 ID 匹配、任务状态允许、API 未启用。
  • 校验通过后写 HttpOnly Cookie（会话 2h），同浏览器内可跳转任务详情无需重复带 token。
  • 失败跳转链接失效页；已启用 API 的报关行返回 reason=api。

生命周期

  • 过渡方案：未对接 API 报关行使用链接协作。
  • 报关行 API 启用后：停止发链，旧链立即失效，与 #01/#04/#08 全量对接。

第 10 章 · 供应商资料上传

报关行侧上传页。等同 #04 线下通道。

打开原型 · 资料上传 → 分册 PRD

单任务上传页（链接直达）

报关行收到短信/邮件/企微中的任务链接后直接打开本页，无需账号。与 ERP 完全分离。

URL 参数

  • token — 签名令牌，绑定 brokerId + taskId + task 类型 + exp。
  • scope=task — 单任务模式；不展示 ERP 侧链；可选隐藏「返回待办列表」。
  • task=material|preentry|formal — 决定开放的上传区块。
  • readonly=1 — 已提交只读查看。

提交后

  • 写入头程「供应商上传审核」待确认队列；可选将任务链接标记 used 或缩短为只读。
  • 退回时头程生成新 token 再发链接，旧链失效。
