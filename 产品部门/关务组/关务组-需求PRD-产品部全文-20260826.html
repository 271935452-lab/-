背景与痛点 · 我们解决什么问题

业务背景

关务在运单签入后立刻做资料（推送报关行、跟预录、确认、改单撤销重发）。这是运单维作业，不并进报关执行列表先做三套功能；先把资料发出去，预录进度在本页跟。本页报关状态页签/列名与报关执行一致。

核心痛点

  • 报关件混进买单：专门的预录页必须只看报关件，非报关件不应出现、也不该生成催促代办。
  • 着急看的三件事散落：是否已出预录、哪家报关行、预录是否已确认，必须在列表上一眼看到。
  • 确认口径不清：确认是关务手动勾选，允许改回；上传放行单后必须锁定。
  • 改单路径断：件毛体/品名变更后要先撤当前预录，原单回退待推送，再重新推送，新预录回来再确认。
  • 合并报关漏改：多运单共用一份报关时，推送/确认/改单/放行必须同组一起改。

本期要解决什么

  • 独立作业台：签入成功 → 仅报关件进本页。
  • 列表三件套 + 报关标记（报关 / 合并报关 / 拆分报关）+ 客户委托标记 + 运单报关编号（运单侧，客户勾选合并/拆分后保留）+ 报关编号（关务作业号 / 报关单号；默认抄运单报关编号，关务再调整后续编新号）。
  • 合并组同改状态；关务拆分出多份报关编号。客户/业务员原标记（单独报关 / 合并报关 / 拆分报关）保留作原始需求；实际执行和收费以关务为准，逻辑同一套。
  • 与运单管理（待配舱/终配舱）、报关执行列表同源展示报关行、预录确认、已放行；状态名与报关执行对齐。
  • 操作日志（通用组件）：挂报关编号；业务提交成功才写。

2. 列表三件套

每票必须能直接看到：是否已出预录单、哪家报关行、预录是否已确认。运单管理同步展示标识。

3. 确认 = 手动勾选

关务核对后勾选「预录已确认」；允许取消/改回。客户改口或核对有误时可反复改，直到放行单上传。留操作人、时间。

4. 放行后锁定

上传放行单后不可再取消/修改确认。改单撤销、重发同样不可用，走线下异常单。

5. 改单 → 撤销 → 回退待推送 → 再推 卢慧恒 8/20 · 8/27 定稿

  1. 改单：件毛体、品名/HS、收发通、抬头等变更（含退税改买单）。
  2. 改单撤销：撤销当前有效预录；同时取消「预录已确认」；记原因。列表进入改单已撤销页签，原单报关状态回退至待推送（推送状态重置）。
  3. 再推：在待推送页签按最新资料重新推送报关行（自动/手工），进入「报关行处理中」。
  4. 新预录回传后，关务重新核对并勾选确认。
  5. 已上传放行单：本路径关闭，走线下异常 / 改配，不在本页硬撤。

6. 待配舱 ≠ 终配舱 8/27 散货卡控

运单管理原「待终配舱」拆成两个状态。本页同步展示配舱阶段：待配舱也可提前推送；终配舱为散货卡控节点 ①（不重推报关行、件毛体以终配舱为准，仍留本页跟预录）。整柜无此节点。见 §一-15 单号进出原则。

7. 签入后推送

NEW
