背景与痛点 · 我们解决什么问题

业务背景

关务在运单签入后立刻做资料（推送报关行、跟预录、确认、改单撤销重发）。这是运单维作业，不并进报关执行列表先做三套功能；先把资料发出去，预录进度在本页跟。本页报关状态页签/列名与报关执行一致。

核心痛点

  • 报关件混进买单：专门的预录页必须只看报关件，非报关件不应出现、也不该生成催促代办。
  • 着急看的三件事散落：是否已出预录、哪家报关行、预录是否已确认，必须在列表上一眼看到。
  • 确认口径不清：确认是关务手动勾选，允许改回；上传放行单后必须锁定。
  • 改单路径断：件毛体/品名变更后要先撤当前预录，原单回退待推送，再重新推送，新预录回来再确认。
  • 合并报关漏改：多运单共用一份报关时，推送/确认/改单/放行必须同组一起改。

本期要解决什么

  • 独立作业台：签入成功 → 仅报关件进本页。
  • 列表三件套 + 报关标记（报关 / 合并报关 / 拆分报关）+ 客户委托标记 + 运单报关编号（运单侧，客户勾选合并/拆分后保留）+ 报关编号（关务作业号 / 报关单号；默认抄运单报关编号，关务再调整后续编新号）。
  • 合并组同改状态；关务拆分出多份报关编号。客户/业务员原标记（单独报关 / 合并报关 / 拆分报关）保留作原始需求；实际执行和收费以关务为准，逻辑同一套。
  • 与运单管理（待配舱/终配舱）、报关执行列表同源展示报关行、预录确认、已放行；状态名与报关执行对齐。
  • 操作日志（通用组件）：挂报关编号；业务提交成功才写。

一、规则口径（8/15–8/20 沟通）

1. 进本页范围 张珊珊 8/15 · 8/27 整柜

专门的预录单页面不进买单/非报关件。签入后若非报关件且非整柜代理报关，跳过本页，不生成预报/预录待办。后续改成报关件或勾选代理报关再重新判定。

业务类型进入条件运单号报关资料系统动作本页
散货 · 报关件是否报关件=是WY…已上传进入「待推送」；推送后跟预录/确认显示
散货 · 报关件是否报关件=是WY…未上传拦截推送；催促代办显示（待上传资料）
整柜 · 我司代理报关整柜且勾选「我司代理报关」TXZG…已上传 / 未上传同散货报关件：资料齐→待推送，缺资料→待上传资料显示
买单 / 非报关否——跳过预报/预录路径不进本页
整柜 · 非代理报关未勾选代理报关——跳过本页不进本页

2. 列表三件套

每票必须能直接看到：是否已出预录单、哪家报关行、预录是否已确认。运单管理同步展示标识。

3. 确认 = 手动勾选

关务核对后勾选「预录已确认」；允许取消/改回。客户改口或核对有误时可反复改，直到放行单上传。留操作人、时间。

4. 放行后锁定

上传放行单后不可再取消/修改确认。改单撤销、重发同样不可用，走线下异常单。

5. 改单 → 撤销 → 回退待推送 → 再推 卢慧恒 8/20 · 8/27 定稿

  1. 改单：件毛体、品名/HS、收发通、抬头等变更（含退税改买单）。
  2. 改单撤销：撤销当前有效预录；同时取消「预录已确认」；记原因。列表进入改单已撤销页签，原单报关状态回退至待推送（推送状态重置）。
  3. 再推：在待推送页签按最新资料重新推送报关行（自动/手工），进入「报关行处理中」。
  4. 新预录回传后，关务重新核对并勾选确认。
  5. 已上传放行单：本路径关闭，走线下异常 / 改配，不在本页硬撤。

6. 待配舱 ≠ 终配舱 8/27 散货卡控

运单管理原「待终配舱」拆成两个状态。本页同步展示配舱阶段：待配舱也可提前推送；终配舱为散货卡控节点 ①（不重推报关行、件毛体以终配舱为准，仍留本页跟预录）。整柜无此节点。见 §一-15 单号进出原则。

7. 签入后推送

报关件 + 资料已上传 → 待推送；报关件缺资料 → 拦截并催促（业务/客服代办）。资料齐后自动转待推送。推送与放行后抓取主键为报关编号（合并报关多运单共用一个编号，工作可在分单号未出前置）。客户单号可随附件带出作辅键。分单号在绑定提单之后按规则生成，只给舱单；调整后重算，不因此重推报关行。无客户委托不可推送报关行（须委托标记=已委托）。

8. 与报关执行列表

本页是关务「做资料/预录」作业台（运单维）。待放行为散货 / 整柜共同出池卡控：预录确认后移交报关执行列表跟放行。报关执行列表不再展示预录阶段页签。两边报关状态说法一致：待推送 / 报关行处理中 / 预录待复审 / 待放行 / 已放行。

9. 报关标记 NEW

三档口径与运单侧相同：单独报关（本页列名「报关」）· 合并报关 · 拆分报关。本页改的是关务实际执行标记；运单上客户/业务员原标记不改。见 §三 原始需求 / 实际执行。

10. 合并报关 · 同改状态 NEW

关务同组（同一报关编号）的运单，推送 / 出预录 / 确认 / 改单撤销 / 重发 / 放行一起改，避免漏改导致漏报、重复报。

11. 报关编号 / 运单报关编号 卢慧恒 8/27 · 整柜 8/27

散货 · 运单报关编号 = 运单侧写出的号（签入默认 运单号-1(1)，括号=运单数量；客户勾选 n 票合并后为 …-1(n)，例如 10 票合并为 ICBU00001-1(10)）。关务再调整也不改这列。

整柜 · 我司代理报关 · 运单号 TXZG… 开头；运单报关编号 = 运单号-1 或 运单号-2（不带件数）。签入默认报关标记「报关」；关务拆分后改为「拆分报关」，报关编号可为 TXZG…-1 TXZG…-2 并列，运单报关编号仍保留签入原号。

报关编号 = 关务作业号，即报关单号。未调整时默认抄运单报关编号；关务标记合并/拆分后续编新序号，不覆盖运单侧原号。内部作业、推送报关行、放行抓取、预录工作台、母子表全部用报关编号。推送/放行抓取主键仍是报关编号。

12. 客户委托标记 NEW

对接报关行：不按分票号查询委托。报关行自行匹配电子委托书，与报关单、放行单打包回传。未对接报关行时本页人工「委托标记」：无标记 / 未委托 / 已委托（无「催办」「已标记·催客户」）。列表「委托标记」列始终展示状态标。合并组同步。仅已委托可推送/重发报关行。

13. 报关行默认分配 NEW

报关件签入进入本页时，按报关行配置自动指定报关行（散货：销售产品+到货分公司；整柜：配送方式+港口）。可手工改（仅§四前四态）。

14. 报关客服按报关编号随机分配 NEW

本票报关客服（关务侧作业人）按报关编号在客服池中随机均分（同一编号永远分给同一人，刷新不重抽）。合并报关共用一个报关编号 → 组内同一报关客服。拆分报关同一运单多段编号时，按第一段编号分配（一行一个报关客服）。客服列仍是运单客服，不参与本分配。

进页默认查询：报关客服岗进入本页，筛选「报关客服」默认带当前登录人，列表与页签只出本人名下报关编号。可改「全部」看全量；数据重置回到本人。主管等角色进页默认「全部」（以实现权限为准；原型按报关客服登录演示）。

15. 单号进出原则 8/27

本页维护的是预录作业池：签入后的报关件 / 整柜代理报关在此做资料、推送、预录确认；待放行起主战场转至报关执行列表。散货与整柜卡控节点不同。

业务进入本页卡控节点离开本页
散货 · 报关件 签入成功（是否报关件=是） ① 终配舱　② 待放行 待放行起移交报关执行；已放行后本页只读

散货 · 卡控 ① 终配舱

运单管理落位终配舱时（本页配舱阶段只读同步）：

  • 预录侧不重推报关行，沿用已推送 / 预录 / 确认进度。
  • 件毛体以终配舱数据为准；分单号若因配舱调整重算，只写分单号，不重推报关行。
  • 运单仍留在本页，继续跟预录确认，直至待放行卡控。

散货 / 整柜 · 卡控 待放行（整柜唯一卡控节点）

  • 勾选预录已确认或收到报关行确认件 → 报关状态待放行。
  • 本页停止作业（见 §四：待放行无工具栏按钮）；后续放行抓取、发舱单等在报关执行列表。
  • 委托标记、操作日志任意态可查。

整柜无终配舱卡控：整柜不走散货「待配舱 / 终配舱」链路，仅在待放行节点移出预录作业池。

二、列表字段

列表仅两级、默认全部展开：分组头抽报关编号 / 推送状态 / 报关标记 / 状态流转 / 报关行 / 预录确认；下面运单行含运单报关编号（运单侧原号，关务调整不改），勾选做关务侧重新合并、拆分。不按报关行再套第三级，运单下也不再展开报关明细。单元格 white-space: nowrap，补充说明进 title。

列口径
勾选分组头 = 该报关编号下全部运单（推送/改行）。运单行 = 标记合并 / 拆分报关。全选只作用于当前页运单。
报关编号勾选后第一列，抽在分组头。关务作业号 / 报关单号。格式 前缀-序号(运单数量)。未调整时=运单报关编号；关务合并/拆分后为续编的新号。合并：一个编号下一组运单，括号=组内运单数。拆分：可多份报关编号（一票多段并列，每段括号=1）。运单行本列为空。点击报关编号进入预录审核详情（与操作列「预录审核」同一页：报关管理-预录单审核详情-MVP.html）。多段编号各自可点，带入对应报关编号。
推送状态抽在分组头（报关编号维）。三档：未推送 / 推送成功 / 推送失败。未推送=尚未推送报关行；推送成功=该编号已推到报关行（后续预录/确认/放行仍走报关状态）；推送失败=接口失败，作业状态仍为待推送，可重试。改报关行后回到未推送。运单行本列为空。
报关标记 / 委托标记 / 客户报关单层级，只在分组头。委托：无标记 / 未委托 / 已委托，合并组同步。客户：只写一个（合并组必须同一客户，取指定报关票件）。没有多客户并列。运单行这三列为空。
运单号分组头「共 n 票」；运单行是业务主键，默认展开。点击运单号进入运单详情。上线走现网运单详情；原型跳转运单管理并带运单号。操作列「查看」同此入口。
运单报关编号只在运单行。运单侧写出的号（签入默认，或客户勾选合并/拆分后的号）。关务「标记合并/拆分报关」不改写。客户已合并 10 票时，组内各运单行可以是同一个号（例 ICBU00001-1(10)）。分组头本列为空。
客户单号只在运单行。客户侧单号，辅键；可随附件带出。筛选可查。
所属业务员只写一个（销售）。合并组必须同一人，分组头取指定报关票件；运单行同值。列表展示、筛选可查。一键催促通知对象之一。
客服运单客服（运单归属），不是报关客服。列表展示、筛选可查。一键催促通知对象之一。
报关客服抽在分组头。按报关编号均分；合并组同一人。运单行不重复。
签入时间签入成功时间。

三、报关标记 / 编号

原始需求 / 实际执行 杨嘉武 8/27 13:31–13:40 · 卢慧恒

杨嘉武：预录工作台「标记合并报关 / 标记拆分报关」和运单那边的合并报关、拆分报关有什么区别？是同个东西吗？随后：所以和之前的合并报关、拆分报关、单独报关没有关系，是吧？

和运单那边的原记录没关系，和整体逻辑、收费逻辑有关系。一样的逻辑（单独报关 / 合并报关 / 拆分报关，以及按几票收报关费）。只是客户和业务员那边的原标记保留、不改他们的记录。实际执行按照关务这边的来。相当于：客户是原始需求，实际执行以关务为准。

运单侧 · 原始需求关务侧 · 实际执行
是什么客户/业务员勾选的单独报关、合并报关、拆分报关关务做资料时按同一套逻辑再调整
入口运单、下单原页面，保留不改本页工具栏「标记合并报关」「标记拆分报关」
记录原标记、运单报关编号不回写报关标记 + 报关编号（报关单号，可续编新号）
推送 / 放行 / 内部作业不跟这套号作业跟关务这套
报关费客户勾选时的预估（例 10 票合并 → 1×300）按关务实际报几票（例拆成 3 票 → 3×300）

不要理解成「关务另做一套无关功能」。不是两套业务规则；是同一套规则的两层：需求留在运单，执行和收费听关务。

例子（卢慧恒 8/27 13:34–13:37）

  1. 客户勾选 10 票合并报关。运单报关编号 = ICBU00001-1(10)，当时只按 1 票报关费 300。
  2. 关务做资料发现这批货要分成 3 票来报，操作拆成 3 份：ICBU00001-2(3)、ICBU00001-3(3)、ICBU00001-4(4)。收 3 份报关费 300 × 3。
  3. 运单那边的报关编号还是 ICBU00001-1(10)（本页列名「运单报关编号」）。
  4. 内部以及关务这边全部用 ICBU00001-2(3)、ICBU00001-3(3)、ICBU00001-4(4)（本页列名「报关编号」）。

序号规则：运单侧已占用 -1，关务新号从 -2 起续编，不把运单侧的 -1(10) 改掉。括号一律是运单数量：客户原 10 票；关务拆成 3 份，各份运单数 3 / 3 / 4。原型 WY260827101/102/103 各代表一份报关编号。

  • 标记合并报关：勾选运单行 ≥2 票（可跨组，用于重新合并）。必须同一客户、同一所属业务员，否则拦截。弹窗对齐运单管理：展示当前合并报关件数（勾选票数）和总价值；下拉「请选择指定报关票件」，选项为勾选运单的客户单号（同客户单号多票时带运单号区分）。所选票件 = 主运单（报关编号前缀）。组号后台生成。组内共用一个新报关编号（续编），收成一个分组头。分组头客户、所属业务员各只写指定票件的那一个。运单报关编号不变。
  • 标记拆分报关：只勾选一票运单。弹窗对齐运单管理：展示运单号、客户单号；散货填拆分件数（从本票拆出的件数，须小于本票件数，余数成第二段）。续编两份新报关编号，一票多段并列（仍一行运单），每段括号=1（仍是这一票运单）。整柜代理不填件数，按票拆成 运单号-1、-2。运单报关编号仍为运单侧原号。

七、怎么测

  1. 非报关件签入：本页无此票、无催促代办。
  2. 报关件缺资料 → 待上传资料：仅见一键催办、改报关行、合并/拆分/取消/单独报关；不可推送。
  3. 资料齐 → 待推送：配置命中且已委托时自动推送；失败或未委托则留待推送，可手工推送。此态可见推送、改行、合并/拆分/取消/单独。
  4. 推送成功 → 报关行处理中：可见改行、合并/拆分/取消/单独、改单撤销、上传预录单（未对接行）；不可见一键催办、推送。
  5. 预录回传 / 上传预录单 → 预录待复审：可见改行、合并/拆分/取消/单独、改单撤销；不可见上传预录单、推送。
  6. 勾选预录已确认或收到确认件 → 待放行：本页无作业按钮；委托标记、操作日志仍可用。
  7. 预录待复审点改单撤销 → 改单已撤销页签可见、本页无作业按钮；原单回退待推送，在待推送页签重新推送。

九、报关行配置 8/27

独立页：关务组-报关行配置-MVP.html。预录签入 / 待推送自动推送时按本页规则命中默认报关行；与 API 配置 联动展示对接状态。

9.1 散货

  • 销售产品数据源 = 销售产品主表，仅 enabled = 已启用 的产品进入可选列表；已停用产品不可选、不可搜出。
  • 多选 + 搜索：支持按产品编号、名称搜索；多个关键词空格分隔（AND），在搜索结果中勾选多个产品。「全选当前」= 选中当前搜索结果全部已启用产品。
  • 到货分公司：多选分公司，每行指定报关行。
  • 命中：签入时运单销售产品 ∈ 已选列表 且 到货分公司有配置 → 带出报关行；否则留空，预录工作台手工改。

9.2 整柜

  • 每条规则：配送方式（多选） + 港口（多选） + 报关行。
  • 运单命中：运单配送方式 ∈ 规则内已选方式 且 起运港/港口 ∈ 规则内已选港口 → 带出该规则报关行。
  • 同一「配送方式 × 港口」组合全局不可重复（保存时校验）。
  • 列表展示：配送方式、港口列以标签并列展示多选值。

9.3 其它

  • 本页不提供「导出 JSON」类演示按钮；配置落库由后端保存接口承接。
  • 右侧「分配试算」：散货 / 整柜分别试算命中来源与 API 对接状态。
  • 已推送后改报关行 → 预录工作台回待推送再推（见 §四）。

八、按报关单号选运单（母子表） 改

独立页：关务组-预录工作台-报关单号母子表-MVP.html。给业务勾选，不替代关务作业台。预录工作台工具栏不放入口（8/27），不从本页跳进母子表、也不从母子表勾选带回工作台。

层级（仅两级）

  • 只做两级：报关编号 → 运单。禁止第三级（报关行 → 报关号 → 运单，或分组头 → 运单 → 再展开报关明细）。
  • 报关行只作筛选项，不作为表结构。

展示

  • 母行：一个报关编号一行。报关单号即报关编号，只展示这一列，不另出海关回传号 / 「未出报关单」。
  • 合并报关：同一编号一行母行，子表多张运单。
  • 拆分报关：每个编号各一行母行，子表为同一运单（该运单可出现在两个母行下）。工作台运单列表仍单行展示 -1(1) -2(1)，不折成两行。
  • 关务把客户合并票再拆成多份报关编号时：母行按报关编号各一行（例 ICBU00001-2(3) / -3(3) / -4(4)），子表运单报关编号仍是 ICBU00001-1(10)。
  • 子表：该编号下的运单（运单号、运单报关编号、客户单号、客户、业务员、客服、件数、委托、预录）。
  • 勾选母行 = 选中其下全部运单；也可只勾部分运单。

选择与带回

  • 底部「确认选择」把勾选运单带回预录工作台运单列表，自动勾选并高亮。
  • 筛选：报关编号、运单号、客户、所属业务员、报关行。
