1 需求版本没有记录、经常变、经常改 腾讯：封面版本号 + 修订记录；口头改不算数，改完升版再评审 §2 文档状态机、修订表、变更单

3 待确认 / 不确定 / 还在调研的附在 PRD 上难读 字节：Parking Lot / 调研池；腾讯：附录不进本期范围 §5 正文禁混入；调研池另文或附录，默认「不得开发」
4 缺字段来源；开发自己补，逻辑不全 字节：字段中文名、来源系统、主数据、计算口径、空值、精度 §6 字段表必填；§7 禁止「开发自行补充」
5 原型风格跟现网不一致；新增/修改不好认 现网骨架复用 + Diff 色标 NEW / 改 / 删 §8 顶栏菜单白底列表；控件打标与 PRD 同义
6 PRD 和原型不一致，不知道哪边为准 腾讯：规则以 PRD 为准；交互稿冲突先改一边再评审 §3 分层权威；冲突未消不得进开发
7 评审讲不细，PRD 写不完善 字节：过会清单；未勾完不得排期 §9 评审议程；§11 过会勾选

原则一句话：能开发、能测试、能验收的才叫本期 PRD。讲不清的进调研池，不进本期。

1. 文档分层（先分册，再写细）

层级文件读者写什么不写什么
总册 ××组-需求PRD.html 或计划总册 负责人、开发负责人 本期范围、功能清单、优先级、跨页联动、版本 每个弹窗字段
页面 PRD 同名-MVP-PRD.html 开发、测试 筛选 / 字段（含来源）/ 逻辑 / 测点 / 异常 调研猜想、未拍板方案
原型 同名-MVP.html 评审、演示 长什么样、点哪里、新/改标记、演示数据 长规则、接口、完整口径
调研池 ××-待确认.html 或 PRD 附录「不得开发」 产品、业务 未确认、多方案、还在问的问题 验收条目

一页能力 = 一个原型 + 一个同名 PRD，版本号相同。组导航同时挂两条链接。原型必须挂 PRD 芯片（见简易标准 §6）。

2. 版本与变更（对应问题 1）

文档状态（只能处于其中一个）

状态含义可否开发
草稿产品自写，未过业务评审否
评审中已发会，结论未落否
已定稿评审纪要已回写，版本号冻结是（仅本版本范围）
变更中定稿后又改，必须升小/大版本再评未过会的增量否

修订记录（每改必加一行，禁止改 silently）

版本日期作者变更点（写结果，不写过程）原因 / 来源评审结论
v1.02026-10-06张三首版：服务商模版增加「多柜一账摊柜」成本组口头 + 纪要 10/06待评
v1.12026-10-08张三柜数来源改为「数量列优先，柜号个数兜底」评审会：姚总确认已定稿
  • 口头改需求不算。会后 1 个工作日内回写修订表 + 正文，否则开发仍按上一已定稿版本。
  • 改规则 / 改字段口径 / 改范围 = 升版本；只改错别字 = 补丁备注，不升功能版本。
  • 原型文件名或页顶标注同一版本：PRD v1.1 · 原型 v1.1。两边版本不一致视为冲突。
  • 已提测后再改：必须出变更说明（影响范围、是否回测、是否改库）。

禁止用「再改一版原型、PRD 回头补」代替升版。先改权威文档，再改原型，或同一提交里两边一起改。

3. 单一事实源：冲突时谁说了算（对应问题 6）

内容权威另一边只做什么
业务规则、拦截、口径、状态流转、字段来源、验收测点PRD原型用演示数据演一遍，不另写一套规则
页面结构、控件位置、交互路径（在现网骨架上的增量）对齐现网的原型PRD 用「位置」列指向锚点，不写像素
文案（按钮名、列名、提示语）PRD 字段/文案表原型跟 PRD 用同一套词
视觉皮肤（色、字号、间距）现网原型复用现网顶栏/菜单/表格，不为了好看换皮肤

PRD 与原型冲突 = 缺陷，不是「开发自己选一边」。过会前必须消掉；消不掉标在修订表，指定以哪边为准并改另一边。

页面顶栏固定写：「规则与验收以本 PRD vX.Y 为准；布局以同名原型 vX.Y 为准（现网骨架）。」

4. 怎么写才好读（对应问题 2）

页面 PRD 固定目录（不要自创骨架）

  1. 封面（状态、版本、范围一句话）
  2. 修订记录
  3. 本期做 / 明确不做
  4. 角色与权限
  5. 一、筛选条件（只写新增或改口径；现网项一行带过）
  6. 二、列表/表单字段（含来源，见 §6）
  7. 三、功能逻辑（1.2.3. 分点 +「测：」单独成条）
  8. 四、状态机（有流转才写）
  9. 五、异常 / 空态 / 权限不足
  10. 附录 A 调研池（默认不得开发）

阅读约定

  • 每条功能点带可点原型锚点（按钮 id / 弹窗 id）。
  • 超过一句就拆 ol.steps：入口、校验、回写、拦不拦分开。
  • 大白话：「空着也能存」而不是「允许为空字符串」。
  • 总册只做索引；细则只在分册。禁止总册、分册、原型注释写三套不同规则。
  • 一屏能扫完一张功能表。不要把调研纪要原文贴进说明列。

5. 未确认需求隔离（对应问题 3）

正文只出现 已确认 且纳入本期范围的条目。

状态放哪开发
已确认正文对应节做
待确认（缺拍板人/缺公式）附录调研池，一行一个问题 + 选项 + 推荐 + 阻塞谁不得做、不得猜
调研中调研池或独立纪要，链回总册「不进本期」不得做
下期总册「明确不做」不得做

调研池写法：问题一句话、可选方案 ≤3 个、推荐方案、确认人、最晚确认日。确认后迁入正文并升版，从附录删掉或标「已迁 v1.1」。

禁止在功能说明里夹「（待业务确认是否…）」——读者分不清哪句是定论。

6. 字段来源说明（对应问题 4 · 前半）

凡列表列、表单格、导入列、计算结果，必须填下表。缺一行 = 逻辑不全，评审不通过。

字段中文 现网控件/列 标记 来源类型 来源说明（系统 / 表 / 计算） 读写 必填 空值展示 精度 / 枚举 原型
过磅重(KG) 提单列表 · 过磅重 改 回写 装柜过磅完成后回写；同一数提单管理=报关管理 只读 否 — 小数 3 位；单位 KG 锚点
单柜金额 待核对实际费用 · 金额 NEW 计算 账单金额 ÷ 柜数；柜数=数量列，缺则柜号拆分数；尾差挂第一柜 系统写，核对可改（改后留痕） 是 不入库，进人工池 与账单币种一致，2 位 锚点

来源类型枚举（只许用这些词）

  • 用户录入：本页输入、下拉、上传。
  • 主数据：客户 / 服务商 / 费用类型字典等，写清哪张主数据、按什么键匹配。
  • 业务回写：轨迹、过磅、报关状态等，写清触发节点。
  • 计算：公式、取数时点、精度、尾差、0 和空怎么处理。
  • 导入映射：服务商模版字段位置 + 映射后系统字段。
  • 他页只读带出：从哪页哪字段来，本页能不能改。

禁止只写「系统带出」「自动计算」。必须写到人能按公式复算、测试能构造数据。

7. 逻辑写全：禁止开发自己补（对应问题 4 · 后半）

每个功能点至少覆盖下面 8 项，缺项评审打回。写不出就说明还在调研，进附录，不进开发。

#必须写清反例（禁止）正例
1谁、在哪、点什么支持摊柜成本组在模版配置页打开「多柜一账」
2前置条件账单进来就拆模版已发布且摊柜开关=开
3校验与拦截（拦不拦、提示原文）数量不对要处理柜数<1 → 进人工池，文案「柜数无效，未入库」
4成功后写到哪（表/字段/状态）同步到实际费用写入待核对实际费用，一柜一行，状态=待核对
5失败 / 部分成功异常走人工同批次：能匹配的行待核对，不能的进人工池，批次状态=部分成功
6权限财务可以配仅模版管理员可发布；核对员不能改模版开关
7并发 / 重复—同一服务商+账单号重复导入拦截
8测点 Given / When / Then测一下摊柜Given 账单 1280 数量 4 四个柜号；When 导入命中该模版；Then 4 行×320 待核对

开发遇到 PRD 没写的分支：停、提单、不猜。产品补进正文并升版后才能继续。

8. 原型风格与新/改识别（对应问题 5）

必须像现网

  • 顶栏、左侧菜单名、列表密度、筛选排布、弹窗宽、主按钮位置跟现网同一套，不为演示换 Stripe/看板风。
  • 新页若现网无对标：用最近的同类页（列表页用列表，配置页用配置）。
  • 演示数据脱敏，但要有差异：正常 / 空 / 告警各至少一条。

标记（与 PRD 用同一套词）

标记含义原型PRD
NEW全新能力、新页、新列、新按钮控件旁红标字段表「标记」列
改现网已有，改交互/口径/位置橙标，旁注「现网是…本期改成…」说明里写旧→新
删去掉的入口或字段不画灰按钮；PRD 写「去掉」功能逻辑一条「本期删除」
现网未改，仅占位帮助认路可弱化，不假装是需求一行带过，不写细则

菜单入口可以是「改」，页内新控件仍标「NEW」。评审时先扫红/橙标，再开 PRD。

9. 需求评审会怎么讲（对应问题 7）

对齐字节过会：按清单讲，不按灵感讲。建议 45–60 分钟，会前 24h 发出「已定稿候选」链接。

时段讲什么产出
5 min背景、目标、本期做/不做、版本号范围无异议
10 min角色走一条主路径（对着原型点，PRD 打开对应节）主路径可开发
20 min字段来源表 + 计算口径 + 拦截文案开发不补逻辑
10 min异常、权限、重复导入、与邻页联动边界有主
10 min调研池：逐条确认或踢出本期附录清空或标不得开发
5 min验收测点抽查 3 条 Given/When/Then测试可写用例
  • 产品主讲，开发/测试可随时叫停「这一句 PRD 没有」。
  • 会上新结论：会后写入修订记录，升版本，再标已定稿。禁止「会上说了就算、文档不改」。
  • 业务评审与内部评审分场：业务拍规则与范围；内部拍字段、状态、联调与工作量。

11. 过会清单（未勾完 = 未定稿）

  • 封面有版本号、状态、原型路径，两边版本一致
  • 修订记录有本版变更点和来源（纪要/谁确认）
  • 本期做 / 明确不做各至少一条，范围无「顺便做一下」
  • 正文无「待确认」「可能」「看情况」；这些只在调研池
  • 每个新/改字段填了来源类型和来源说明，计算有公式和空值
  • 每个功能点有入口、校验、回写、失败、权限、测点
  • 测点是 Given / When / Then，能在原型上走一遍
  • 原型现网骨架；NEW / 改 / 删 与 PRD 同词同位置
  • PRD 与原型已对过，无未消冲突
  • 调研池每条有确认人或已标下期；无确认人不进开发
  • 组导航同时挂原型和 PRD；原型已挂 PRD 芯片
  • 评审纪要回写完毕，状态改为已定稿

过会口令：这一版能开发、能测试、能验收。做不到就停在评审中，不要用原型顶替 PRD。
