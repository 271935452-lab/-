关键设计：无论报关侧字段来自通道①还是②，都进入同一套比对面板； 基准始终是下单资料。识别失败或结构化缺失时，回退到现有「审预录附件」人工路径。

② 双通道对照

通道① 我方识别附件 通道② 报关行预录结构化
时机 客户上传后即可；可在推报关行前自检 已推报关行、进入预录复审
输入 客户报关资料附件（PDF/图/表） 报关行回传的结构性文档 / API 字段
产出 结构化字段 + 置信度 + 原文定位 结构化字段（与预录单一致）
优势 早发现差异，少推一次错资料 字段质量通常更高，贴近正式申报
风险 版式多、识别不准需人工确认 依赖报关行能力与接口字段完整度
现状 缺失 有附件 #04 无结构化比对

④ 状态与关键动作

状态含义可执行动作
待取数 有下单资料，报关侧尚未有识别结果或预录结构化 触发识别 / 等待预录回传
识别中 / 取数中 通道①任务运行或通道②拉取中 查看进度
待核准 报关侧已有结构化，存在 diff 或待确认项 比对、确认、退回、通过
已退回 差异需客户或报关行修改 跟踪重传；重跑识别/预录
已核准 下单 ↔ 报关侧对齐（或已确认采纳策略） 进入允许报关 / 下游舱单 AMS
已作废 查验改配 / 换提单号后旧结果失效 新旧单关联；新单重核准

⑤ 落地分期与依赖

阶段做什么依赖验收
一期 通道②结构化回传 + 核准工作台 diff（对接下单字段） 报关行可回传字段清单；扩展现有 #04 协议 预录复审不再纯肉眼；差异可一键退回
二期 通道①高频模板识别（草单/装箱单） ≥10 份样例；识别准确率门槛 推送前可自检，减少错推
三期 委托/抬头闸门；改配换绑关联重建核准 装柜表抬头、委托状态数据 无委托不可通过；改配可追溯
与三表关系：装柜表决定报关行与排柜节点，是「何时推送 / 推给谁」的上游； 核准工作台解决「推什么、对不对」。二者衔接：终配/待配可出资料 → 进入核准 → 通过后再发报关行或进入预录复审。
