1. 公共：网关、请求头、签名

项约定

Method / Content-TypePOST · application/json; charset=UTF-8
超时示例 30s
密钥佳成分配 app_key / app_secret，放配置中心。PDF 里 Java 示例密钥仅对照签名，禁止写死进代码。

请求头（PDF 表格缺失，按 Java 示例补齐）

Header示例 / 规则
app_key平台分配
format固定 json
method三个 method 之一
nonce每次请求新 UUID
sign_type固定 md5
timestamp毫秒时间戳字符串
version固定 1.0
sign见下方，小写 32 位 MD5

签名只拼请求头值，不拼 Body。顺序固定，中间无分隔符：

sign = MD5( app_key + format + method + nonce + sign_type + timestamp + version + app_secret ).toLowerCase()
Body 是业务 JSON。改 method 或 nonce/timestamp 必须重算 sign。响应信封：code / msg / data / timestamp。文档只给了 code=200，其它码、空单、权限拒绝待佳成补。

2. 接口 1 · 获取 DW 时段

method trk.fist.dw.query

请求 Body

{
  "fbaShipmentId": "FBA19CXS685Y"
}

响应 data（需落库 / 回写列表）

字段类型含义ESS 建议
fbaShipmentIdstringFBA 单号查询键，对齐 DW 预警「FBA 单号」
waybillNumberstring佳成单号存对照，列表可展示
sellerAllowCarrierUpdateDwbool是否允许物流商改 DW对齐「是否允许卖家/物流商修改」；false 时禁止调 update
estimatedDeliveryDateISO UTC预计送达修正 DW 的输入基准
dwChoiceStartDateISO UTCDW 开始对齐亚马逊窗口起
dwChoiceEndDateISO UTCDW 结束对齐亚马逊窗口止
differenceFlagbool是否有差异预警着色 / 筛「缺失或差异」

时间均为 2026-07-03T00:00:00Z。入库建议转业务时区后展示，回推仍用 UTC。

3. 接口 2 · 修改 DW 时段

method trk.fist.dw.update

请求 Body

字段必填说明
fbaShipmentId是FBA 单号
estimatedDeliveryDate是新的预计送达，UTC
estimatedDeliveryDateSource是产生该时间的业务节点，见枚举

estimatedDeliveryDateSource

代码节点
PC提柜
UC拆柜
IB入库
PO计划
OB出库
AP约仓
CC目的国清关
OTHER其他
待确认文档还写了「干线到达 LA」，未给代码。上线前问佳成（是否 LA 或并入 OTHER）。

返回 data 结构与 query 相同。调用成功后用返回的 start/end 覆盖本地 DW，不要自己算窗口。

调用前先 query：sellerAllowCarrierUpdateDw !== true 则只提示、不调 update。失败重试需记操作日志（DW 预警已有「DW操作日志」入口）。

4. 接口 3 · 修改运输信息

method trk.fist.transportation.update

字段必填说明ESS 建议来源
fbaShipmentId是FBA 单号运单 / FBA
middleLegEstimatedDepartureTime是干线预计出发 UTC船期 ETD
middleLegEstimatedArrivalTime是干线预计到达 UTC船期 ETA
originPort是始发港，如 CNSHA提单起运港 UN/LOCODE
destinationPort是目的港，如 USLGB提单目的港
middleLegServiceLevel是STANDARD / FAST / EXPEDITED产品等级映射，需主数据表
minTransitDays是运输最小天数产品时效下限
maxTransitDays是运输最长天数产品时效上限
transportMode是示例仅 OCEAN空运代码待佳成确认
billOfLading否提单号提单
containerNumber否柜号柜子
masterNumber否主单号主单；示例与提单号相同，以业务为准
distributionType否装箱类型枚举未给
boxType否箱型枚举未给

响应把请求字段原样带回，并多 waybillNumber。PDF 把 minTransitDays 注释写成「运输最新时间」，按请求侧「最小时间」实现。

5. 建议开发任务拆分

序号任务说明
D1 Fist 客户端 统一 POST 网关 + 签名 + 超时 + 把非 200 / 网络失败打成可重试错误。method、nonce、timestamp、sign 每次现算。
D2 配置 gatewayUrl、app_key、app_secret、version。测试/生产隔离。密钥不进仓库。
D3 DW 查询同步 按 FBA 单号调 query，回写 7 个 data 字段；differenceFlag、不允许修改要能筛、能标。
D4 DW 更新 业务改预计送达 → update。source 按当前轨迹节点映射枚举。成功后用返回窗口覆盖本地。
D5 运输信息更新 ETD/ETA/港口/提单/柜号变更触发。服务等级、海空运映射做成配置，不要写死 EXPEDITED/OCEAN。
D6 操作日志 每次 query/update 记：FBA、method、请求摘要、code/msg、耗时、操作人（定时任务记系统）。对齐 DW 页「DW操作日志」。

6. 待佳成 / 产品确认（挡联调）

  • 测试环境网关 URL（不要用生产域名测）。
  • 非 200 的 code 字典；FBA 不存在、不允许改 DW、重复提交怎么返回。
  • 「干线到达 LA」的 estimatedDeliveryDateSource 代码。
  • transportMode 是否有 AIR 等；distributionType / boxType 枚举。
  • 港口是否必须 UN/LOCODE 五位。
  • 是否限流、是否要幂等键。
  • 产品：销售产品 → STANDARD / FAST / EXPEDITED 对照表。
