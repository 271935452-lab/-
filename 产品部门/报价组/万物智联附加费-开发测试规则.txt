万物智联附加费 · 开发 / 测试规则（文字版）
来源：海外仓至外州地址报价系统.html（测算页源码）
      + 私卡报价-AI报价规则配置-MVP.html（规则维护台）
日期：2026-08-17
适用：仅外州小车（26 尺、走万物智联）。内州价表、外州 53 尺单迈价不加本套附加费。

════════════════════════════════════
一、附加费从哪来（先分清两笔钱）
════════════════════════════════════

1）平台基础运费（API）
   万物智联 createQuote 返回的 totalCharge / totalFreightCharge。
   这是该车（板数 + 磅重 + 货运等级 + 起终点）的卡车运费。
   不在本规则表里维护。

2）本地附加费表（本规则说的「附加费」）
   不在 API 价里取 Lift Gate / Appoint / Residential 这三项金额。
   金额来自测算页各仓配置 carrierAccessorial（承运商附加费表）。
   规则维护台不维护这张表（无附加费模块）。改金额以测算页为准。
   查表方式：承运商名称包含表内 key 即命中；命不中用缺省值。

3）州合规附加（第三笔，跟地址类型无关）
   看收货州，不看住宅/商业：
   - 收货州 = CA：从 API rates 里找 rateCodeValue = "California Compliance Surcharge"，有则加上，没有则 0。
   - 收货州 = TX：合规附加 = API 基础运费 × 6.25%。
   - 收货州 = GA：配置为 0。
   - 其他州：0。
   洛杉矶仓测算页写了 CA→api；休斯顿仓写了 TX→0.0625。上线按收货州判定，不按起发仓。

总价（该车、该承运商）=
   API 基础运费
 + 尾板（若触发）
 + 预约（若触发）
 + 住宅费（若触发）
 + 州合规附加（若触发）

报价员核对时看到的渠道价应含上述合计。业务员只收确认后最优 1 条单价（个位 USD/KG），不看附加费拆项。
尾端派送费仍是确认台按票取整登记，不做计算，与本套附加费不是同一笔。

════════════════════════════════════
二、什么时候加、什么时候不加
════════════════════════════════════

只看询价「收货地址类型」。起发仓默认商业有卸货台（洛杉矶 / 休斯顿测算页发货侧固定商业）。

地址类型          尾板 Lift Gate     预约 Appoint              住宅费 Residential
住宅              加                  加（因为不是「有卸货台」）   加
商业 · 无卸货台    加                  加                          不加
商业 · 有卸货台    不加                不加                         不加

口诀：
- 尾板：住宅 或 无卸货台 → 加。有卸货台 → 不加。
- 预约：只要不是「商业有卸货台」→ 加。有卸货台 → 不加。
- 住宅费：只有住宅 → 加。两种商业都不加。

金额 = 0 的承运商（表内 appoint=0，如 Estes、FedEx）即使「该加预约」，加的也是 $0，总价不变。测试时要区分「规则触发了」和「金额为 0」。

内州（≤150 迈）：不走万物智联，不加本表。26 尺只在报价上标注「可能受尾板限制」，费用走距离档起步+续托。
外州 53 尺：走单迈价，不加本表。尾量改成 26 尺的那一辆才走万物智联，那一辆要加附加费。

多车：
- 满载 26：平台测一次，附加费按同一地址类型加在每辆满载车上（测算页满载车复用同一条平台价，附加费同样复用）。
- 尾量 26：独立再测，附加费再加一次（同一地址类型，金额按该承运商表）。
- 禁止 53 的地址（住宅 / 无卸货台）：全部是 26，每辆都加。

════════════════════════════════════
四、请求平台时带的地址标记（和加费是两件事）
════════════════════════════════════

调用 createQuote 时，收货侧会把标记传给平台：
- isResidential = 住宅
- liftGate     = 住宅 或 无卸货台
- appoint      = 不是「有卸货台」
- limitedAccess = false（本期不做）

发货侧：洛杉矶 / 休斯顿测算页固定商业、不传住宅/尾板；其他仓按发货地址类型动态传。本期询价起发仓由销售产品绑定，默认商业有卸货台。

开发注意（待产品确认，测试先按现状做对照）：
测算页现状是「请求里带了 liftGate/appoint 标记，返回后再用本地表加一遍」。
若平台已按标记把尾板打进 totalCharge，本地再加会重复。
上线二选一，不要两头都加：
  A. 请求带标记，总价直接用 API totalCharge，本地表只作核对/缺省；
  B. 请求不带附加服务标记，总价 = API 基础运费 + 本地表。
本期测试用例按 B 的金额口径写期望值（API 基础运费 + 本地表），并加一条「对照 API 明细是否已含 Lift Gate」的探索用例。

════════════════════════════════════
五、给开发的计算步骤
════════════════════════════════════

仅当：距离 >150 迈 且 该车是 26 尺（含外州大车拆完改小车的尾量车）。

对每一辆 26、每一个启用中的优先品牌：
1. 调万物智联，拿到该品牌最便宜 1 条，记 apiTotal。
2. 用承运商名查附加费表，得 liftGate / appoint / residential 单价。
3. 按第二节开关：不触发的项置 0。
4. 按收货州算 complianceFee。
5. 渠道价 = apiTotal + 触发项之和 + complianceFee。
6. 优先 8 个启用品牌各出 1 条（有报价才出）。8 个全部没有、或部分没有：再从其他承运商按总价从低到高补上，返回给报价员。不能因为 8 个没价就整票空。
7. 仅报价员可见这些条；确认后最优 1 条给业务员（单价口径个位 USD/KG，附加费已含在该产品测算里，不单独给业务员拆项）。

满载车：同一满载规格只请求一次，附加费按辆数连加（N 辆满载 = N × 单车含附加费总价）。
尾量车：另一次请求，附加费再加一套。

金额验算示例（人工可算）：

例 A  住宅 + XPO + 非 CA/TX，假设 API=328
     328 + 80 + 25 + 100 = 533

例 B  无卸货台 + Estes，假设 API=310
     310 + 75.58 + 0 + 0 = 385.58

例 C  有卸货台 + 收货 TX，假设 API=400
     400 + 0 + 0 + 0 + 400×0.0625 = 425

例 D  住宅 + 收货 TX + XPO，假设 API=400
     400 + 80 + 25 + 100 + 25 = 630
     （6.25% 只乘 API 基础运费 400，不乘三项附加费——与测算页一致：complianceFee = apiTotal * 0.0625）

════════════════════════════════════
七、验收要点
════════════════════════════════════

- 有卸货台：三项附加费全 0（合规仍可有）。
- 无卸货台：有尾板、有预约、无住宅费。
- 住宅：三项都有（预约金额可为 0）。
- 内州、外州大车：不加这张表。
- 附加费按车加，满载复用、尾量另加。
- 8 品牌优先；没有则取其他最便宜补位。补位承运商附加费按表命中或缺省。
- 报价员可见含附加费的渠道总价；业务员只见确认后单价，不拆附加费。
- 附加费金额不在规则维护台改；跟测算页承运商表。品牌启用仍在规则维护「外州规则」。
