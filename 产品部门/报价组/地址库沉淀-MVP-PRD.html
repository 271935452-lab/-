一、业务员询价（PC + APP）

入口：询价编辑 PC · 询价编辑 APP 散货。角色：业务员。

1.1 详细地址与 AI 识别 NEW

字段来源口径原型
详细地址录入新增必填（街道门牌级）。AI 识别入口挪至本字段（上传/识别回填城市、州、邮编、门牌）。询价编辑 · 详细地址
城市 / 州 / 邮编录入 / AI 回填必填；州须与邮编一致（纽约跨州确认规则见组总 PRD）。同页
询价详情备注录入其他备注 / 客户备注；地址 AI 识别入口在「详细地址」询价编辑 · 备注

1.2 匹配地址库并带出类型 NEW

页面 vs 落库：询价编辑不要求业务员单独填「门牌号 / 街道名」；匹配用字段在首次保存/提交时由系统 Geocode 写入地址主档（见 §5.3 附）。撞库不用「详细地址整段文本是否一致」（顺序、缩写不同仍应命中同键）。

  1. 保存/提交前：调用 Google 地理编码（输入 = 详细地址 + 城市 + 州 + 邮编）；解析 门牌级结构化结果（如 street_number、route、postal_code；系统可用 place_id，不对业务展示）。
  2. 生成匹配键：优先 place_id；否则 标准化邮编 + 门牌号 + 街道名（route）。Suite / Unit / # 不进匹配键（同一门牌一条主档，见 ADDR-R1）。
  3. 用匹配键强查地址主档。Google 失败时降级：仅按邮编 + 门牌号（标准化后）匹配，并记录降级原因供监控。
  4. 命中：询价单关联已有 ADDR；静默带出 一级场景（地址类型）（业务员可改三选一）。
  5. 未命中：见 §1.3；当次即写入 Geocode 结构化字段 + 匹配键（非「第二次才规范」）。
  6. 命中后仅带出地址类型；业务员侧不展示地址库历史概率、票次、等时次数。

1.2 附 · 录入阶段 vs 保存/提交 NEW

阶段Geocode / 撞库地址类型（三选一）地址库关联
录入中（未点保存/提交） 不调用 Google 做正式撞库；不对详细地址做正则拆门牌当主路径 业务员自选三选一，或不选（允许空，交给报价员核实） 无；询价单尚未绑定 ADDR
保存/提交（唯一正式入口） 按 §1.2 调用 Geocode → 匹配键查主档；可与测距同一次编码结果 见下表「提交时类型规则」；结果回写表单/询价快照，业务员仍可改选项后再次保存（若产品允许多次保存） 命中关联已有主档，或未命中当次新建并关联

原型说明：询价编辑 PC 在邮编/详细地址 input、失焦时演示「带出类型」，为本地假库验收，不是上线口径。开发不得按该交互在录入阶段写库或替代 Geocode。

可选体验（非 P0）：若要做失焦「预览」，须与 §1.2 同一套 Geocode + 匹配键，只读、不写 ADDR；正式关联与类型以保存/提交结果为准。未单独立项则不做。

1.2 附 · 提交时地址类型规则 NEW

撞库结果地址类型怎么处理报价员侧
命中已有主档 按主档生效一级场景（海外已核实 > 报价已核实 > 业务员曾填）静默回填三选一；业务员可改，不以回填为锁死 库中类型已核实且与本单地址一致 → 核实区可跳过（见 §3.1）；否则仍可能待核实
未命中（当单新建主档） 不用库值「修正」类型；保留业务员当次已选（若有），写入新主档；未选则空 新地址或库中从未核实类型 → 须完成「确认核实（本地址）」后才能核对确认（§3.1）

1.3 未匹配则新增主档 NEW

  1. 未命中：创建地址主档，编号 ADDR + 四位顺序号。
  2. 展示：标准化地址 = 详细地址 + 城市 + 邮编 + 州（列表/抽屉；可追加别名存客户原文）。
  3. 匹配：写入 §5.3 附系统字段（place_id / 邮编 / 门牌 / 街道 / 匹配键等），来源当次 Geocode。
  4. 初始状态：业务提交；写入业务员当次一级场景（若有）。

1.4 一键下单（仅 PC） NEW

入口：我的询价 · 已确认报价的散货询价单行 ·「一键下单」。

  1. 弹出下单弹窗（iframe/抽屉），打开 FBA 录入（或现网等价下单页）。
  2. 自动回填：重量、客户、销售产品、地址信息（详细地址/城市/州/邮编）、产品信息、询价详情中的客户备注、询价附件。
  3. 业务员补录下单页其余必填项后提交；系统不自动下单。

二、询价详情（报价员回传后）

入口：ESS散货询价详情。角色：业务员。

  1. 报价员未「核对确认」：无单价、无地址提示，状态「报价中」。
  2. 核对确认后：展示各渠道单价（N 渠道 N 条）。
  3. 地址提示门控：仅当本单提交询价时按 §1.2 已命中地址库已有主档（邮编+门牌），接口才返回 addrMaskConcl，页面展示「地址提示」整块。本单未命中、新建主档时：接口不返回该对象，页面不展示地址提示区域（不出现空绿条）。APP 同口径。
  4. 有地址提示时：整票一份，含地址类型、默认可进车型；不展示迈数。字段名为产生等时费比例、使用尾板比例（发生次数 ÷ 该地址历史票数）、平均签收时效（上传 POD 时间 − 出发时间的平均天数）。无历史票时后三项为「—」。不展示逐票次数明细。
  5. 多渠道须单选 1 条后「确认报价」；不展示尾程派送费、AI 试算、万物智联品牌。
  6. 绑运单由报价员在报价员详情完成，本页不做绑单。
场景提交时地址库核对确认后接口询价详情 UI
命中已有主档邮编+门牌匹配到库中记录返回 addrMaskConcl单价 + 地址提示
未命中新建新增 ADDR，业务提交不返回 addrMaskConcl仅单价

细则见 散货 PRD §4.5。

三、报价员报价

入口：报价员详情 · 报价员列表。

3.1 核实门控与待报价

  1. 地址类型默认取地址库（海外已核实 > 报价员核实）。
  2. 新地址或库中该地址从未核实类型：须在本单完成「确认核实（本地址）」后才能核对确认；否则单据保持 待报价（或 AI 待确认但不展示有价卡）。
  3. 库中类型已核实且与本单收货地址一致：可跳过重复核实 UI（只读展示）。
  4. 配送距离：询价提交时已由 Google 写入试算快照；报价员在「试算日志」查看，不需在核实区填写迈数。

3.2 地址类型核实区

展示规则
回写业务员填写只读一行摘要（业务员当次三选一）。
默认带出地址库 海外已核实一级场景；无则 报价员核实；均无则展示核实区且必选。
海外已核实存在类型只读，不需再点核实。

3.3 配送距离（Google · 本期不做报价员核实）

v1.1.0 起：取消报价员详情「派送距离核实 / 核实迈数」区块。各销售产品/海外仓的里程在询价提交时由 Google Routes / Distance Matrix 测算，仅出现在试算日志与算价引擎；地址主档不维护「报价员核实距离」从表。

3.4 相同地址近期询价提醒 NEW

入口锚点：报价员详情 · repeatInquiryPanel。与「地址类型核实」并排，占用原核实迈数栏位。

  1. 命中：滚动 30 天 · 同邮编+同详细地址（标准化口径同撞库）· 同货量口径（计费重/体积等与本次一致）。
  2. 不限历史业务员/报价员；展示每次时间、询价单号、业务员、报价员、各销售产品单价+尾程。
  3. 无命中不展示；只读，不阻断核实与核对确认。业务员侧不展示。
