  9. 保存/提交 → 后台 AI 试算；业务员仍为「报价中」，不见试算日志

项大白话
业务痛点地址写得乱，类型靠猜；同一地址重复录入；业务员不该看到历史敏感统计
这页要达成地址规范录入 + 静默匹配地址库 + 类型可改；测距算价放后台，业务员只负责把货和地址填对
和 V1 散货 AI仍走「提交 → AI 试算 → 报价员核对」；本页是入口，改的是字段与地址库写库

三、功能怎么走

环节大白话原型
打开编辑 入口
  1. 我的询价 →「+ 新增询价」或行「编辑」
  2. APP 散货同字段，无本页特有能力差异（除一键下单仅 PC 他页）
 我的询价
AI 识别地址 XJ-01
  1. 在详细地址触发识别/上传
  2. 回填城市、州、邮编、门牌等；备注区不提供识别入口
 详细地址
匹配地址库 XJ-02
  1. 保存/提交前：按收货邮编 + 门牌号（标准化）强匹配
  2. 命中：静默带出一级场景（地址类型）到三选一，业务员可改
  3. 不展示历史票次、等时次数、敏感长文案
 地址类型
未匹配新增 XJ-03
  1. 创建主档 ADDR + 四位序号
  2. 标准化地址 = 详细地址 + 城市 + 邮编 + 州
  3. 状态待报价核实；写入业务员当次选的一级场景（若有）
 —
保存校验
  1. 缺必填 → 拦截标红
  2. 收货州 ≠ 邮编所在州 → 拦截（含误填海外仓州）
  3. 纽约海外仓：仓州 ≠ 收货州（NY/NJ 跨州）→ 弹窗确认，不拦截；价表按收货州匹配（NY 一口价 / NJ 距离档）
  4. 业务员不可手填距离，不可手切内外州
 保存
提交后后台 V1+本页
  1. 按各所选销售产品绑定海外仓 → 仓邮编 + 收货邮编测距
  2. 判定内州/外州（默认 ≤150 / >150 迈，规则页可改）
  3. 713 / 万物智联试算 → 报价员列表进 AI待确认
  4. 业务员侧保持「报价中」，无单价、无试算日志
  5. 新地址须报价员在详情核实类型+迈数后才能出价（见报价员专稿）
 —
PC / APP 一致 XJ-04 详细地址、匹配、类型带出、保存校验口径一致；APP 不做一键下单。 APP 散货
