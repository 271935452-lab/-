〇、背景 · 目标 · 验收 · 变更

背景 尾端地址类型与卸货条件需从询价→报价核实→港后履约沉淀为可复用档案；业务员侧不暴露历史敏感明细；报价取库内已核实类型与迈数。
目标 本清单 A–E 节功能点一次确认，开发与验收按勾选条目执行；分角色负责人签字后进入排期。
验收 以本清单勾选 + 验收用例 为准；PRD 不含测试条文。
变更 签字后范围变更须升版清单并四方重新签字；A–E 未勾选条目本期不做；F 节为各方确认的明确不做边界。

签字分工：A 节由询价 · 业务员侧负责人签；B 节由报价 · 报价侧负责人签；C 节由海外 · 港后负责人签；D/E 与整体优先级由项目负责人总签；F 节（不在本期）由项目负责人确认边界（四方知悉）。四方均签后视为 V2 需求定稿。

A. 询价侧（业务员）询价负责人签字

PC：询价编辑 · 我的询价 · 询价详情；APP：散货询价编辑 · 询价详情 APP。

确认编号功能点
录入与地址库匹配
XJ-01 详细地址必填；AI 识别入口迁至详细地址；询价详情/备注区仅保留其他客户备注（不再承担识别入口）
XJ-02 按邮编 + 门牌号匹配地址库，命中则静默带出地址类型（三选一，可改）；不展示历史票次/次数等敏感长文案
XJ-03 未匹配则新增地址主档（ADDR+四位序号），状态待报价核实
XJ-04 APP 与 PC 字段口径一致（详细地址、匹配、类型带出；APP 不做一键下单）
确认报价与下单
XJ-05 询价详情：报价员核对确认后展示多渠道单价 + 地址脱敏结论；多渠道单选 1 条后「确认报价」；不展示尾程/AI 过程
XJ-06 报价中无单价与脱敏结论；绑运单不在业务员询价详情完成

B. 报价侧（报价员）报价负责人签字

报价员列表 · 报价员详情 · AI 规则见 V1 组总 PRD。

确认编号功能点
QT-01 地址类型、核实迈数默认取地址库（海外已核准 > 报价员核实）；报价匹配可读待海外核准 / 海外已核准主档
QT-02 新地址或库中未核实：须完成核实后才能出价/核对确认，否则单据保持待报价（或 AI 待确认但无价卡）
QT-03 地址类型核实区：回写业务员填写；默认带出海外/报价员库值；海外已核准则只读；无库值则必选后核实
QT-04 迈数核实区：按始发仓/销售产品分行展示 AI 测算；核实迈数默认带出地址库，无则必填；有则免填
QT-05 「确认核实（本地址）」一次提交：类型 + 本单涉及各行迈数写入地址库
QT-06 核实完成后方可「核对确认」回写业务员；全渠道有价规则、试算日志、绑运单沿用 V1 口径
QT-07 核对确认后主档状态 → 待海外核准（港后补齐后 → 海外已核准）
QT-08 核实迈数按始发仓/销售产品沉淀至地址库，仅报价员核实写入（海外不写迈数）

一、业务员询价（PC + APP）

入口：询价编辑 PC · 询价编辑 APP 散货。角色：业务员。

1.1 详细地址与 AI 识别 NEW

字段来源口径原型
详细地址录入新增必填（街道门牌级）。AI 识别入口挪至本字段（上传/识别回填城市、州、邮编、门牌）。询价编辑 · 详细地址
城市 / 州 / 邮编录入 / AI 回填必填；州须与邮编一致（纽约跨州确认规则见组总 PRD）。同页
询价详情备注录入其他备注 / 客户备注；地址 AI 识别入口在「详细地址」询价编辑 · 备注

1.2 匹配地址库并带出类型 NEW

  1. 保存/提交前，按 收货邮编 + 门牌号（标准化后） 强匹配地址主档。
  2. 命中：静默带出 一级场景（地址类型） 至询价表单（业务员可改选三选一：住宅 / 商业无卸货台 / 商业有卸货台）。
  3. 命中后仅带出地址类型；业务员侧不展示地址库历史概率、票次、等时次数。

1.3 未匹配则新增主档 NEW

  1. 未命中：创建地址主档草稿，编号规则 ADDR + 四位顺序号。
  2. 标准化地址 = 详细地址 + 城市 + 邮编 + 州（展示用，可追加别名）。
  3. 初始状态：待报价核实；写入业务员当次填写的一级场景（若有）。

1.4 一键下单（仅 PC） NEW

入口：我的询价 · 已确认报价的散货询价单行 ·「一键下单」。

  1. 弹出下单弹窗（iframe/抽屉），打开 FBA 录入（或现网等价下单页）。
  2. 自动回填：重量、客户、销售产品、地址信息（详细地址/城市/州/邮编）、产品信息、询价详情中的客户备注、询价附件。
  3. 业务员补录下单页其余必填项后提交；系统不自动下单。

二、询价详情（报价员回传后）

入口：ESS散货询价详情。角色：业务员。

  1. 报价员未「核对确认」：无单价、无地址提示，状态「报价中」。
  2. 核对确认后：展示各渠道单价（N 渠道 N 条）。
  3. 地址提示门控：仅当本单提交询价时按 §1.2 已命中地址库已有主档（邮编+门牌），接口才返回 addrMaskConcl，页面展示「地址提示」整块。本单未命中、新建主档时：接口不返回该对象，页面不展示地址提示区域（不出现空绿条）。APP 同口径。
  4. 有地址提示时：整票一份，含地址类型、默认可进车型；不展示迈数。字段名为产生等时费比例、使用尾板比例（发生次数 ÷ 该地址历史票数）、平均签收时效（上传 POD 时间 − 出发时间的平均天数）。无历史票时后三项为「—」。不展示逐票次数明细。
  5. 多渠道须单选 1 条后「确认报价」；不展示尾程派送费、AI 试算、万物智联品牌。
  6. 绑运单由报价员在报价员详情完成，本页不做绑单。
场景提交时地址库核对确认后接口询价详情 UI
命中已有主档邮编+门牌匹配到库中记录返回 addrMaskConcl单价 + 地址提示
未命中新建新增 ADDR，待报价核实不返回 addrMaskConcl仅单价

细则见 散货 PRD §4.5。

三、报价员报价

入口：报价员详情 · 报价员列表。

3.1 核实门控与待报价

  1. 地址类型、核实迈数默认取地址库（海外已核准 > 报价员核实）。
  2. 新地址或库中该地址从未核实类型/迈数：须在本单完成「确认核实（本地址）」后才能 AI 出价/核对确认；否则单据保持 待报价（或 AI 待确认但不展示有价卡）。
  3. 库中已核实且与本单收货地址一致：可跳过重复核实 UI（只读展示）。

3.2 地址类型核实区

展示规则
回写业务员填写只读一行摘要（业务员当次三选一）。
默认带出地址库 海外已核准一级场景；无则 报价员核实；均无则展示核实区且必选。
海外已核准存在类型只读，不需再点核实。

3.3 迈数核实区

展示规则
AI 测算值按始发仓 / 销售产品分行展示「AI测算」只读。
核实迈数默认带出地址库该「地址 + 始发仓（+ 销售产品）」已核实迈数；无则输入框为空且必填；有则免填。
落库与类型同地址一次确认写入地址库（按本单涉及的始发仓/销售产品各行）。

背景与目标

项内容
用户价值业务投诉报价慢。看板让报价员和上级看到：从业务员重提，到报价员把价回给业务员，有没有落在 20 分钟内。
公司价值报价时效进月度考核。当前查询范围内，有效询价的 20 分钟内占比 ≥90% 即达标。
主用户报价员（看自己）、报价主管 / 组长（看下级）、报价部门负责人与管理员（看全部）。

可量化目标单票有效时长 ≤20 分钟为未超时；月度整体达成率 ≥90% 达标。平均时长只作参考，不单独作为达标条件。

三、功能逻辑

功能点说明原型
什么算有效
  1. 散货同时满足：重提时刻在 09:00–18:00；重提时刻不在 11:30–13:00；报价员已核对确认，或 AI 失败后的人工报价已提交。
  2. 整柜同时满足：重提时刻在 09:00–18:00；不在午休；全部手报方案已提交。
  3. 以下不算有效，不进分母：未重提（草稿、打回后未重提）、时段外或午休重提、仍停在待报价 / AI待确认、全渠道价未齐还不能核对、只试算未核对、已打回且本轮未重提。
  4. 已完结（已绑运单）仍算有效，时长沿用首次核对确认，绑单不延长、不重算。
  5. 测：Given 询价停在 AI待确认 When 打开当月看板 Then 该单不进有效票数。
 KPI
计时 改
  1. 起点一律是重提时间。打回前的等待不算进报价员考核。
  2. 终点散货 = 核对确认保存成功（列表变为已报价，业务员见到人工已报价）。AI 失败走人工报价时，终点 = 该次报价提交。
  3. 终点整柜 = 全部手报方案提交完成。
  4. 午休：过程与 11:30–13:00 有重叠就扣掉重叠分钟。整段跨过午休扣 90 分钟。

## 1. 什么是「有效」

**有效询价** = 纳入报价时效看板统计（计入票数、平均时长、超时占比）的询价单。

**不是**系统里所有询价单都会统计。看板上的「有效询价票数」是分母，只包含满足下文全部条件的单据。

**有效时长** = 在有效询价上，按规则计算出的报价耗时（分钟），用于判断是否超时及求平均。

散货新流程：业务员提交 → AI 试算 → **AI待确认**（价不回业务员）→ 报价员**核对确认** → 业务员见「人工已报价」。本看板量的是从重提到报价员把价回给业务员，不量绑运单、不量业务员再点「确认报价」。

## 2. 「有效」与「无效」判定总表

| 判定 | 条件 | 是否计入看板 | 说明 |
|------|------|-------------|------|
| **有效 · 散货** | 当日 **09:00–18:00** 重提 + 已**核对确认**（或 AI 失败后人工报价已提交） | ✓ | 从重提起算，到核对确认 / 人工报价提交 |
| **有效 · 整柜** | 09:00–18:00 重提 + 全部手报方案已提交 | ✓ | 整柜本期无 AI |
| **有效** | 重提时刻不在 **11:30–13:00** | ✓ | 午休时段重提整单剔除 |
| **无效** | 未重提（草稿、打回后尚未重提） | ✗ | 不算一次有效询价 |
| **无效** | **09:00 前** 或 **18:00 后** 重提 | ✗ | 非工作统计时段 |
| **无效** | **11:30–13:00** 重提 | ✗ | 午休剔除 |
| **无效** | 仍停在待报价 / AI待确认 | ✗ | 价未回业务员 |
| **无效** | 全渠道价未齐、尚不可核对 | ✗ | 对齐 AI「整票价齐才可核对」 |
| **无效** | 打回后尚未重提的轮次 | ✗ | 作废轮次 |

## 3. 询价计时起点（已确认）

**不单独区分「草稿 / 打回重提 / 业务员撤回重提」，统一以重提时间为准。**

- **重提时间** = 有效轮次业务员**最后一次正式提交**时刻（首次正式提交即该轮重提时间）。
- 草稿保存、打回前提交、业务员撤回前提交等**作废轮次**不参与计时。
- 打回前的等待时间**不算**在报价员考核里。

**示例**

```
09:00 提交 → 打回 → 09:40 重提 → 09:55 核对确认
→ 有效轮次起点 = 09:40（重提时间）
→ 终点 = 09:55（核对确认）
→ 有效时长 = 15 min
```

---

## 4. 有效时长计算（在「有效询价」上）

| 步骤 | 规则 |
|------|------|
| 起点 | 有效轮次 **重提时间**（见 §3） |
| 终点 · 散货 | 报价员「**核对确认**」保存成功；AI 失败走人工「报价」时取该提交时间 |
| 终点 · 整柜 | **全部手报方案提交完成** |
| 午休扣除 | 若过程跨越 11:30–13:00，**减去 90 分钟** |
| 公式 | `有效时长 = (终点 − 起点) − 午休重叠分钟` |
| 超时 | 有效时长 **> 20 分钟** |

**不改终点**：业务员「确认报价」、绑运单 / 改绑 / 解绑、核对后撤回再核对（本轮以**首次核对确认**关账）。

---

## 5. 看板指标与「有效」的关系

| 指标 | 计算 |
|------|------|
| 有效询价票数 | 当日满足「有效」条件的询价单数（散货/整柜分别统计） |
| 平均报价时长 | `SUM(有效时长) / 有效询价票数` |
| 超时票数 | 有效时长 > 20 min 的单数 |
| 超时占比 | `超时票数 / 有效询价票数 × 100%` |
| **达成率** | `(有效询价票数 − 超时票数) / 有效询价票数 × 100%`（= 20min 内占比） |

明细列「完成路径」：散货 = AI核对 / 人工兜底；整柜 = 手报价。散货不再用「报价方案数」判定完成。

## 5.1 月度考核（7/24 袁华君补充）

| 指标 | 说明 |
|------|------|
| 统计周期 | **自然月**（按有效轮次**重提时间**归属月份） |
| 月度有效票数 | 当月全部有效询价合计（散货/整柜分别统计） |
| 月度超时票数 | 当月有效时长 > 20 min 的单数 |
| **月度达成率** | `(月度有效 − 月度超时) / 月度有效 × 100%` |
| **考核达标** | 月度整体达成率 **≥ 90%** 即达标（不要求平均时长单独达标） |
| 按人考核 | 每人当月达成率 ≥ 90% 为个人达标；看板需展示个人 + 整体合计行 |

**示例：** 散货 7 月有效 532 单，超时 45 单 → 达成率 91.5% → **达标**。

**备注文案（看板展示建议）：**

> 有效询价：09:00–18:00 重提，且报价员已核对确认（散货）或手报完成（整柜）；剔除午休重提、作废轮次。计时起点为重提时间，散货终点为核对确认，整柜终点为全部手报方案提交。

## 6. 系统实现要点

### 6.1 需落库字段

| 字段 | 用途 |
|------|------|
| `inquiry_no` | 询价单号 |
| `submit_seq` | 提交轮次（1, 2, 3…） |
| `resubmit_time` | 重提时间（有效轮次最后一次正式提交） |
| `quote_done_time` | 散货=核对确认 / 人工报价提交；整柜=全部方案提交 |
| `done_path` | AI核对 / 人工兜底 / 手报价 |
| `is_valid_for_sla` | 是否纳入 SLA 统计 |
| `invalid_reason` | 无效原因：未重提/时段外/午休/待核对/价未齐/已打回 |

### 6.2 计算逻辑（伪代码）

```text
FOR each inquiry ON stat_date:
  IF 无有效重提 OR 仅草稿/作废轮次 → invalid
  IF 最新有效轮次 resubmit_time NOT IN [09:00, 18:00] → invalid
  IF 最新有效轮次 resubmit_time IN [11:30, 13:00) → invalid
  IF 散货 AND 尚未核对确认 AND 尚未人工报价提交 → invalid
  IF 整柜 AND 未全部方案报价完成 → invalid

  start = 最新有效轮次.resubmit_time
  end   = 最新有效轮次.quote_done_time   // 散货=首次核对确认
  duration = end - start - lunch_overlap(start, end)

  IF duration > 20 → timeout
  ELSE → normal

  纳入看板汇总（按报价员 × 散货/整柜）
```

### 6.3 明细页建议展示

- 询价单号、业务类型、报价员
- **当前统计轮次**（第几次提交）
- **重提时间**、报价完成时间、完成路径
- 是否有效、无效原因（无效单可单独 Tab 查看，不进 KPI）
- 有效时长、是否超时

## 8. 权限（按组织结构）

数据可见范围与系统**组织架构 / 汇报关系**挂钩，接口层强制过滤。

|------|----------|
| **报价员** | 仅**本人**（统计、KPI、汇总、超时明细） |
| **上级**（主管 / 组长等） | **本人 + 组织下级**（直接/间接下属，以组织树为准） |
| **其他管理角色**（报价主管、部门负责人、管理员等） | **全部**报价员 |

**补充规则**

- 「上级看下级」：按**当前生效的组织汇报关系**解析；人员调动以组织主数据为准。
- 汇总「合计 / 整体」行：在**当前用户可见范围**内重算（管理员看全部时为全量）。
- **导出 Excel**：与当前可见范围一致。
- 报价员登录时「报价员」筛选默认锁定本人（或隐藏该筛选项）。
