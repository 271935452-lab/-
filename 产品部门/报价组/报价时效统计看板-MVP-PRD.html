需求来源

报价组袁华君 7/24 沟通 · 2026-09-27 按散货 AI 核对确认改终点。背景：业务投诉报价慢，需将报价时效纳入月度考核。散货现网是 AI 试算 + 报价员核对后才回写业务员；整柜仍手报。单票 ≤20 分钟，月度达成率 ≥90% 即达标。

页面说明

按报价员维度统计，分散货 / 整柜；上方筛选确定统计范围，下方展示当前查询统计结果。页面仅保留筛选、KPI、汇总与明细；规则口径见本 PRD。

考核标准（7/24 袁华君）

当前查询范围内，有效询价中 20 分钟以内占比（达成率）≥ 90% 即达标。

达成率 = (有效票数 − 超时票数) / 有效票数 × 100%

口径摘要（已按 AI 核对确认改）

  • 有效：09:00–18:00 重提，且报价员已完成核对确认（散货）或手报价提交（整柜）；剔除午休重提 / 未重提轮次。
  • 询价计时：统一以重提时间为起点（业务员最后一次正式提交）。
  • 报价计时 · 散货：以报价员核对确认保存为终点（单价回写业务员 = 已报价）。AI 失败走人工「报价」提交的，以该提交时间为终点。
  • 报价计时 · 整柜：仍以全部手报方案提交完成为终点（整柜本期无 AI）。
  • 不计入本段时效：业务员「确认报价」、绑运单 / 改绑、试算耗时单独不拆、撤回核对后再核对（首次核对已关账）。
  • 超时：有效时长 > 20min · 考核看达成率 ≥90%。

背景与目标

业务投诉报价慢。散货新流程：业务员提交 → 后台 AI 试算 → AI待确认（价不回业务员）→ 报价员核对确认 → 业务员见「人工已报价」。考核量的是从重提到报价员把价回给业务员，不再量「报几个方案」。单票目标 ≤20 分钟；月度整体达成率 ≥90% 即达标。

统计维度

  • 报价员：按完成报价的报价员统计，不分渠道。
  • 业务类型：散货(LCL) / 整柜(FCL) 分 Tab，散货优先。
  • 统计范围：由筛选条件确定（默认统计月份）；KPI 与汇总均为当前查询统计，无日报/月报切换。

1. 什么是「有效」

有效询价 = 纳入看板 KPI 的分母，不是系统全部询价单。

  • 有效 · 散货：09:00–18:00 重提 + 报价员已核对确认（或 AI 失败后的人工报价已提交）+ 重提时刻不在 11:30–13:00。
  • 有效 · 整柜：09:00–18:00 重提 + 全部手报方案已提交 + 重提不在午休。
  • 无效：未重提（草稿 / 打回后未重提）、时段外或午休重提、仍停在「待报价 / AI待确认」、全渠道价未齐尚不可核对、仅试算未核对。

1.1 对齐散货 AI 状态（报价员侧）

报价员状态是否进时效说明
待报价否AI 未出账或失败，报价员尚未人工提交
AI待确认否价未回业务员；全渠道未齐时不可核对
已报价（核对确认后）是终点 = 核对确认保存时刻
已完结（已绑运单）是（沿用首次核对）绑单不延长、不重算本段时效
已打回否本轮作废，等业务员重提

2. 询价计时起点（已确认）

不单独区分「草稿 / 打回重提 / 业务员撤回重提」，统一以重提时间为准。

  • 重提时间 = 有效轮次业务员最后一次正式提交（首次正式提交即该轮重提时间）。
  • 草稿保存、打回前提交、业务员撤回前提交等作废轮次不参与计时。
  • 打回前等待不算在报价员考核里。
  • 示例：09:00 提交 → 打回 → 09:40 重提 → 报价员 09:55 核对确认 → 从 09:40 起算。

3. 有效时长计算

  • 起点：重提时间（见 §2）。
  • 终点 · 散货：报价员详情「核对确认」保存成功（列表 → 已报价，业务员见人工已报价）。AI 失败走人工「报价」时，终点 = 该次报价提交。
  • 终点 · 整柜：全部手报方案提交完成。
  • 午休扣除：过程跨越 11:30–13:00 时减 90 分钟。
  • 公式：有效时长 = (终点 − 起点) − 午休重叠分钟。
  • 超时：有效时长 > 20 分钟。

不改终点的动作：业务员询价详情「确认报价」；报价员绑运单 / 改绑 / 解绑；核对后的撤回再核对（本轮时效以首次核对确认关账）。

4. 看板指标

  • 有效询价票数：满足有效条件的单数。
  • 平均报价时长：SUM(有效时长) / 有效票数（参考指标）。
  • 超时票数：有效时长 > 20min 的单数。
  • 达成率：(有效 − 超时) / 有效 × 100%（即 20min 内占比，无需单独展示票数）。
  • 完成路径（明细列）：散货 = AI核对 / 人工兜底；整柜 = 手报价。散货不再用「报价方案数」判定完成。

5. 月度考核（7/24 袁华君）

  • 统计周期：自然月（按有效轮次重提时间归属月份）。
  • 月度有效 / 超时 / 达成率：当月汇总，散货/整柜分别统计。
  • 达标标准：月度整体达成率 ≥ 90% 即达标（不要求平均时长单独达标）。
  • 按人考核：每人当月达成率 ≥90% 为个人达标；汇总表需有合计/整体行。
  • 示例：散货 7 月有效 532 单、超时 45 单 → 达成率 91.5% → 达标。

6. 页面结构

  • 筛选：统计月份、统计日期（可选，不填则按整月）、报价员、是否超时、单号、业务员；点「查询」刷新当前查询统计。
  • Tab：散货 / 整柜（业务类型，非时间维度）。
  • KPI：当前查询有效、超时、达成率、平均时长、考核结果。
  • 汇总表：按报价员 + 合计行；仅超时票数 > 0 的可点击，超时明细展开在对应行下方（仅展示超时单）。
  • 导出 Excel（占位）。

7. 明细字段

  • 下钻范围：仅有效时长 > 20min 的超时询价；20min 内正常单不下钻、不展示。
  • 询价单号、业务类型、业务员、重提时间、报价完成时间（散货=核对确认 / 人工报价提交；整柜=全部方案提交）、完成路径、有效时长、扣除午休、是否超时。
  • 建议扩展：提交轮次、是否有效、无效原因（无效单可单独 Tab，不进 KPI）。

8. 落库字段（实现参考）

  • inquiry_no、submit_seq、resubmit_time（重提时间）、quote_done_time（散货=核对确认时间 / 人工报价提交时间；整柜=全部方案提交时间）、done_path（AI核对 / 人工兜底 / 手报价）、is_valid_for_sla、invalid_reason。

9. 权限（按组织结构）

数据可见范围与系统组织架构 / 汇报关系挂钩，接口层强制过滤；前端筛选「报价员」下拉仅展示当前用户有权查看的人员。

  • 报价员：仅可查看本人的统计、KPI、汇总行及本人超时明细；不可查看其他报价员数据。
  • 上级（主管 / 组长等）：可查看本人 + 组织下级（直接/间接下属，以组织树为准）的报价员数据；不可越级查看平级或其他分支。
  • 其他管理角色（如报价主管、部门负责人、管理员等非一线报价岗位）：可查看全部报价员数据。

规则说明

  • 「上级看下级」：按当前生效的组织汇报关系解析；人员调动、兼岗以组织主数据为准（与人员映射/组织模块一致）。
  • 汇总「合计 / 整体」行：在当前用户可见范围内重算，非全公司口径（管理员等看全部角色除外）。
  • 导出 Excel：导出内容与当前用户可见范围一致，不得导出无权限数据。
  • 报价员登录时「报价员」筛选默认锁定为本人且不可改（或隐藏该筛选项）。
