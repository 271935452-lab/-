长稿 完整 skill 版 · 入口 · 签字清单 · 双入口：#/ProblemFollowUp 放行 · #/StockChecking 扣件放行确定

背景

货在仓扣件期间，销售报价可能已调价；若仍按签入单价出库，公司与客户口径不一致。放行时按 T放行 对齐有效价： 有销售报价的扣件 → §1 涨价则重算； 整柜 / 私卡无价格表 → §2 校有效期，过期仍正常放行并推报价员代办； 非扣件（集货、拼货、等柜等）价差由公司承担，不走 §1 自动涨价。

§1 重新计费 · 核心口径（开发必看）

  1. 计价时点：每次扣件放行成功的服务器时间记为当次 T放行。查价、算「放行单价」、调用重新计费时，均把该次 T放行 当作到货时间（不改运单界面「到货时间」字段）。
  2. 匹配哪张价表：在 T放行 下，按销售产品等现网维度取价——直客只匹配业务员成本报价表；同行匹配销售报价 + 业务员成本报价表。未匹配到有效价 → 拦截放行，提示 请联系产品同事维护报价。
  3. 费用类型：对齐现网费用重算能力，本需求触发的重算类型为：应收运费重算、业务成本运费重算（与运单/业务数据统计费用重算同口径）。
  4. 须同时满足才重新计费：非 §2 无价格表；走对应价表维护范围；本次为扣件放行；能匹配到 T放行 有效价；放行单价 > 签入单价。
  5. 重新计费结果：直客走业务成本运费重算（业务员成本）；同行走应收运费重算 + 业务成本运费重算。入参到货时间 = 当次 T放行。失败则放行回滚并提示。
  6. 多次放行：运单有多条扣件放行记录时，每一次放行都完整走一遍本逻辑。事后在运单/业务数据统计点「重算」时，计价时点取最近一次「放行且实际更新了费用」的 T放行（未涨价、未改费的放行不作为重算时点）。
  7. 触达与日志（涨价重算成功时同时发生）：
    • 通知业务员：运单{运单号}因扣件放行时价格上涨，已按最新的价格表更新价格，请知悉。
    • 运单日志：扣件放行同时说明，放行时间价格已上涨{上涨金额}￥，价格已按最新价格表更新。（须带放行时间说明；{上涨金额}为本次涨价差额）
    • 计费日志：按费用重算再计一轮，参数带放行时间 = T放行。
  8. 手工录入费用：若运单对应费用项（业务员成本 / 应收运费）已为手工录入，则不再匹配价表、不更新该费用（放行可成功；不触发对该项的涨价重算与 §1 通知）。

§2（无价格表）：整柜/私卡且无价格表 → 放行时校报价/绑单有效期；过期则仍正常放行，并推询价员配置对应报价员代办清单（不触发 §1 重新计费）。

§1 · 重新计费条件一览

条件不满足时
到货时间（计价）= 当次 T放行—（每次放行各记各的）
直客 → 业务员成本报价表；同行 → 销售报价 + 业务员成本报价表未匹配 → 拦截：请联系产品同事维护报价
费用类型：应收运费重算、业务成本运费重算对齐现网费用重算
放行单价 > 签入单价放行成功，维持原价，不通知
多次放行后手动「重算」时点 = 最近一次放行且更新了费用的 T放行
对应费用已手工录入不匹配价表、不更新该费用；放行可成功

通知业务员：运单{运单号}因扣件放行时价格上涨，已按最新的价格表更新价格，请知悉。

运单日志：扣件放行同时说明，放行时间价格已上涨{上涨金额}￥，价格已按最新价格表更新。

计费日志：费用重算再计一轮，参数带放行时间 = T放行。

§2 · 整柜 / 私卡无价格表

类型校验过期 / 无对标
私卡绑定询价有效期至 ≥ 放行日过期仍正常放行 + 推报价员代办；处理范例：解绑 → 重询价 → #/MyQuote 再绑
整柜有合约/报价有效期则校验；常无询价过期/无对标仍正常放行 + 推报价员清单（可无询价单号）；报价员与业务员线下沟通

操作人提示（不拦放行）：报价已过期或无有效价格，已通知报价员处理。

代办去处理：#/MyQuote · 询价单号筛选项 = 清单询价单号（例 XJ202610200031）并自动查询。

样式对齐 运单 · 签入代办、 询价 APP 列表、 RISK-006 退仓代办。 报价员代办「去处理」→ #/MyQuote（我的报价），将清单中的询价单号带入列表筛选项并触发查询；无询价单号（整柜常见）时仅打开我的报价页，不做询价单过滤。本期仅清单，不要求在代办内点放行。
