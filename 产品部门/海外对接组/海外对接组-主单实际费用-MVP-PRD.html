主单实际费用

旁支 · 计划一。按账单批次对账；日常改数覆盖当前值，不再堆对冲。 本页原型 · 产品旁支 · 计划一

范围 批次对账 批次核销（对冲退役） 批次与请款联动 字段 修改 / 附件 缺预估待办 分摊 / 撤销 导入 / 导出

一、范围

入口：财务结算 → 费用管理 → 主单实际费用。编辑对象是费用行上的修改后金额（海外口径）；应付 / 实际费用新增账单批次号维度。

点说明原型
对账主视角
  1. 页面按账单批次号汇总展示，不默认铺全部费用明细
  2. 需查看时再点「看明细」展开本批费用行
 批次列表
一批柜子
  1. 同一账单批次可含多柜、多费用行
  2. 可同时含正常费用与补收费用
 展开明细

二、账单批次对账

规则页面表现原型
BR-BATCH-001：批次汇总 列表行 = 账单批次号；展示服务商简称/全称、柜数、费用行数、含补收、实际/预估/差额 RMB、批次状态、预估缺口。 汇总表
BR-BATCH-002：点开看明细 默认不展示费用明细；点 ▸ /「看明细」展开本批柜子费用；可再勾选费用行做改金额、分摊、撤销。 看明细
BR-BATCH-003：对冲噪音 历史对冲行默认隐藏。新逻辑见「三、批次核销」——日常改数不再生成对冲行。 隐藏对冲
BR-BATCH-004：换单差额挂原单 换单差额更新原单当前金额并打标；不靠正负两笔对冲堆明细。 对冲行

三、批次核销（对冲退役）

问题：分摊 / 撤销每次写正负对冲，再改再对冲 → 单票明细指数涨（可达数十万行）。方案：用批次 + 覆盖当前值代替日常对冲。

层干什么
当前费用（Current） 主单费用只保留一行当前金额。列表、成本、提成都读这层。
账单批次（Batch） 导入 / 补收 / 调整 = 一个批次。批次确认后覆盖当前费用；不在当前表插 ± 对冲行。
变更日志（Audit） 谁、何时、改了多少、关联哪个批次。审计看日志，不靠对冲流水轧差。
场景怎么做
未请款改金额 / 分摊 / 撤销直接改当前值 + 写日志；不对冲。
补收、二次账单、已确认后再调开新批次 → 确认后覆盖/合并进当前值。
已请款 / 已付款按请款状态联动，见第四节；禁止静默改已付金额。
历史脏数据超限单票轧差固化后归档旧对冲；新单走本规则。

一句话：批次是确认边界，当前金额是唯一真相，对冲不再当日常写库方式。

原型交互怎么演示入口
账单确认覆盖 勾选「待确认」批次 →「账单确认（覆盖当前）」→ 确认后状态待分摊，无对冲行 账单确认
未请款改金额 展开已分摊·未请款行 → 修改 → 提示「覆盖当前、不对冲」→ 保存 修改抽屉
已请未付改金额 改后覆盖当前，行标「已请未付·待重算」 请款状态标
已付开调整批 勾选已付款行 →「开调整批次」→ 生成 BATCH-ADJ-* 并覆盖当前；原请款锁定 开调整批次
请款 「＋ 付款请款」按当前金额生成请款单（核销仍用请款单） 付款请款

四、批次与请款单联动

批次管「费用认不认、怎么改」；请款单管「怎么付钱、怎么核销」。核销维度仍用请款单，批次不取代请款单。

主流程：导入批次 → 核对确认（覆盖当前费用）→ 按请款单请款 / 付款 / 核销。

请款状态批次有调整时怎么联动
还未请款 只改当前费用。请款时按最新金额勾选生成请款单，无旧单可改。
已请款、未付款
（或未核销完）
  1. 金额变少：请款单标「待重算」；未付可改请款金额，或作废重提
  2. 金额变多 / 补收：新开调整批次 → 再生成补请款单（或原单追加，二选一；建议补请款）
  3. 整笔撤销：请款单作废或冲减；费用回待分摊 / 待请款
  4. 未付请款单可改或作废；禁止静默改已锁定金额
已付款 / 已核销
  1. 原请款单锁死不改
  2. 只能：新调整批次（补收 / 冲减）→ 新请款单（补付 / 收回）→ 再核销
  3. 原请款单与调整批次互挂 batch_no、pay_req_no 留痕
挂接说明
费用当前行可关联多个来源批次（原批 + 调整批）
请款单明细勾选费用行，并带对应 batch_no
调整批次若费用已请过款，关联原请款单号
列表状态费用需能看出：已请款 / 有调整待补请 / 已付锁定

待拍板：已请未付时，改金额是「改原请款单」还是「作废 + 新请款」——与财务确认后定一条。原型暂按「覆盖当前 + 请款待重算」演示。

五、字段（本期）

字段说明原型
账单批次号
  1. 应付 / 实际费用新增维度；代理主单实际费用按批次账单对账
  2. 筛选、导出、推待办均可按批次
 批次列
服务商简称
  1. 主单实际费用新增服务商简称字段（列表汇总与明细均展示）
  2. 与结算服务商全称并存；筛选支持简称
 简称列
未确认实际金额 / 修改后金额
  1. 未确认 = 账单/导入原始实际金额，待财务确认；修改后默认相同，改后可不一致
  2. 折合 RMB、分摊按修改后金额；日常不生成对冲分录（见第三节）
 明细列
虚拟运单
  1. 提单未挂运单时，系统造虚拟运单承接费用，明细打「虚拟运单」标
  2. 导入某运单费用未进应付 → 标记「未进应付·待找运单」
 运单列

六、修改逻辑与附件

按费用行是否已分摊分流；调整必须填理由，并支持截图粘贴 / 上传附件。

状态说明原型
未分摊
  1. 含待确认、待分摊、待重新分摊等尚未完成分摊的费用行
  2. 直接改修改后金额 / 币别 / 汇率；须选调整理由；须粘贴截图或上传附件
  3. 覆盖当前值 + 写日志；未确认实际金额不变
 修改抽屉
已分摊（未请款）
  1. 直接覆盖当前分摊结果 + 写日志；不再生成正负对冲
  2. 换单差额挂原单当前值并打标；本行可再分摊
 已分摊 · 修改
已请款后再改
  1. 按请款状态分流，细则见第四节 · 批次与请款联动
  2. 已付：只开调整批次 + 新请款；禁止静默覆盖已付金额
 —
依据附件
  1. 调整理由必填；附件至少 1 个（Ctrl+V 粘贴截图或本地上传 jpg/png/pdf）
  2. 附件随修改记录留痕，便于复核
 粘贴区

七、缺预估 → 推产品部

点说明原型
触发
  1. 实际账单已出，但预估费用未生成 / 缺口行
  2. 由财务主动发起待办给产品部（工具栏「推产品部确认预估」或批次行「推待办」）
 推待办
确认回填
  1. 产品确认后回填预估费用
  2. 保留处理记录（发起 / 确认时间、说明）
 模拟回填

测：打开缺预估批次 → 财务推待办 → 状态「待产品确认」→ 产品确认后预估回填、留痕可见。

八、分摊 / 撤销分摊

点说明原型
按费用项分摊
  1. 只对勾选费用行，用修改后金额分摊到运单/票
  2. 未挂运单落虚拟运单；同柜未勾选费用项不重算
  3. 写当前值，不生成对冲
 分摊
撤销分摊
  1. 勾选已分摊费用行/批次 →「撤销分摊」→ 填原因 → 状态回待分摊（覆盖当前，不对冲）
  2. 若柜子数据相对分摊时点已变化：提示付款管理明细可能与当前货态不一致，确认后再撤
 撤销分摊
