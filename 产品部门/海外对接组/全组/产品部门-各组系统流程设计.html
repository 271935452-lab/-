① 总体系统架构（原流程 vs 目标）

以运单/柜为唯一业务对象；各组写各自主责字段，状态机驱动跨组订阅。下方先总对比，各组详情见各章。

部门主链 · 原流程

  B --> C["手拼播报\n先安排后录"]
  C --> D["资料核准对票"]
  D --> E["船务发舱单\n跨组对单"]
  E --> F["报关·口头查验"]
  F --> G["人肉刷放行\n人肉通知"]
  G --> H["海外表导美库"]
部门主链 · 目标流程 
flowchart LR
  BJ["AI报价·有效期·绑运单"] --> WAY["运单"]
  FK["查货卡点·计费·授权工单"] --> WAY
  CW["运价·订舱·配舱·提单·放行订阅"] --> CTR["柜子/船期"]
  GW["资料员闭环\n核准→舱单AMS/ISF→报关查验"] --> WAY

  HW["海外事件·计划·POD\n未确认"] --> CTR
  WAY --> EVT["事件总线"]
  CTR --> EVT
  EVT --> N["客服/业务/仓/客户"]

主数据归属（已确认 A）

  • 船务主写：舱位 / 配舱 / 装柜执行字段
  • 关务主写：资料 / 分单号 / 舱单·AMS·ISF / 报关 / 查验
  • 风控主写：查货结果 / 附加费标识 / 侵权工单
  • 私卡主写：报价结果 / 有效期 / 运单绑定

组织优化 职责重切

  • 资料员 → 关务编制
  • 发舱单 / AMS / ISF → 关务资料岗闭环
  • 船务不再发舱单，只读状态
  • 港后预报/Bond：建议随资料员，待船务确认

设计原则

  • 自动算 ≠ 自动放行（报价/舱单均留人工复核点）
  • 跨组只传状态与约束，不传 Excel
  • 异常必须事件通知，禁止静默改配
  • 未齐口径配置化，禁止写死金额

② 私卡报价组 · 系统流程设计

调研：0731 AI 报价评审 · 详案 · 纪要

2.1 调研痛点 → 设计目标

痛点系统设计目标优先级
Excel 规则手算，效率低、易过期规则表驱动自动算价 + 人工复核台P0

④ 船务组 · 系统流程设计

4.1 调研痛点 → 设计目标

痛点系统设计目标优先级
运价不在系统，播报手拼船司运价上系统；播报一键复制P0
先安排后录；待配仓难批量待配仓批量勾选；系统内分配；消费关务同柜约束P0

5.3 系统页面 / 能力清单

资料员工作台（新建/强化）

  • 出单任务池（预配舱可进）
  • 委托催办
  • 分单号生成与异常手填留痕
  • 核准双通道工作台
  • 舱单 / AMS / ISF 发送与改单台
  • 发送 SLA、同船批量、海管家/表格双通道

报关 / 查验 / 改配

  • 同柜约束 / 分柜装风险确认
  • 授权附件与抬头硬拦
  • 推报关与放行状态机
  • 查验一键通知 + 处置状态
  • 改配三类 + 通知矩阵
  • 三表视图（引用船务主写装柜字段）
组织优化收益（设计口径）： 砍掉「资料齐 → 再等船务发舱单 → 对单改单」跨组环； 分单号与舱单硬一致变为组内闭环； 改配时舱单/AMS/ISF 由同一资料岗改单留痕，避免二次作业。
待确认：AN/AMS/ISF 海管家启用阻塞与案例；改港费触发/金额/归属；港后预报/Bond 是否随资料员划转；分单号真实提单样例校验。
