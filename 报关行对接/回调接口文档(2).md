# 洪城捷运回调接口文档

## 1. 接口概述

洪城捷运通过该接口向系统回传报关预录单、正式件或放行资料附件。系统收到回调后会解密外层 `body`，校验业务字段，匹配报关行推送记录，并保存附件、更新对应业务状态。

测试环境:http://115.159.43.128:8862/

生产环境:https://interface.txfba.com/

## 2. 接口信息

| 项目 | 说明 |
| --- | --- |
| 请求方式 | `POST` |
| 接口地址 | `/customs/hongChengJieYun/callback/{callbackKey}` |
| 测试环境示例 | `http://115.159.43.128:8862/openApi/customs/hongChengJieYun/callback/pre_entry_callback` |
| Content-Type | `application/json;charset=UTF-8` |
| 字符编码 | `UTF-8` |

## 3. callbackKey 说明

| callbackKey | 兼容值 | 场景 | 处理说明 |
| --- | --- | --- | --- |
| `pre_entry_callback` | - | 预录单回传 | 保存预录单附件，更新推送记录和分单预录状态为 `预录待复审` |
| `formal_callback` | - | 正式件回传 | 保存正式件附件，更新分单报关单号、分单待放行状态、终配舱待放行状态和推送记录状态为 `待放行` |
| `release_callback` | - | 放行资料回传 | 保存放行资料附件，更新分单放行附件、放行状态、终配舱报关状态和推送记录状态为 `报关放行` |

## 4. 请求头

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `IV` | String | 是 | AES CBC 解密偏移量，需与加密时使用的 IV 一致 |
| `Content-Type` | String | 是 | 固定为 `application/json;charset=UTF-8` |

## 5. 外层请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `body` | String | 是 | 加密后的业务数据，Base64 字符串 |
| `timestamp` | String | 是 | 回调时间戳 |
| `mcNum` | Integer | 否 | 消息次数，系统仅记录日志使用 |

外层请求示例：
```http
POST /customs/hongChengJieYun/callback/pre_entry_callback
Content-Type: application/json;charset=UTF-8
IV: 1652161764065798
```

```json
{
  "body": "rbnbxHpF5eJpBbYp17rL2+ZPvB0KTT8cqMRXM2yWky/LJmMjtEe8KtuRboI2A7rLxw1+NgZNz3eMIUQguCzEWHEn/...",
  "mcNum": 0,
  "timestamp": "1652161764066"
}
```

## 6. body 加密规则

| 项目 | 说明 |
| --- | --- |
| 加密算法 | `AES/CBC/NoPadding` |
| 密钥 | 系统配置的洪城捷运 `APP_SECRET`；未配置时使用 `SECRET` |
| 偏移量 | 请求头 `IV` |
| 密文格式 | Base64 |
| 明文格式 | JSON 字符串 |

说明：系统使用 UTF-8 将密钥和 IV 转字节后解密，解密后的 JSON 会先读取根节点下的 `body` 对象；如果不存在 `body` 对象，则直接读取根节点。

## 7. 解密后业务字段

推荐明文 JSON：
```json
{
  "body": {
    "customerDocNo": "FBA123456-1",
    "billNo": "TDVWG8KX32",
    "customsDeclarationNo": "123456789012345678",
    "remark": "xxx回传",
    "fileList": [
      {
        "attachName": "FBA123456-1_xxx.pdf",
        "url": "https://example.com/files/pre-entry.pdf",
        "remark": "xxx附件"
      }
    ]
  }
}
```

业务字段说明：
| 字段 | 兼容字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `customerDocNo` |  | String | 是 | 系统分单号，用于匹配推送记录的 `SPLIT_BILL_NO` |
| `billNo` |  | String | 否 | 系统提单号 |
| `customsDeclarationNo` |  | String | 否 | 报关单号；传入后会同步更新分单报关单号 |
| `remark` |  | String | 否 | 备注；预录单回传写入预录备注，放行资料/正式件回传写入推送记录备注 |
| `fileList` |  | Array | 是 | 附件列表 |

附件字段说明：
| 字段 | 兼容字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `attachName` |  | String | 是 | 附件名称，建议包含文件后缀 |
| `url` |  | String | 是 | 附件可访问下载地址 |
| `remark` |  | String | 否 | 附件备注 |

## 9. 处理规则

### 9.1 预录单回传
请求地址：
```http
POST /customs/hongChengJieYun/callback/pre_entry_callback
```

处理逻辑：
- 保存附件到 `S_SYS_ENCLOSURE`，附件类型为 `报关预录件`
- 附件 `PRIMARY_NO` 使用匹配到的订单号
- 如传入报关单号，同步更新分单 `CUSTOMS_DECLARATION_NO`
- 更新推送记录状态和分单预录状态为 `预录待复审`

### 9.2 放行资料回传

请求地址：
```http
POST /customs/hongChengJieYun/callback/release_callback
```

处理逻辑：
- 保存附件到 `S_SYS_ENCLOSURE`，附件类型为 `报关放行资料`
- 附件 `PRIMARY_NO` 使用匹配到的订单号
- 更新分单放行附件、放行状态和预录状态
- 同步终配舱报关状态
- 更新推送记录状态为 `报关放行`

### 9.3 正式件回传

请求地址：
```http
POST /customs/hongChengJieYun/callback/formal_callback
```

处理逻辑：
- 保存附件到 `S_SYS_ENCLOSURE`，附件类型为 `正式件`
- 附件 `PRIMARY_NO` 使用匹配到的订单号
- 如传入 `customsDeclarationNo`，同步更新 `S_BUSS_ORDER_SPLIT_BILL.CUSTOMS_DECLARATION_NO`
- 更新分单状态为 `待放行`
- 同步终配舱报关状态为 `待放行`
- 更新推送记录状态为 `待放行`

## 10. 响应格式

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | Integer | 业务状态码，`200` 表示成功 |
| `data` | Object/String | 成功时返回处理结果说明 |
| `message` | String | 失败时返回错误信息；成功时通常为 `null` |

预录单回传成功：

```json
{
  "code": 200,
  "data": "洪城捷运回调数据已接收",
  "message": null
}
```

放行资料回传成功：
```json
{
  "code": 200,
  "data": "洪城捷运放行资料回调数据已接收",
  "message": null
}
```

正式件回传成功：
```json
{
  "code": 200,
  "data": "洪城捷运正式件回调数据已接收",
  "message": null
}
```

失败示例：
```json
{
  "code": 400,
  "data": null,
  "message": "IV不能为空"
}
```

## 11. 常见错误

| code | message | 说明 |
| --- | --- | --- |
| `400` | `不支持的callbackKey:xxx` | `callbackKey` 不在支持范围内 |
| `400` | `IV不能为空` | 请求头缺少 `IV` |
| `400` | `请求体不能为空` | 请求体为空 |
| `400` | `body不能为空` | 外层请求体缺少 `body` |
| `400` | `timestamp不能为空` | 外层请求体缺少 `timestamp` |
| `400` | `未找到洪城捷运报关行配置` | 系统未配置洪城捷运报关行 |
| `400` | `body解密或解析失败...` | `body` 解密失败、Base64 无效或明文不是合法 JSON |
| `400` | `uniqueNo不能为空` | 解密后的业务数据缺少分单号 |
| `400` | `fileList不能为空` | 解密后的业务数据缺少附件列表 |
| `400` | `fileList存在空元素` | 附件列表中存在空对象 |
| `400` | `fileList.attachName不能为空` | 附件名称为空 |
| `400` | `fileList.url不能为空` | 附件下载地址为空 |

## 12. 注意事项

- `customerDocNo` 是必填匹配字段 按分单号匹配。
- 附件 URL 必须能被系统服务访问。
- 同一个回调可传多个附件，系统会为匹配到的推送记录分别保存附件。
- `AES/CBC/NoPadding` 要求加密前明文字节长度满足算法补位要求，请对接方按双方约定的补位方式生成密文。
