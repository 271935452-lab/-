# 第三方接口文档

> 本文档面向第三方系统对接人员，描述AI报关系统向第三方系统推送数据的接口规范。

---

## 一、核对单发送接口

### 1.1 接口基本信息

| 项目 | 说明 |
|------|------|
| 接口名称 | 核对单数据推送 |
| 请求方式 | POST |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |
| 内容类型 | application/json |

### 1.2 接口地址

配置项：`thirdparty.checksheet.url`

由AI报关系统运营方提供具体地址。

### 1.3 请求参数

#### 请求体（Request Body）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| customerDocNo | string | 是 | 客户单证唯一编号 |
| checkSheetPdfUrl | string | 是 | 核对单PDF的NAS下载地址 |
| headerData | object | 是 | 表头数据（报关单基本信息） |
| bodyData | array | 是 | 表体数据（商品信息列表） |
| containerData | array | 是 | 集装箱信息列表 |
| licenseDocData | array | 是 | 随附单证信息列表 |

### 1.5 表体数据（bodyData）

数组元素，每个元素代表一条商品信息：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| goodsNo | string | 项号 |
| codeTs | string | 商品编号（HS编码） |
| goodsName | string | 商品名称 |
| elements | array[string] | 申报要素（规格/型号） |
| elementItems | array[object] | 申报要素选项（见下方） |
| goodsQty | string | 成交数量 |
| goodsUnit | string | 成交单位 |
| declPrice | string | 申报单价 |
| declTotal | string | 申报总价 |
| tradeCurr | string | 币制 |
| firstUnit | string | 法定单位 |
| firstQty | string | 法定数量 |
| districtCode | string | 境内货源地/境内目的地 |
| originCountry | string | 原产国 |
| secondUnit | string | 第二单位 |
| secondQty | string | 第二数量 |
| destinationCountry | string | 最终目的国 |
| dutyMode | string | 征免方式 |
| destCode | string | 目的地代码 |
| destName | string | 目的地名称 |
| goodsUnitName | string | 商品单位名称 |
| tradeCurrName | string | 币制名称 |
| originCountryName | string | 原产国名称 |
| districtCodeName | string | 境内货源地名称 |
| destinationCountryName | string | 最终目的国名称 |
| firstUnitName | string | 法定单位名称 |
| secondUnitName | string | 第二单位名称 |
| dutyModeName | string | 征免方式名称 |
| elementsSize | int | 申报要素数量 |
| ciqCode | string | 检验检疫编码 |
| ciqName | string | 检验检疫名称 |

#### elementItems 结构

| 字段名 | 类型 | 说明 |
|--------|------|------|
| code | string | 要素编码 |
| name | string | 要素名称 |
| value | string | 要素值 |

---

### 1.6 集装箱信息（containerData）

### 1.7 随附单证信息（licenseDocData）

数组元素：

|--------|------|------|

### 1.9 响应要求

第三方系统应返回 JSON 格式响应：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| code | int | 状态码（200表示成功） |
| message | string | 响应消息 |
| data | object | 可选，返回数据 |

#### 成功响应示例

```json
{
  "code": 200,
  "message": "success",
  "data": null
}
```

#### 失败响应示例

```json
{
  "code": 500,
  "message": "处理失败：具体错误原因",
  "data": null
}
```

## 二、放行资料发送接口

### 2.1 接口基本信息

| 项目 | 说明 |
|------|------|
| 接口名称 | 放行资料数据推送 |
| 请求方式 | POST |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |
| 内容类型 | application/json |

### 2.2 接口地址

配置项：`thirdparty.releasedoc.url`

由AI报关系统运营方提供具体地址。

### 2.3 请求参数

#### 请求体（Request Body）

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| customerDocNo | string | 是 | 客户单证唯一编号 |

| releasePdfUrl | string | 是 | 放行单PDF的NAS下载地址（带章） |
| attorneyPdfUrl | string | 是 | 委托协议PDF的NAS下载地址（带章） |
| headerData | object | 是 | 表头数据（放行状态页面数据） |
| bodyData | array | 是 | 表体数据（商品信息列表） |
| containerData | array | 是 | 集装箱信息列表 |
| licenseDocData | array | 是 | 随附单证信息列表 |

> **注意**：headerData、bodyData、containerData、licenseDocData 的数据结构与核对单接口完全一致，详见 1.4~1.7 节。

## 三、通用说明

### 3.1 数据推送时机

| 接口 | 触发时机 |
|------|----------|
| 核对单发送 | 前端用户点击"发送核对单"按钮时触发 |
| 放行资料发送 | ① 前端用户点击"发送放行资料"按钮时触发<br>② 系统收到海关"放行"回执时自动触发 |


### 3.5 数据安全

- PDF下载地址为NAS系统生成的临时下载链接，有效期由NAS系统控制
- 建议第三方系统在收到数据后及时下载PDF文件到本地存储

## 四、附录

### 4.1 常见 code 字段说明

| 字段 | 示例值 | 说明 |
|------|--------|------|
| ieType | 0/1 | 0=出口，1=进口 |
| hasLcl | 0/1 | 0=整箱，1=拼箱 |
| hasDangerousGoods | 0/1 | 0=非危险品，1=危险品 |
| isSpecial | 0/1 | 0=否，1=是 |
| isEffect | 0/1 | 0=否，1=是 |
| isPayment | 0/1 | 0=否，1=是 |
| tradeMode | 0110 | 一般贸易 |
| trafMode | 2 | 2=水路运输 |
| dutyMode | 1 | 1=照章征税 |
| transMode | 1/2/3/4/5/6 | 1=CIF，2=C&F，3=FOB，4=C&I，5=市场价，6=垫仓 |
