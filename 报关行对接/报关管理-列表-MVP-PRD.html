报关执行列表

报关岗作业页：排柜后正式件、发舱单、放行抓取、查验。预录阶段页签已从本页去掉，待上传 / 待推送 / 报关行处理中 / 预录待复审走预录工作台。

页顶说明（已收入 PRD，不占主列表）

  • 委托（#12）：已对接报关行 → 不按分票号查询。报关行自行匹配电子委托书，与报关单、放行单打包回传；本页核对回传结果。未对接 →「委托标记」催办/已委托 + 截图归档。无委托不可报关。
  • 品牌授权比对：已移除。查货侧已提前确认侵权；本页不做客户授权同步、抬头比对、推送硬拦。子表仅保留「报关资料抬头」展示。
  • 报关查验：「一键通知客户查验」或「查验处置」；行内展示查验天数、提醒/处置状态。与 清关管理 · 查验通知 口径一致。入口：页签「报关查验」或 ?tab=check。
  • 合并报关 · 再分票：客户可合并为 1 票；关务实操再拆为 N 票（例 10→3）。标记时选同柜优先或分柜装（分柜装须风险确认）。见 关务方案 §⑦。

与预录工作台

  • 本页不再展示预录阶段页签（未绑分单号 / 待推送 / 报关行处理中 / 预录待复审）。也不再挂预录工作台入口。
  • 排柜后在本页展开运单明细看预录单状态（未出 / 处理中 / 已出），并勾选预录单已确认；放行后锁定。
  • 未排柜做资料、推送报关行、预录审核、收取正式件（#08）走关务组预录工作台。终配舱后沿用已推送/预录进度，不重推报关行。

页签

  • 全部、待放行、报关查验、报关放行、查验放行。默认打开「待放行」。「报关中」仅作行内状态，不设独立页签。报关查验（#11）本期不对接，模块保留，手动维护。页签区不再展示「申报/放行」阶段标记。
  • 推送报关行、预录审核、上传资料、收取正式件不在本页工具栏。

页签说明

  • 全部：申报/放行各状态全量视图（不含预录工作台里的待推送等预录态）。
  • 待放行：预录工作台完成确认 / 收取正式件（#08）后进入；等待海关放行。不走报关行对接的线下单亦可能直接进入此态。本页默认打开此签。
  • 报关查验：本期不对接 API（#11），业务手动登记查验通知、更新状态；支持一键通知客户查验与查验处置（登记处置动作、开船前提醒、查验天数）。
  • 报关放行：未布控查验、海关已正常放行；抓到放行资料（#10）后系统自动进入此页签。
  • 查验放行：经海关查验后放行。

评审结论（#01–#12）

  • #01 推送报关资料附件 → 传附件 + 报关编号（主键，合并报关共用）；客户单号可作辅键；若子表「备注」有内容，推送报关行时一并传给报关行。不传分单号作主键。
  • #02 推送报关资料信息 → 不处理
  • #03 报关资料修改 → 修改附件、备注或客户单号后触发再次推送；分单号重算不触发报关行重推（分单号只给舱单）
  • #04 预录单附件回传 → 保存附件、审附件（标记：预录审核、预录单号列）
  • #05 预录单信息回传 → 不处理
  • #06 预录单修改 → 线下沟通
  • #07 线上沟通 → 线下沟通
  • #08 正式件收取 → 列表点击「收取正式件」时，调用报关行接口抓取该票最新预录单信息，保存为「报关正式件」（标记：工具栏紫色 #08）；保存成功后进入待放行。Webhook 推送时走同一保存逻辑
  • #09 报关单号回传 → 增加字段（标记：报关单号列）
  • #10 放行资料回传 → 接收 + 抓取（标记：放行资料抓取）
  • #11 报关查验回传 → 本期不对接，模块保留，手动处理
  • #12 电子委托 → 不按分票号查询。报关行自行匹配电子委托书，与报关单、放行单打包回传；本页核对。未对接用「委托标记」（催客户 + 截图归档）；无委托不可报关

页内对本期对接功能（#09 #10 #12）做彩色编号标记。#01 / #04 / #08 在预录工作台。

新增列

  • 预录单号、报关单号（#09）、放行资料（#10）、最近抓取、推送时间、预录回传、业务标记（ISF / AMS / 舱单 / 已发代理 / 改单 / 合并分柜 / 客户合并 / 再分票 / 分单号 / 船务改单①甩柜②换单③换柜）。报关状态列只写报关状态（待放行等），不夹合并/分票/分单号标。
  • 报关单号与预录单号区分：预录单号为报关行预录阶段编号；报关单号为海关正式报关单号，申报受理后由报关行 API / webhook 写入，预录阶段为空。
  • 展开子表字段（与线上一致）：客户、电子委托（#12）、委托内容（#12）、商品材质、商检报告资料、业务员、打单号、客户单号、件数、总体积、总重量、标记、附加服务、主品名、分单号、报关编号、预录单状态（未出 / 处理中 / 已出）、预录单已确认（可勾选，放行后锁定）、报关资料、报关资料抬头（仅展示）、备注（有值时随 #01 推送报关行）、FBA单号、REFERENCE ID、放行资料、托盘号、装柜扫描时间、更新时间、操作（报关资料，末列）。
  • 品牌授权比对：已移除（不设客户授权 / 授权抬头 / 是否一致列，不筛抬头，推送 #01 不再因授权硬拦）。

分单号规则 NEW

  • 生成时机：绑定提单之后按船司 × 港口规则自动生成（规则表：美森/合德/以星/COSCO·OOCL/WHL/EMC/华南）。未绑主单不生成；终配舱落成本身不触发生成。
  • 入口：申报/放行功能栏「分单号自动生成」（勾选提单 → 按规则整组试算并写入）、「分单号规则」（链至配置页）、「绑定分单号」手填兜底（申请类：以星上海、WHL 上海）。子表操作列「生成」同入口。
  • 规则维护：分单号规则配置（船司×港口→模板 T1–T7/T0；可试算）。
  • 货物/配舱调整：新增/删除/改序或终配舱调整后，整组按新序重新生成；顺序可错，号必须对舱单。重算只写本系统分单号，不重推报关行。
  • 子表「推送同步」：按客户单号推送态（未推送 / 已同步 / 待重推=附件或备注变更）。与分单号是否已生成无关。

推送报关行（#01）与重推（#03）

  • 推送主键：报关编号。内容：报关资料附件、报关编号（合并组共用）。回调匹配同一报关编号。客户单号可作辅键。
  • 备注：若子表「备注」字段有内容，推送报关行时同时传给报关行；无备注则不传或传空（以报关行接口字段为准）。
  • 重推：修改附件、备注或报关编号后（#03）再次推送。分单号变更不走 #03。
  • 阻断建议：附件/备注待重推时，「收取正式件」前应先完成 #03，避免报关行侧资料与头程不一致。

收取正式件（#08）

  • 入口：预录工作台「预录待复审」确认 / 收取正式件。本页从待放行起接。
  • 点击后：调用报关行 #08 接口，抓取报关行侧该票最新预录单信息（以报关行当前有效版本为准）。
  • 保存：抓取成功后，将返回内容保存为「报关正式件」，挂载至提单详情 · 清报关附件（附件类型：报关正式件；可与既有报关预录件并存）。
  • 状态：保存成功后进入本页「待放行」页签；失败则提示错误，状态不变、不落正式件。
  • Webhook：报关行主动推送正式件/最新预录单时，执行相同抓取保存逻辑，成功后自动进入待放行（若已订阅 #08）。

  • 品牌授权比对：已移除。本页不做授权同步与抬头硬拦；子表仅保留报关资料抬头展示。
  • 报关查验：页签「报关查验」下可「一键通知客户查验」「查验处置」；行内展示查验天数、提醒/处置状态。与清关管理 · 查验通知口径一致。入口 ?tab=check。
  • 合并报关 · 再分票：客户可合并为 1 票；关务再拆为 N 票实际报关单（例 10→3）。标记须选同柜优先或分柜装（分柜装须风险确认）。见关务方案 §⑦。

新增能力

  • 船务改单并入业务标记列（不再单独开列、不再单独筛）。三种短标：①甩柜（同提单同柜）／②换单（换提单同柜）／③换柜（换提单换柜）。待处理带左边线，已处理变淡。业务标记筛选可按①②③ / 改单待处理。本页只读展示，不提供改配登记 / 改单提醒入口。

工具栏

  • 筛选区两行：第一行 6 个条件；第二行「预录已确认 / 业务标记」与更多筛选、查询、一键通知客户查验、查验处置同一行，不再单独占一行。委托状态、合并报关在「更多筛选」展开。工具栏主功能栏：分单号自动生成、舱单、分单号等（无「申报/放行」分组标签）；查验按钮在筛选第二行。与「当前：页签」同一行。合并报关收在栏末尾「更多 · 合并报关 ▾」下拉（次要入口；主工作台在预录工作台）。无「委托回传核对 / 委托标记」按钮；无「改单 / 改配」按钮（品名/件毛体改单走预录工作台「改单撤销」；船务换柜换船改单标只读展示）。
  • 分单号自动生成（NEW）：勾选一票提单 → 打开弹窗，按船司×港口规则整组试算分单号 →「写入列表」后子表「分单号」列更新。货物/配舱变更后「按规则重算」→「确认重算结果」；只写舱单用分单号，不重推报关行 #03。以星上海、WHL 上海等申请类规则弹窗告警，改走「绑定分单号」。
  • 本页无预录工具栏。推送报关行、预录审核、上传资料、收取正式件、未对接委托催办标记在预录工作台。
  • 一键通知客户查验（NEW）：进入「报关查验」页签后显示；勾选查验提单 → 生成通知文案 → 发送/复制给业务员或客户。与清关管理查验通知口径一致（国内出口查验）。
  • 合并报关标记（NEW）：勾选提单 → 将组内运单标记为客户「合并报关 1 组」（生成合并组号、指定报关员）；主行业务标记展示「客户合并1组」，子表「标记」列可见合并报关。须选择同柜优先或分柜装（分柜装须勾选风险确认）。取消合并标记可清除。入口：申报栏「更多 · 合并报关」下拉；日常作业以预录工作台为主。
  • 合并后再分票（NEW）：客户已合并为 1 票后，关务将组内运单再分配到 N 票实际报关单（例：10→3）。子表「标记」列展示「报关票1/2/3」；主行业务标记展示「再分票 N」（与「客户合并1组」同列）。筛选项「合并报关」（更多筛选内）可按已合并 / 已再分票过滤；业务标记下拉也可筛客户合并 / 再分票。
  • 业务标记：一列展示 ISF、舱单、已发代理、改单、合并分柜、客户合并、再分票、分单号待生成/已生成，以及船务发起的①甩柜 / ②换单 / ③换柜。筛选区同一下拉过滤。不展示 AMS（AMS 在船务提单管理发送）。「舱单」= 已直推海管家；「已发代理」= 舱单已发给代理（车队/船代）。船务改单标只读，本页不提供登记或已知悉操作。
  • 发舱单（NEW）：勾选一票提单打开报文弹窗。通道：海管家直推 + 发给代理（与「下载舱单 / 标记已发代理」组成双通道）。关务本期需求已满足，不再扩发送通道。弹窗按现网「新增上海舱单」：无顶部「选择模板 / 保存为模板 / 关闭」；货物数据列为序号、提单号、箱号、封号、箱型、货主箱标记、英文品名、件数、包装单位、毛重、体积、唛头（右键删行、右侧新增行）。保存草稿不打标；海管家发送成功系统自动打「舱单」标。
  • 发 ISF（NEW）：勾选一票提单，弹窗按现网「新增ISF」（ISF-10 / 出口方 / 进口方），不另加字段。保存并提交、提交都算发送成功，打「ISF」标。ISF 走信号旗：本期只弹窗打标、不直连；下期对接信号旗。AMS 仍在船务，本页不提供「发 AMS」。
  • 下载舱单（NEW）：推代理 = 下载表格，发给代理核对进港（舱单双通道之一）。同船名航次可批量；混船名航次给出提示仍可下载。下载本身不打标。
  • 标记已发代理（NEW）：线下已把表格发给代理时，弹窗内点「仅标记已发代理」手工打标。无「系统发送给代理」。
  • AMS：仍由船务提单管理装柜前发送。本页不展示 AMS 标、不提供「发 AMS」。
  • 合并分柜：合并报关件不在一个终配舱时打标，提示分柜装风险。
  • 筛选项「委托状态」可按子表委托态过滤（示意）。

报文预填来源（弹窗不再展示，开发按本段）

字段可改，不回写来源主档。表单格上的来源标仅作对照。

  • 上海舱单
    1. 提单管理：主提单、船公司、船名航次、港口、柜号封号。来源页：船务提单管理。
    2. 进口商：收货人 / 发货人 / 通知人（通知人默认跟随收货人）。来源页：进口商档案。
    3. 终配舱：件毛体、委托书号 / 终配舱单号。来源页：终配舱。
  • ISF（本页发送；通道=信号旗，下期对接）
    1. 收发货人 · 装柜表 + 进口商：装柜表登记的抬头，再去进口商档案索地址 / ID / Bond。发货人、出口卖方、装柜地点、工厂跟装柜表；收货人、进口方跟进口商。来源页：装柜表、进口商档案。
    2. 船名航次 / 提单柜封港口 · 车队或代理：AMS B/L 等从车队或代理回传。
    3. 件数毛重拼柜 · 仓库数据表：HSCODE 等取仓库数据。可改，不回写仓库。
  • AMS：发送与预填口径见船务提单管理。

状态自动流转

  • 收取正式件 → 待放行：在预录工作台完成确认 / #08 后进入本页「待放行」。Webhook 推送时同样处理。
  • 放行资料抓取 → 报关放行：通过 #10 接口/webhook 抓到放行资料且判定齐全后，系统自动将状态更新为「报关放行」（未布控查验场景），并同步资料至运单/柜子。

操作列

  • 待放行 → 报关放行 / 抓取（#10）；已允许报关 → 抓取。分单号规则、绑定分单号在申报/放行功能栏（舱单用）。推送报关行、预录审核在预录工作台。
  • 做资料分票：执行侧仅入口，不展示核准状态。「已核准」是做资料分票页内标记，资料岗在该页点「核准通过」写入。点开本页可查看该标记。
