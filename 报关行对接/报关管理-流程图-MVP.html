报关管理业务流程图

与报关执行列表对齐。执行列表已去掉预录阶段页签；预录单状态与已确认在运单明细。

报关执行 · 运单明细

  1. 展开提单下运单：看预录单状态（未出 / 处理中 / 已出），勾选预录已确认；放行后锁定。
  2. 终配舱后沿用预录进度，不重推报关行。

预录工作台（不再出现在报关执行页签）

  1. 资料齐 → 待推送 → 按客户单号推送报关行（附件 + 客户单号 + 备注（有则传），#01；结构化信息不推，#02）。不要求先绑分单号。
  2. 终配舱落成后按船司×港口规则生成分单号（给舱单）；货物/配舱调整则整组重算，不重推报关行。
  3. 报关行处理中 → 预录单附件回传（#04），回调按报关编号匹配。
  4. 预录待复审 → 审附件（#04）；字段对比示意保留但不对接（#05）。
  5. 收取正式件（#08）→ 抓取报关行最新预录单信息，保存为「报关正式件」，进入报关执行「待放行」。

申报 / 放行

  1. 收取正式件（#08：抓取最新预录单 → 保存正式件；或 Webhook 同等逻辑）→ 进入待放行。
  2. 报关中（行内状态）→ 报关单号回传（#09）。
  3. 分支：未查验 → 报关放行；布控查验 → 报关查验 → 查验放行（#11 本期手动维护，不对接）。
  4. 放行资料抓取（#10）齐全 → 自动进入报关放行，并同步至运单/柜子。

本期调整

  • 已移除预录单改单、预录单补传分支。
  • 复审通过前新增收取正式件节点。
  • 报关查验（#11）本期不对接 API，模块保留，业务手动维护。

预录工作台节点

  • 待推送 — 资料已齐，按报关编号推送附件（#01）
  • 未绑分单号 — 终配舱后分单号为空，须规则生成或手填（舱单用，不拦推送）
  • 报关行处理中 — 等待预录单附件回传（#04）
  • 预录待复审 — 审附件；字段对比不做（#05）
  • 收取正式件 — #08：在预录工作台抓取最新预录单信息，保存为报关正式件后进入报关执行待放行；或 Webhook 自动同等处理
  • 复审通过 — 下发允许报关

申报 / 放行节点

  • 待放行 — 收取正式件（#08）完成后进入
  • 报关中 — 海关申报，报关单号回传（#09）
  • 报关放行 — 未布控正常放行；抓到放行资料（#10）后自动进入
  • 报关查验 → 查验放行 — 手动维护（#11 不对接）
  • 放行资料齐全 → 同步 — 抓取资料（#10），挂载至运单/柜子

手动操作

  • 不走报关行对接 → 待放行 → 手动报关放行 → 同步

本期不含

  • 预录单改单、预录单补传、线上沟通改单流转、报关查验 API 对接（#11）。
