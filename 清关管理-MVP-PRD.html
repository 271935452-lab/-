背景与痛点 · 我们解决什么问题

业务背景

目的港清关是关务尾端主路径：资料齐备 → 待清关 → 清关放行 / 清关查验 → 查验放行。清关客服需登记轨迹、盯控国外查验进度，并把进度同步给业务员/客服。现网列表字段与船务、报关执行、查验报表口径分散，国外查验缺少结构化跟进台。

核心痛点

  • 国外查验盯控散：送检 / 开查 / 放行、状态进程、清关行回邮等多靠邮件与手工表，列表难回溯。
  • 通知口径不统一：查验消息曾写「请转发客户」等文案，与本期「只同步进度、不建客户待办」冲突。
  • 取消 IT 职责混淆：取消 IT 属船务提单管理动作，清关页不应再提供操作入口，只需只读协同。
  • 进口商 / 清关行展示不一致：列名「清关供应商」与目录不符；未绑定展示规则不清。

本期要解决什么

  • 收敛清关管理列表：页签状态、现网筛选/列、进口商·清关行只读展示。
  • 规范清关查验轨迹登记与消息推送（站内 + 企微，仅业务员/客服）。
  • 新增查验跟进 · 国外查验弹窗与历史，对齐业务表「查验统计」Sheet1；周汇总见查验报表。
  • 清关详情区分出口报关品名与海外清关品名；取消 IT 只读、不设工具栏入口。

四、清关查验 / 消息推送

4.1 清关查验（轨迹登记）

  • 勾选清关查验中提单 →「清关查验」登记系统轨迹节点。
  • 弹窗下方直接铺开消息推送：渠道、对象、说明、文案预览、复制/发送，不必再点页脚按钮。
  • 与「查验跟进」区分：轨迹登记写系统轨迹；查验跟进写业务盯控进度与卡点。

4.2 消息推送 改

项口径
入口列表工具栏常驻「消息推送」（事后补发）；清关查验弹窗内嵌推送区
适用勾选清关查验 / 查验放行提单
渠道业务员/客服站内待办 + 企微；不发邮件、不建客户待办
对象业务员+客服 / 仅业务员 / 仅客服
文案只同步目的港查验进度；不写「请转发客户 / 无需转发客户 / 无需操作回复」

测：推送预览无「转发客户」字样；渠道无邮件选项。

五、查验跟进 · 国外查验 NEW

适用：列表状态为清关查验 / 查验放行的柜票。工具栏「查验跟进」或行内「跟进 / 历史」进入。

5.1 字段（本期精简）

  • 基本信息（只读）：提单号、柜号、到港、船名航次、起运目的、进口商、清关行、查验状态、跟进人、状态进程。不含查验方式、系统轨迹。
  • 登记本次跟进：查验状态（进行中 / 退运）、清关行、跟进人、状态进程、跟进说明。不含查验方式、送检/开查/放行时间、海外仓、系统轨迹摘要。
  • 查验状态不含「放行后查验」「HOLD」。
  • 跟进人默认当前清关客服，可改。

5.2 历史

  • 每次保存追加一条跟进历史（时间、跟进人、节点、说明）；支持查看完整回溯。
  • 列表「查验跟进」列展示最近节点摘要（如状态进程 / 开查日）。

5.3 与报表

周分析汇总见 查验报表 · 国外（饼图：正常 / 查验中 / 退运 / 查验已放行）。

测：清关查验行点跟进可保存；历史多一条；待清关行点跟进 toast 拦住。

六、清关详情 · 海外清关品名

  • 清关详情中出口报关品名与海外清关品名分字段维护。
  • 目的港清关资料以海外清关品名为准。
  • 测：详情可见两字段，可分别保存。

七、取消 IT · 进口商 / 清关行

7.1 取消 IT（只读协同） 改

  • 「取消IT」仅在船务 提单管理 操作；本页不设取消IT工具栏入口。
  • 列表「取消IT」列只读：已取消标取消IT，未取消显示无。不展示有IT / 无IT。
  • 筛选项仅「取消IT / 无」，与列展示一致。

7.2 进口商 / 清关行

  • 船务绑定进口商时一并选定已授权清关行并落库。本页与做资料只展示，不在本页改绑。
  • 清关行目录：精准 / 02B / 赛因 / 关关通 / 人人数智 / 帝成。
  • 未绑定进口商时进口商、清关行均显示 —。筛选支持名称/编码、清关行、未绑定。
